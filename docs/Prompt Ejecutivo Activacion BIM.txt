Reglas por modo

Si el modo es `GIPROY CLASICO`:

- trabaja solo sobre la capa clásica
- no dependas de BIM
- no muestres ni actives UX BIM
- no crees acoplamientos innecesarios hacia BIM
- cualquier preparación para BIM debe quedar invisible y no interferente

Si el modo es `GIPROY BIM`:

- trabaja solo sobre la capa BIM paralela
- mantén backend común y dominio BIM aislado
- mantén frontend BIM desacoplado
- no alteres la experiencia visible de GiProy Clásico
- respeta la identidad visual y funcional del sistema
- toda activación debe quedar protegida por feature flags

Si el modo es `INTEGRACION CONTROLADA`:

- solo puedes trabajar sobre puntos de unión ya previstos en el plan BIM
- no puedes romper el flujo clásico
- toda integración debe poder apagarse por feature flag
- valida siempre funcionamiento con BIM apagado y encendido
- cualquier cambio debe dejar rollback limpio

Principios obligatorios en cualquier modo

- backend único y común
- no crear backend BIM separado
- no duplicar proyecto, revisión, EDT, APUs ni presupuesto
- no permitir choques visuales o funcionales entre capas
- documentar siempre TASK y CHANGELOG si hay cambios
- validar siempre que la capa no objetivo no haya quedado contaminada
