# TASK-0076

## Fecha
2026-03-12

## Estado
DONE

## Objetivo
Blindar la regla de negocio que impide crear o importar recursos en subcategorías de la categoría principal `APU` (`subcategoria_codigo = 5`), ya que esos registros no se generan directamente desde `Recursos` sino a través del flujo propio de creación de `APUs`.

## Contexto
La UI de `Recursos` ya operaba solo sobre las categorías `1..4`, pero faltaba cerrar el backend para evitar que una llamada directa, un estado legado o una operación indirecta (`move`, `duplicate`, `import`) introdujera recursos bajo subcategorías `APU`.

## Implementación
- Se añadió validación explícita en `backend/app/repositories/recurso.py` para bloquear subcategorías con `subcategoria_codigo = 5`.
- La regla se aplica ahora en:
  - creación de recursos
  - importación masiva
  - movimiento entre subcategorías
  - duplicación de recursos legacy si el origen estuviera en `APU`
- Se actualizaron los endpoints de `backend/app/api/endpoints/recursos.py` para devolver `400` con mensaje funcional cuando la regla se viola.

## Validación
- `python -m py_compile backend/app/repositories/recurso.py backend/app/api/endpoints/recursos.py`

## Resultado
La restricción ya no depende solo de la UI: el sistema impide definitivamente que existan recursos creados o importados manualmente bajo subcategorías de la categoría principal `APU`.
