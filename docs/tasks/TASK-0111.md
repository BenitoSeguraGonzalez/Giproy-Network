# TASK-0111

Estado
DONE

Tipo
refactor

Prioridad
high

Descripción
Sanear y eliminar de forma controlada el rol legacy `supervisor`, hoy sin uso real en datos pero todavía presente en backend, frontend, cuotas, auditoría y permisos operativos. El objetivo es retirar completamente ese residuo sin romper flujos actuales de administración, licencias, dispositivos, auditoría ni gestión de usuarios.

Contexto verificado
- La base de datos actual no tiene usuarios con rol `supervisor`.
- La base de datos actual no tiene empresas con `limite_supervisores > 0`.
- El residuo actual es técnico y visual, no operativo en datos reales.
- `TASK-0110` reintrodujo soporte explícito para `supervisor` dentro del módulo de licencias; esta TASK corrige ese desalineamiento con la política real del producto.

Objetivo
Eliminar el rol `supervisor` como concepto vigente del sistema y consolidar la plataforma en tres capas reales:
- `Superadministrador`
- `administrador`
- `usuario`

Reglas de ejecución
- No eliminar columnas, campos ni ramas lógicas hasta verificar primero que no existen datos activos incompatibles.
- No romper contratos de API sin ajustar en el mismo cambio todos los consumidores frontend.
- Toda validación de permisos que hoy incluya `supervisor` debe resolverse explícitamente a `administrador` o a la política correcta del módulo.
- Si durante la ejecución aparecen datos legacy no detectados, la TASK debe pasar a `BLOCKED` antes de aplicar cambios destructivos.

Alcance
- Retirar `supervisor` de creación, edición y validación de usuarios.
- Retirar `limite_supervisores` y `total_supervisores` de cuotas y licencias.
- Retirar `supervisor` de auditoría, consola auditada y métricas de empresa.
- Retirar `supervisor` de permisos de dispositivos.
- Retirar `supervisor` de `Settings`, `Licencias y cuotas`, `AppLayout` y formularios de personal.
- Limpiar snapshot y documentación operativa para que el rol deje de figurar como actor vigente.

Fuera de alcance
- Rediseño completo del módulo de administración.
- Replanteamiento de RBAC fino por permisos granulares.
- Cambios visuales ajenos al saneamiento de este rol.

Plan de ejecución
1. Confirmar inventario final de huellas de `supervisor` en backend, frontend y snapshot.
2. Añadir una migración conservadora que reasegure `limite_supervisores = 0` en todas las empresas y deje el sistema listo para eliminar la columna.
3. Eliminar `supervisor` del contrato backend de usuarios, licencias y métricas.
4. Reasignar permisos donde hoy aparece `administrador/supervisor` al actor correcto, evitando ampliar privilegios por accidente.
5. Eliminar `supervisor` del frontend administrativo y de auditoría.
6. Ejecutar migración de esquema para retirar el residuo estructural si no aparecen bloqueos.
7. Actualizar documentación, snapshot y handoff.

Decisiones funcionales propuestas
- Las capacidades antes compartidas con `supervisor` pasan a `administrador`, salvo que un módulo requiera una regla más restrictiva explícita.
- El sistema deja de mostrar cualquier cuota, contador o etiqueta de `supervisores`.
- Las licencias quedan reducidas a:
  - `administradores`
  - `usuarios`

Riesgos a vigilar
- Endpoints de dispositivos y ajustes que hoy aceptan `supervisor` podrían quedar más restrictivos de lo esperado si no se revisa cada caso.
- Cambios de contrato en `admin-licenses/summary` pueden romper la UI si no se actualiza la lectura agregada en el mismo commit.
- La eliminación de columnas requiere migración reversible y validada contra la BD local.

Matriz mínima de pruebas
- Backend
  - Crear usuario `administrador` como `Superadministrador`.
  - Crear usuario `usuario` como `Superadministrador`.
  - Verificar que ya no se puede crear ni asignar `supervisor`.
  - Editar rol de usuario entre `administrador` y `usuario`.
  - Validar `GET /api/v1/admin-licenses/summary` sin referencias a `supervisores`.
  - Validar endpoints de dispositivos con `Superadministrador` y `administrador`.
- Frontend
  - `Administración Global > Licencias y cuotas` sin tarjetas ni textos de `Supervisores`.
  - `Settings > Empresas` sin campo `Supervisores Máx.`.
  - `Settings > Usuarios` sin referencias de rol `supervisor`.
  - `Consola de empresa auditada` sin bloque ni métricas de `supervisores`.
  - `AppLayout` mantiene acceso correcto a `Ajustes` para roles vigentes.
- Datos
  - Ejecutar consulta de verificación previa y posterior:
    - usuarios con rol `supervisor`
    - empresas con `limite_supervisores > 0`
  - Validar migración `upgrade` y `downgrade` en local si la revisión elimina columna.
- No regresión
  - `npm run build`
  - compilación backend (`python -m py_compile` sobre archivos tocados)
  - pruebas manuales de login, gestión de usuarios y dispositivos

Criterio de cierre
- No existe ninguna referencia funcional viva a `supervisor` en modelo, API, UI ni permisos.
- La base de datos queda sin usuarios `supervisor` y sin cuota `limite_supervisores`.
- El sistema sigue operando con `Superadministrador`, `administrador` y `usuario` sin regresiones detectadas.
