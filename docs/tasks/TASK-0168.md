# TASK-0168

Estado
CLOSED

Tipo
bug

Prioridad
high

Descripción
Corregir la invisibilidad de APUs en el listado y la inconsistencia con los conteos de las subcategorías.
El usuario reporta que el contador indica la existencia de APUs (ej: "(1)"), pero el listado aparece vacío ("No hay APUs").
Esto se debe a una falta de alineación entre el binomio Base de Proyecto / Revisión solicitado por el usuario.

Análisis
1. `SubcategoriaItemRepository` cuenta APUs ignorando la lógica de revisión.
2. `APUs.jsx` solicita APUs filtrando por `base_trabajo_id`, pero si es una "Base de Proyecto", la lógica debe respetar la revisión activa.
3. Se debe asegurar que las consultas de APUs (lectura y conteo) consideren la revisión si `BaseTrabajo.tipo == "Base de Proyecto"`.

Archivos afectados
- backend/app/repositories/apu.py
- backend/app/repositories/subcategoria_item.py
- frontend/src/pages/APUs.jsx

Checklist
[x] Modificar `APURepository.get_all` para aceptar un parámetro opcional `revision`.
[x] Modificar `read_apus` en el endpoint de APUs para pasar la revisión de la base activa si es Base de Proyecto.
[x] Actualizar `SubcategoriaItemRepository` para que los conteos de APUs (`items_count`) consideren la revisión de la base.
[x] Asegurar que al crear/duplicar APUs en una Base de Proyecto se herede o asigne la revisión correcta.
