Resultado
- Se descartó orfandad clásica: no había APUs sin base, sin subcategoría, con referencias colgantes ni cruces activos de contexto.
- Se detectó una degradación del catálogo en la base de proyecto `34` de `Santiago Bermeo`:
  - faltaban `5` APUs respecto a la base fuente `32`
  - `3` APUs compartidos estaban vacíos aunque en la base fuente sí tenían líneas
  - ninguno de los APUs de la base `34` estaba vinculado al presupuesto del proyecto
- Se creó y ejecutó `repair_santiago_apu_catalog.py` para restaurar de forma conservadora:
  - `5` APUs faltantes por código
  - `3` APUs vacíos cuya definición coincidía exactamente con la base fuente
  - sincronización adicional de `1` APU alterado durante depuración
- Tras la reparación, la base `34` quedó con `34` APUs y `42` líneas APU, alineando toda la parte claramente recuperable del catálogo.
- Permanecen `4` códigos divergentes frente a la base `32` (`5-011-0001`, `5-021-0001`, `5-027-0001`, `5-029-0001`), todos sin líneas en ambos lados; no se tocaron por tratarse de divergencias semánticas potencialmente intencionales.
