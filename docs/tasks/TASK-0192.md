Descripción
Corregir el uso indebido de `revision` en bases maestras. La regla operativa vigente es: solo las `Bases de Proyecto` manejan revisión; las `Bases Maestras` no deben enviar, mostrar ni depender de ese dato en el módulo APU.

Archivos afectados
- frontend/src/pages/APUs.jsx
- frontend/src/layouts/AppLayout.jsx
- docs/tasks/TASK-0192.md
- docs/CHANGELOG.md
- docs/HANDOFF.md

Checklist

[x] análisis
[x] implementación
[x] pruebas
[x] documentación

Resultado
- Se introdujo `effectiveBaseRevision` en `APUs.jsx` para propagar `revision` solo cuando `selectedBaseTrabajo.tipo === 'Base de Proyecto'`.
- Las cargas de subcategorías, recursos y APUs dejaron de enviar revisión para bases maestras.
- Las acciones de crear, duplicar e importar APUs también dejaron de inyectar `revision` en contexto de base maestra.
- El encabezado global de `AppLayout` ya solo muestra la insignia `REV n` cuando la base activa es de proyecto.

Validación de licencias
- Sin impacto en licencias.
- No modifica cuotas, permisos ni middleware.

Impacto UI
- Se corrige el contexto visual y funcional de bases maestras.
- La interfaz deja de insinuar revisión donde el modelo operativo no la contempla.
