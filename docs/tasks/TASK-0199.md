# TASK-0199

Estado
DONE

Tipo
feature

Prioridad
high

Descripción
Construir la capacidad backend común de exportación documental para reportes del sistema, tomando APUs como primer caso de implementación. Debe soportar salidas reutilizables para visor previo, Excel y PDF, incluyendo el caso de múltiples APUs donde cada APU se renderiza en una hoja/página independiente.

Archivos previstos
- backend/app/api/endpoints/reporting.py
- backend/app/services/reporting.py
- frontend/src/api/reporting.js
- docs/tasks/TASK-0199.md

Checklist

[x] análisis
[x] implementación
[x] pruebas
[x] documentación

Plan de adecuación
1. Definir contrato backend común para solicitudes de reporte con:
   - tipo de reporte
   - selección de entidades
   - formato de salida
2. Crear soporte multi-entidad para APUs como primer caso.
3. Generar workbook multihoja para selección múltiple.
4. Exponer salida consumible por visor previo.
5. Añadir exportación a PDF desde la misma capa documental.
6. Mantener validación backend por empresa y por ids autorizados.

Validación de licencias
- Validación backend obligatoria por empresa.
- No permitir exportar APUs fuera del contexto de empresa/base autorizado.

Impacto UI
- Permite que el frontend consuma un backend unificado de reportes para Excel y PDF.
- Evita que cada módulo implemente su propia lógica ad-hoc de exportación.

Resultado
- Se creó contrato backend común de `preview` y `export` para reportes, con APUs como primer caso soportado.
- La exportación Excel APU ahora soporta uno o varios ids; en selección múltiple genera workbook multihoja.
- La validación backend se mantiene por empresa y por acceso a los ids solicitados.

Pruebas ejecutadas
- `python -m py_compile backend/app/api/endpoints/reporting.py backend/app/services/reporting.py backend/app/schemas/reporting.py`
