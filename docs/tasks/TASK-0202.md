# TASK-0202 - Corregir autenticación del visor común de reportes

## Estado

Alta

## Agentes asignados
- Arquitectura
- Frontend

## Objetivo
Corregir el cliente frontend de reportes para que reutilice la infraestructura común de autenticación y contexto multiempresa, evitando respuestas `401 Unauthorized` al abrir la vista previa o exportar.

## Alcance
- Sustituir cualquier cliente Axios paralelo en el módulo de reportes por `axiosConfig`.
- Garantizar que las rutas de reportes usen el `baseURL` compartido y hereden `Bearer token` + `empresa_id`.
- Validar compilación frontend.

## Impacto en licencias
- Sin impacto.
- No cambia permisos, cuotas ni restricciones.
- Mantiene el mismo backend protegido; solo corrige la forma de consumirlo.

## Impacto UI / diseño
- Sin cambios visuales.
- Mantiene el mismo visor común de reportes.

## Implementación ejecutada
- `frontend/src/api/reporting.js` dejó de usar `axios` crudo y ahora reutiliza `./axiosConfig`.
- Las llamadas `preview` y `export` usan rutas relativas sobre el `baseURL` compartido.
- El flujo hereda automáticamente autenticación y `tenant injection`.

## Validación
- `npm run build`

## Resultado
- El visor de reportes ya no debe responder `401` por pérdida de token o de contexto de empresa.
- La regla técnica queda fijada: los nuevos consumidores de reportes deben usar siempre el cliente HTTP común del frontend.
