# TASK-0203 - PDF nativo backend para visor común de reportes

## Estado
COMPLETED

## Tipo
Feature

## Prioridad
Alta

## Área
Backend + Frontend

## Agentes asignados
- Arquitectura
- Backend
- Frontend
- QA
- Documentación

## Objetivo
Eliminar la dependencia operativa del diálogo de impresión del navegador para la exportación PDF del visor común de reportes y sustituirla por una generación PDF nativa en backend.

## Alcance
- Extender el contrato común de exportación para soportar `format = pdf`.
- Generar PDF backend para `apu`, `presupuesto`, `edt`, `vae` y `polinomica`.
- Adaptar todos los consumidores del visor común para descargar PDF real desde backend.
- Actualizar la dependencia Python necesaria y validar compilación.

## Impacto en licencias
- Sin impacto.
- No modifica permisos ni restricciones de uso.
- Mantiene backend como punto central de control documental.

## Impacto UI / diseño
- Sin cambios estructurales del visor.
- El botón `PDF` conserva la misma ubicación, pero ahora ejecuta exportación nativa.

## Implementación ejecutada
- `backend/app/services/reporting.py` ahora construye PDFs nativos con `reportlab`.
- `backend/app/api/endpoints/reporting.py` soporta `POST /reporting/export` con `format = pdf`.
- `backend/app/schemas/reporting.py` amplió el contrato de exportación a `xlsx | pdf`.
- `frontend/src/pages/APUs.jsx` y los consumidores `Presupuesto`, `EDT`, `VAE` y `Fórmula Polinómica` ya descargan PDF desde backend.
- `backend/requirements.txt` incorpora `reportlab==4.4.4`.

## Validación
- `python -m pip install reportlab==4.4.4`
- `python -m py_compile backend/app/api/endpoints/reporting.py backend/app/services/reporting.py backend/app/schemas/reporting.py`
- `npm run build`
- verificación sintética de generación PDF (`%PDF-`)

## Resultado
- El sistema ya no depende del `window.print` del navegador para PDF.
- La infraestructura común de reportes queda endurecida con salida `Excel` y `PDF` nativos desde backend.
