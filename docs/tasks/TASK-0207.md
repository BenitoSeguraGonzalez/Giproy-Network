# TASK-0207 - Propagación del orden APU a consumidores y reportes

## Estado
COMPLETED

## Tipo
Feature

## Prioridad
Alta

## Área
Backend + Frontend

## Agentes asignados
- Arquitectura
- Backend
- Frontend
- QA

## Objetivo
Garantizar que el orden persistido de líneas APU se reutilice en todas las visualizaciones y derivados funcionales del sistema.

## Consumidores mínimos a revisar
- `frontend/src/components/presupuestos/TanteoTab.jsx`
- `frontend/src/components/projects/DesagregacionTab.jsx`
- `backend/app/services/reporting.py`
- cualquier respuesta `get_apu` / `apuDetails` consumida por `APUs`, `Presupuestos` y visor común de reportes

## Alcance
- Confirmar que todas las lecturas de `apu.lineas` llegan ordenadas por backend.
- Eliminar dependencias de orden accidental por inserción.
- Verificar que preview/export de reportes respeten el orden guardado.
- Verificar que tanteo y desagregación técnica reflejen el mismo orden del editor.

## Criterio de cierre
- Un mismo APU reordenado se ve igual en editor, tanteo y reportes.
- No existen divergencias de orden entre API y frontend.

## Implementación ejecutada
- `backend/app/services/reporting.py` ordena líneas APU por `orden, id`.
- `backend/app/services/formula_polinomica.py` ya consume `apu.lineas` ordenadas.
- `frontend/src/components/presupuestos/TanteoTab.jsx` y `frontend/src/components/projects/DesagregacionTab.jsx` heredan el orden backend estable vía `get_apu`.
- La verificación de base local confirmó `0` APUs con secuencias de orden inválidas.
