# TASK-0211 - Modo responsive del editor APU para portátil

## Estado
DONE

## Tipo
Feature

## Prioridad
Alta

## Área
Arquitectura + Frontend

## Agentes asignados
- Arquitectura
- Frontend
- QA
- Documentación

## Objetivo
Implantar un modo responsive específico para el editor APU que mantenga usabilidad real en portátiles con alto escalado de sistema, evitando que la tabla técnica quede ilegible.

## Contexto funcional
- En portátiles con escalado del sistema elevado (por ejemplo `150%`), el ancho efectivo del editor APU se reduce lo suficiente como para volver inviable la tabla lineal actual.
- La descripción de línea pierde prioridad y queda anulada por la densidad de columnas numéricas.

## Regla funcional a fijar
- El editor APU debe tener al menos dos comportamientos visuales:
  1. modo amplio para escritorio real
  2. modo portátil / densidad intermedia con jerarquía reordenada

## Plan de ejecución
1. Detectar ancho útil del editor y activar un layout alternativo por umbral.
2. Reorganizar la fila de línea APU en dos niveles en modo portátil.
3. Ajustar panel lateral izquierdo para que no consuma ancho excesivo.
4. Documentar la regla en el libro de estilo.

## Impacto en licencias
- Sin impacto.

## Impacto UI / diseño
- Alto.
- Afecta directamente la experiencia principal del editor APU.

## Criterio de cierre
- En portátil la descripción vuelve a ser legible.
- No se depende del solape ni del scroll horizontal como solución principal.
- El comportamiento queda documentado en `STYLE_GUIDE.md`.

## Resultado
- Se implantó un modo responsive del editor APU basado en umbral de viewport.
- Las líneas APU pasan a jerarquía de dos niveles en ancho intermedio.
- El panel lateral reduce su ancho para ceder espacio útil al área de composición.
- La regla quedó documentada en `docs/STYLE_GUIDE.md`.
