# TASK-0216 - Portable Workspace Mode global

## Estado
COMPLETED

## Tipo
Feature

## Prioridad
Alta

## Área
Arquitectura + Frontend + Documentación

## Agentes asignados
- Arquitectura
- Frontend
- QA
- Documentación

## Objetivo
Definir e implantar un modo transversal de trabajo para portátiles y anchos intermedios que maximice el área útil operativa del sistema, reduciendo shell, headers, banners, paneles laterales y bloques fijos que hoy consumen espacio de trabajo.

## Contexto funcional
- Ya se confirmó necesidad real en `APUs` y `Presupuesto`.
- El problema no es solo de tablas: la shell global del sistema sigue siendo `desktop-first`.
- En portátil con escalado alto se pierde demasiada altura y anchura útil antes de llegar al área central de trabajo.

## Alcance
- Shell global
- Headers locales de módulos técnicos
- Política común de paneles laterales
- Modales densos de presupuesto
- Árboles y tablas técnicas de proyecto
- Libro de estilo

## Regla funcional a fijar
- En modo portátil, el sistema debe priorizar siempre el área central de trabajo sobre contexto repetitivo, avisos persistentes, paneles laterales fijos y métricas sobredimensionadas.

## Plan de ejecución
1. Compactar shell global y banner superior.
2. Compactar headers locales de módulos operativos.
3. Convertir sidebars densos a patrón rail/overlay/colapso.
4. Ajustar modales técnicos de alta densidad.
5. Extender el patrón responsive a árboles y tablas restantes.
6. Documentar el patrón en `STYLE_GUIDE.md`.

## Impacto en licencias
- Sin impacto.

## Impacto UI / diseño
- Muy alto.
- Afecta experiencia base del producto en portátiles.

## Criterio de cierre
- El área útil de trabajo aumenta visiblemente en portátil.
- El sistema deja de depender de shell y headers sobredimensionados.
- El patrón queda documentado como regla transversal.

## Cierre
- El programa `Portable Workspace Mode` quedó ejecutado por fases mediante `TASK-0217` a `TASK-0222`.
- La shell global, headers locales, sidebars, modales densos y vistas técnicas restantes ya adoptan el patrón compacto para portátil e intermedios.
- `docs/STYLE_GUIDE.md` ya formaliza el patrón como requisito transversal de producto.
- Los ajustes posteriores de módulos concretos quedan como refinamientos puntuales, no como deuda abierta del programa madre.
