# TASK-0229 - Ajuste integral de clasificación OmniClass

## Estado
COMPLETED

## Objetivo
Auditar y corregir el flujo completo de clasificación OmniClass en frontend, backend y base de datos para `Recursos`, `Subcategorías`, `APUs` y consumidores relacionados.

## Hallazgos iniciales
- La tabla `omniclass_maestro` sí tiene datos cargados (`14379` registros).
- Las tablas operativas `21`, `22`, `23` y `34` existen y contienen registros.
- El endpoint backend `/api/v1/maestros/omniclass/search` responde con resultados.
- Existe una inconsistencia de mapeo en frontend `Recursos`: el label muestra `Tabla 23`, pero la búsqueda envía `Tabla 22` para `Materiales`.
- El `SearchableSelect` no precarga opciones al abrirse; solo muestra resultados tras búsqueda manual.

## Resolución
- Se validó que la base y el endpoint backend sí contienen y entregan datos OmniClass.
- Se corrigió el mapeo frontend de tablas OmniClass mediante utilidad centralizada.
- Los selectores de `Recursos`, `Subcategorías` y `APUs` ahora precargan opciones al abrirse.
- La búsqueda backend queda ordenada por código para estabilizar resultados.
