# TASK-0295 - Sincronización de Códigos EDT con Presupuesto

Estado
COMPLETED

Fecha
2026-03-20

Objetivo
Corregir la sincronización entre la estructura jerárquica de `EDT` y la vista operativa de `Presupuesto` para que, cuando una cuenta cambie de padre o de orden:
- el `código EDT` se regenere conforme a la nueva jerarquía
- `Presupuesto` refleje esa nueva jerarquía sin residuos de numeración anterior
- no se confunda nunca el `código de cuenta EDT` con el `código de línea de presupuesto/APU`

Alcance
- backend de `EDT` y cualquier servicio/repositorio que derive o persista códigos jerárquicos
- sincronización de estructura proyectada en `Presupuesto`
- saneamiento de datos ya desalineados
- validación visual y documental

Validaciones obligatorias
- Si una cuenta pasa a depender de otra cuenta, su código y el de todos sus descendientes debe recalcularse.
- La cuenta hija inmediata debe numerarse como `.1` respecto a su nuevo padre.
- `Presupuesto` debe leer y mostrar la nueva jerarquía EDT sin conservar códigos viejos.
- El código EDT debe seguir siendo una referencia estructural distinta del código de línea APU.
- Los `STAKEHOLDER` no deben participar en la sincronización estructural entre `EDT` y `Presupuesto`.

TASK hijas
- `TASK-0296` Regeneración jerárquica de códigos EDT tras mover nodos
- `TASK-0297` Sincronización estructural de Presupuesto con EDT renumerado
- `TASK-0298` Saneamiento de proyectos ya desalineados
- `TASK-0299` QA funcional, responsive y documentación

Resultado esperado
- `EDT` y `Presupuesto` vuelven a compartir exactamente la misma jerarquía estructural.
- Los movimientos en `EDT` ya no dejan códigos obsoletos ni numeraciones intermedias incorrectas en `Presupuesto`.

Implementación
- Se endureció `backend/app/repositories/edt.py` para regenerar códigos por rama con contadores separados para `CUENTA_PAQUETE` y `STAKEHOLDER`, y para sincronizar presupuesto también en altas, movimientos, borrados, movimientos masivos y actualización de nombre.
- Se añadió `sync_presupuesto_codes_with_edt(...)` en `backend/app/services/presupuesto.py` para:
  - alinear filas estructurales del presupuesto con la jerarquía EDT vigente
  - deduplicar filas estructurales viejas por `edt_id`
  - reparentar las líneas APU al capítulo estructural canónico
  - recalcular `codigo_item` solo para líneas APU
- Se añadió saneamiento reproducible en `backend/scripts/sanitize_edt_presupuesto_sync.py` y se ejecutó contra la base local.

Validación ejecutada
- `python -m py_compile backend/app/repositories/edt.py backend/app/services/presupuesto.py backend/scripts/sanitize_edt_presupuesto_sync.py`
- `python backend/scripts/sanitize_edt_presupuesto_sync.py`

Resultado
- La numeración estructural EDT ya no se contamina por nodos `STAKEHOLDER`.
- `Presupuesto` vuelve a reflejar el código EDT actualizado sin mezclarlo con el código de línea presupuestaria/APU.
- La sincronización `EDT -> Presupuesto` queda limitada a nodos `CUENTA_PAQUETE`; los `STAKEHOLDER` quedan excluidos de capítulos, códigos visibles y subtotales presupuestarios.
