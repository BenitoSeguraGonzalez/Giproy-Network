# TASK-0297 - Sincronización de Presupuesto con EDT Renumerado

Estado
COMPLETED

Fecha
2026-03-20

Objetivo
Garantizar que `Presupuesto` consuma y represente correctamente la jerarquía actualizada de `EDT` después de movimientos y renumeraciones, sin arrastrar códigos previos.

Alcance
- `frontend/src/components/presupuestos/LineasPresupuestoTab.jsx`
- utilidades de composición árbol-presupuesto
- contratos de lectura entre `Presupuesto` y `EDT`

Validaciones obligatorias
- Si `EDT` renumera una cuenta a `1.1.1`, `Presupuesto` debe mostrar esa misma cuenta como `1.1.1`.
- No se debe reutilizar un código EDT stale en memoria o derivado de snapshot viejo.
- El código EDT debe mostrarse como código estructural de cuenta.
- El código de línea APU debe seguir mostrándose como identificador independiente de partida, nunca como sustituto del código EDT.
- Los `STAKEHOLDER` no deben proyectarse como capítulos, subcapítulos ni líneas estructurales de `Presupuesto`.

Resultado esperado
- `Presupuesto` representa correctamente la estructura EDT vigente y distingue jerarquía de cuentas frente a códigos de partidas.

Implementación
- Se añadió `sync_presupuesto_codes_with_edt(...)` en backend.
- Las filas estructurales (`apu_id is null`) heredan `codigo`, `descripcion`, `tipo` y `parent_id` desde EDT.
- `recalculate_line_codes(...)` ya no toca filas estructurales; solo renumera líneas APU reales dentro de cada capítulo EDT.
