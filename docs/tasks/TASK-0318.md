# TASK-0318 - Comunidad: mensajería directa y auditoría administrativa

## Estado
COMPLETED

## Objetivo
Implementar comunicaciones directas usuario a usuario con política explícita de auditoría.

## Alcance
- hilos directos entre dos usuarios
- listado de conversaciones
- envío, lectura y estados base
- adjuntos si el modelo ya lo permite o queda preparado
- auditoría de acceso administrativo excepcional

## Regla crítica
- Los mensajes directos no deben tratarse como publicaciones de foro.
- Si `SUPERADMIN` o un administrador accede administrativamente a un hilo directo, el acceso debe quedar auditado.
- Si existe `bloqueo_dm`, backend debe impedir enviar y responder mensajes directos.

## Política administrativa recomendada
- `Administrador de empresa` no debería leer DM ajenos por defecto.
- Si se habilita una excepción administrativa futura, debe ser:
  - explícita
  - justificada
  - auditada

## Resultado esperado
- Contrato backend separado para DM y base trazable para control posterior

## Implementación
- Se implementaron hilos directos `1 a 1`, lectura de mensajes y envío bajo endpoints específicos de DM.
- El backend mantiene `Mensajes directos` como superficie separada del foro y valida pertenencia del hilo al usuario y al contexto activo.
- El bloqueo de DM ya impide nuevos envíos sobre hilos bloqueados y la sanción `bloqueo_dm` se aplica antes del envío.
- La base de auditoría administrativa sensible quedó preparada mediante `community_admin_alerts`, `community_infractions` y eventos auditados del módulo.

## Evidencia
- `GET /api/v1/community/dm/threads`
- `GET /api/v1/community/dm/threads/{thread_id}/messages`
- `POST /api/v1/community/dm/messages`
- `POST /api/v1/community/dm/threads/{thread_id}/block`
- `POST /api/v1/community/dm/threads/{thread_id}/unblock`
