# TASK-0360 - Comunidad Feed Serialization Hardening

## Estado
COMPLETED

## Tipo
Backend + QA + Documentation

## Objetivo
Evitar que `GET /community/posts` falle con `500` cuando existan publicaciones, respuestas o adjuntos heredados con fechas nulas o mezcladas entre naive y aware.

## Alcance
- Normalización defensiva de fechas en serialización de publicaciones, respuestas y adjuntos.
- Normalización defensiva de fechas en sanciones, apelaciones, alertas, infracciones e hilos/mensajes DM.
- Normalización defensiva de fechas al calcular `last_activity_at` y ordenar el feed.
- Cobertura QA directa del endpoint lógico `read_community_posts(...)`.

## Reglas
- No se cambia contrato público del API.
- No se relaja ninguna validación de licencias o permisos.
- El feed debe seguir filtrando por empresa activa y tema visible.

## Validación
- `PYTHONPATH=backend python -m pytest -q backend/app/tests/test_community_permissions.py`

## Resultado
- El feed de `Comunidad` ya no depende de que todos los registros antiguos tengan datetimes homogéneos para poder listarse.
