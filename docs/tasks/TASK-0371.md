# TASK-0371 - Backend: evitar agotamiento de pool en carga inicial de Comunidad

Estado: COMPLETED

Tipo: Backend + QA + Documentation

Prioridad: Crítica

Área: Comunidad / Infra

Objetivo
Evitar que la carga inicial concurrente de `Comunidad` agote el pool SQLAlchemy del backend HTTP y termine devolviendo timeouts a todas las capas del módulo.

Alcance
- Liberar las sesiones abiertas por middlewares antes de `call_next()`.
- Ajustar el pool del engine para tolerar mejor el patrón de carga paralela del frontend.

Resultado
- `backend/app/main.py` ya no retiene la sesión de mantenimiento durante toda la respuesta cuando solo necesita validar el estado previo.
- `backend/app/middleware/license_middleware.py` ya no mantiene una sesión abierta hasta el final de cada request autenticada.
- `backend/app/core/database.py` sube el pool base a `10`, `max_overflow` a `20` y mantiene `pool_pre_ping`.

Validación ejecutada
- `python -m py_compile backend/app/core/database.py backend/app/main.py backend/app/middleware/license_middleware.py`
- comprobación HTTP local de `http://127.0.0.1:3000/api/v1/`
