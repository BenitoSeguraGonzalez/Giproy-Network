# TASK-0417 - Superadmin company switch resets operational context

## Objetivo
Hacer que el cambio de empresa del `Superadministrador` se comporte como un login limpio, sin arrastrar base maestra, base de proyecto ni proyecto activo desde la empresa anterior.

## Agentes
- Frontend
- QA
- Documentación

## Hallazgo
- El cambio de empresa solo limpiaba base/proyecto si la base activa informaba una `empresa_id` distinta.
- Eso permitía conservar contexto operativo residual al cambiar empresa, especialmente bases maestras.

## Implementación
- Se endureció `selectEmpresa` en `AuthContext`.
- Al cambiar empresa se limpian siempre:
  - `selectedBaseTrabajo`
  - `activeProject`
  - `giproy_working_base`
  - `giproy_working_project`
- La empresa seleccionada se mantiene, pero el resto del contexto vuelve a estado equivalente a post-login.

## Validación
- `npm run build`

## Resultado
- Cambiar de empresa con `Superadministrador` ya no arrastra bases ni proyectos previos.
