# TASK-0438 - Reparación integral de Tanteo en Presupuesto

## Objetivo
Reparar el módulo `Tanteo` de `Presupuesto` para que vuelva a operar sobre `rendimiento` de las líneas del `APU`, no sobre el precio del recurso, manteniendo simulación en tiempo real, propagación al presupuesto y persistencia en cascada al aceptar.

## Plan de ajuste
1. Auditar la regresión en frontend y backend para identificar si `Tanteo` está mutando precio o rendimiento.
2. Corregir la UI del panel para que la edición y la lectura correspondan a rendimiento, con layout estable y valores formateados con los decimales de cálculo del proyecto.
3. Mover la persistencia de tanteo desde `recursos` hacia `apu_lineas`, preservando reversión y propagación a APU y presupuesto.
4. Verificar migración, recálculo en cascada y actualización en tiempo real del presupuesto activo.

## Cambios ejecutados
- El panel `Tanteo` ahora edita `rendimiento` por línea de `APU`.
- Se corrigió el layout lateral para que la etiqueta de tarifa no rompa el contenedor.
- El input de rendimiento respeta siempre los decimales de cálculo del proyecto.
- La persistencia se movió a `apu_lineas` con trazabilidad reversible (`tanteo_activo`, `rendimiento_original`, `rendimiento_tanteo`).
- Al aplicar o revertir un tanteo se recalcula el `APU` y se propaga al presupuesto en cascada.

## Validaciones
- `python -m py_compile` sobre backend afectado
- `python -m alembic -c backend/alembic.ini upgrade head`
- verificación directa en BD de nuevas columnas en `apu_lineas`
- `npm run build`
