# TASK-0451 - Unicidad de APU por EDT en movimientos de Presupuesto

## Objetivo
Garantizar que un mismo `APU` no pueda quedar duplicado dentro del mismo `EDT` del presupuesto tras un movimiento.

## Política
- Si una línea se mueve a un `EDT` que ya contiene una línea operativa con el mismo `apu_id`, el sistema debe:
  - sumar `cantidad_destino + cantidad_origen`
  - recalcular el subtotal de la línea resultante
  - eliminar la línea origen
- Si no existe coincidencia previa en el `EDT` destino, la línea se inserta con la semántica normal del drop.

## Validaciones esperadas
- No quedan dos líneas del mismo `APU` bajo el mismo `EDT`.
- El presupuesto mantiene subtotales, códigos y totales coherentes después del merge.
