# TASK-0485: Implementación Global de Redondeo en Cascada

## Contexto y Objetivo
El usuario requiere comprobar y asegurar que el "redondeo en cascada" y la cantidad de decimales definidos ("decimales moneda" y "decimales proyecto" ajustados por Empresa/Presupuesto) se apliquen de forma universal a lo largo de toda la aplicación, tanto en Backend como en Frontend.

## Resultado de la Implementación
Se ha completado la auditoría y refactorización de todos los servicios críticos del sistema. Ahora todos los cálculos financieros respetan la configuración dinámica de la empresa o el presupuesto, utilizando el algoritmo de `redondeo_cascada`.

## Scope y Tareas (Checklist)

### Fase 1: Backend (COMPLETADO)
- [x] **`app/services/apu.py`**: Refactorizado para usar `decimales_moneda` y `decimales_calculos` de la Empresa.
- [x] **`app/services/presupuesto.py`**: Refactorizado para usar `dec_moneda` y `dec_calculos` del Presupuesto (Incluye Totales y Pareto).
- [x] **`app/services/reporting.py`**: Integración de `redondeo_cascada` en reportes Excel y PDF (VAE).
- [x] **`app/services/recurso.py`**: Redondeo normativo en la creación e importación de recursos.
- [x] **`app/services/formula_polinomica.py`**: Ajuste de coeficientes de monomios e incidencia.
- [x] **`app/api/endpoints/cronogramas.py`**: Estandarización de la distribución de costos y avances.

### Fase 2: Frontend (COMPLETADO)
- [x] **Auditoría de Componentes**: Verificación del uso de `useFormatters.js` en APUs, Presupuestos y Reportes.
- [x] **Limpieza**: Confirmación de que `toFixed()` se usa solo para fines estéticos de presentación.

## Criterios de Aceptación
1. [x] Cualquier cambio en las preferencias de "Mi Empresa" se refleja de inmediato.
2. [x] Los valores no quedan truncados sino redondeados escalarmente (`redondeo_cascada`).
3. [x] Consistencia total entre la web y los reportes descargables.
