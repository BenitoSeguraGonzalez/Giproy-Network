## Descripción

Cuando el usuario modifica el porcentaje de indirectos en el modal de indirectos (`IndirectosModal`),
los totales del presupuesto se actualizan (cabecera), pero los `precio_unitario` de cada línea
de detalle NO SE RECALCULAN. Esto provoca inconsistencias entre el subtotal de cada partida
y el total del presupuesto.

La política obligatoria es: `precio_unitario = CD × (1 + %ind / 100)` usando `redondeo_cascada`.

## Root Cause

El endpoint `PUT /{id}/indirectos` en `presupuestos.py` solo llama a `calculate_presupuesto_totals`
pero NO llama a `refresh_presupuesto_prices`. Esta función es la responsable de recalcular el
`precio_unitario` de cada línea de detalle usando el `% indirectos` del presupuesto.

## Checklist

- [x] Backend: Añadir `refresh_presupuesto_prices(db, pres.id)` al endpoint `update_presupuesto_indirectos` en `presupuestos.py` (ANTES de `db.commit()`)
- [x] Verificar que `refresh_presupuesto_prices` usa `redondeo_cascada` para los cálculos
- [x] Frontend: Asegurar que `PresupuestoDetail.jsx` llama a `refreshActivePresupuesto()` tras el guardado en `IndirectosModal` (ya existe `onSaved`)

## Archivos a Modificar

- `backend/app/api/endpoints/presupuestos.py` → añadir llamada a `refresh_presupuesto_prices`
- `backend/app/services/presupuesto.py` → verificar uso de `redondeo_cascada`
