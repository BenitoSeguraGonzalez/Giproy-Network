# Descripción
Reducir el ocultamiento del problema en frontend cuando el catálogo de APUs/recursos no coincide con la base esperada.

# Objetivo
Que el usuario vea cuándo la base del proyecto está desalineada o incompleta, en vez de depender de un fallback silencioso.

# Ajustes previstos
- indicador de estado de sincronización de base
- aviso cuando el catálogo cae en fallback
- acceso a diagnóstico o resumen de diferencias

# Validación
- el usuario puede distinguir entre “sin datos” y “base desalineada”
- el catálogo no oculta la incidencia sin señalizarla
- el editor del APU muestra si el contenido es heredado, local o divergente
