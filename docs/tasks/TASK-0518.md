# Descripción
Alinear el cálculo visual de parciales en los editores de APU con el precio monetario funcional mostrado al usuario.

# Objetivo
Evitar casos donde la UI muestra `0,57` como precio pero calcula el parcial con un valor crudo distinto y termina presentando `0,28` en lugar de `0,29`.

# Archivos afectados
- [frontend/src/pages/APUs.jsx](e:/Repositorios/GiProy%20Network/frontend/src/pages/APUs.jsx)
- [frontend/src/components/presupuestos/ApuBudgetEditor.jsx](e:/Repositorios/GiProy%20Network/frontend/src/components/presupuestos/ApuBudgetEditor.jsx)

# Validación
- `0,57 x 0,500000` muestra parcial `$0,29`
- el subtotal por categoría usa el mismo criterio
- el editor APU de presupuesto conserva el mismo redondeo funcional
