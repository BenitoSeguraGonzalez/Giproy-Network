# Descripción
Sustituir integralmente la antigua regla de redondeo sucesivo por la política oficial de redondeo directo, recalcular los datos persistidos afectados y fijar el cumplimiento obligatorio en código, pruebas y documentación.

# Objetivo
Eliminar divergencias sistemáticas provocadas por el redondeo sucesivo y alinear todos los módulos económicos del sistema a una única regla matemática estándar.

# Validación
- la política oficial queda fijada como `v2_direct_rounding`
- backend y frontend dejan de depender de `redondeoCascada` / `redondeo_cascada`
- `0.0846` a dos decimales devuelve `0.08`
- el caso `0.57 x 0.500000` mantiene `0.29`
- los módulos críticos (`APUs`, `Presupuesto`, `Cronogramas`, `Desagregación`, `EDT`, `Fórmula Polinómica`, `Reporting`) consumen una sola regla
- la base de datos local queda recalculada mediante script de migración
