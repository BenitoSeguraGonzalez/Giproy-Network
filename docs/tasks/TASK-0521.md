# Descripción
Corregir de forma integral el flujo de cálculo de líneas `APU hijo` para que los editores trabajen siempre con `costo_directo` como precio funcional del APU anidado y no queden bloqueados por subtotales persistidos obsoletos durante la edición en vivo.

# Objetivo
Eliminar la deriva de cálculo detectada con el APU `ENCOFRADO DE MADERA PARA LOSAS (2 USOS)` en la empresa `Santiago Bermeo`, cerrando el problema en el contrato API, el helper numérico común y las superficies de edición que consumen APUs anidados.

# Diagnóstico real
- Empresa auditada: `Santiago Bermeo` (`empresa_id = 3`).
- APU anidado auditado: `5-009-0005 - ENCOFRADO DE MADERA PARA LOSAS (2 USOS)`.
- Valores reales en la base local:
  - `APU 538`, base `32`, `costo_directo = 18.5700`, `precio_unitario_total = 22.4697`
  - `APU 615`, base `34`, `costo_directo = 11.4700`, `precio_unitario_total = 13.8787`
- Uso real como APU hijo detectado:
  - `APU padre 102` usa el hijo `538` con `cantidad = 0.500000`, `precio_congelado = 18.5700`, `subtotal = 9.2900`
- La fuga no estaba en el dato persistido principal sino en el flujo de edición:
  - el esquema mínimo del `apu_hijo` no exponía `costo_directo`
  - el editor de APU en presupuesto seguía priorizando `precio_unitario_total` para APUs anidados
  - el helper común reutilizaba `subtotal` persistido incluso cuando la fila local ya había cambiado en pantalla

# Solución aplicada
- El contrato `APUMinResponse` ahora expone `costo_directo` para cualquier consumidor de `apu_hijo`.
- La política numérica común admite explícitamente una excepción controlada para edición viva: puede ignorar `subtotal` persistido y recalcular desde los valores actuales de la fila.
- `APUs` y `ApuBudgetEditor` fuerzan ese recálculo vivo al pintar parciales y totales durante la edición.
- `ApuBudgetEditor` usa ya `costo_directo` como precio funcional de los APUs anidados al mapear líneas existentes, al añadir nuevas líneas y al mostrar el catálogo lateral.

# Validación
- El contrato mínimo del APU hijo incluye `costo_directo`.
- Los editores críticos ya no quedan anclados al `subtotal` persistido durante edición viva.
- Los APUs anidados ya no toman `precio_unitario_total` como precio funcional cuando existe `costo_directo`.
- Se añaden pruebas de regresión para contrato API y para evitar que reaparezca el orden incorrecto de prioridad de precio en el editor.
