# Descripción
Introducir una aritmética decimal segura en el frontend para eliminar discrepancias visuales provocadas por `Number` / `parseFloat` en cálculos monetarios y de cantidades operativas.

# Objetivo
Evitar casos como `2.05 × 1.5 = 3.07` en UI cuando la política oficial del sistema y la base de datos producen `3.08`, cerrando la contaminación por `float` en los módulos económicos críticos.

# Hallazgo detonante
- Caso real auditado en `Santiago Bermeo`
- `APU 5-007-0001`
- línea `2-0003-00001 - Alambre de amarre No. 18 negro recocido`
- BD correcta:
  - `precio_congelado = 2.0500`
  - `cantidad = 1.500000`
  - `subtotal = 3.0800`
- React estaba degradando el valor porque multiplicaba con `Number`, obteniendo `3.0749999999999997` antes de redondear.

# Solución aplicada
- Se añadió `decimal.js` como base de aritmética segura en frontend.
- Se creó `decimalNumbers.js` como núcleo común para parseo, suma, multiplicación, división y redondeo decimal seguro.
- `operationalNumbers.js` dejó de multiplicar con `Number` y ahora calcula con aritmética decimal exacta.
- `APUs`, `ApuBudgetEditor`, `Tanteo`, `LineasPresupuestoTab`, `EDT Valorada`, `Cronogramas` y `PresupuestoContext` migraron sus rutas críticas a helpers decimales.
- `useFormatters` dejó de depender de `Number` para redondeos oficiales de entrada/salida.

# Validación
- El frontend crítico ya no debe producir `3.07` para `2.05 × 1.5`.
- Las rutas de cálculo crítico usan `decimalNumbers.js` o `operationalNumbers.js`.
- Se añadieron guardas automáticas para detectar regresiones por reintroducción de `float` en módulos económicos clave.
