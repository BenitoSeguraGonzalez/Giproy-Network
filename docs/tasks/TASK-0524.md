# TASK-0524

## Objetivo
Blindar los entrypoints React más usados frente a fallos de interoperabilidad de hooks en la instancia Vite remota.

## Diagnóstico
- La instancia remota seguía arrojando `TypeError: Cannot read properties of null (reading 'useContext')` y antes `useState`.
- El patrón común aparecía en archivos que importaban hooks React como named imports directos.
- `AppLayout` ya estaba endurecido y la siguiente fuga visible era `BasesTrabajo`, junto con hooks y providers compartidos.

## Cambios aplicados
- Se migraron a `import * as React from 'react'` los módulos críticos de arranque y contexto:
  - `AuthContext`
  - `useFormatters`
  - `useAppDialog`
  - `ProtectedRoute`
  - `AppDialogProvider`
  - `BasesTrabajo`
  - `Subcategorias`
  - `Dashboard`
  - `Settings`
  - `Login`
- `vite.config.js` endureció la resolución de React con aliases exactos y se desactivó `fastRefresh` para reducir estados híbridos del runtime remoto.
- `AppRouter` dejó `BasesTrabajo` y `Subcategorias` como imports estáticos para sacarlos del camino `lazy/HMR` que estaba amplificando la fuga.
- Los hooks usados por esos módulos ahora se desestructuran desde el namespace `React`, reduciendo la fragilidad frente a prebundles/caché desalineados del dev server.

## Validación
- `npm run build` en `frontend`: correcto.
- `BasesTrabajo` compila con el nuevo patrón y deja de depender del import nombrado de `useContext`.

## Notas
- Este blindaje se aplicó sobre la ruta crítica visible del sistema para cortar la regresión actual sin tocar lógica funcional.
