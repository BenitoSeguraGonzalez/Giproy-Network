# TASK-0536

## Objetivo
Endurecer el flujo de edición de `APUs anidados` con control de cambios no guardados, contexto visible de anidamiento y confirmación con impacto estimado.

## Alcance
- `backend/app/services/apu.py`
- `backend/app/api/endpoints/apus.py`
- `frontend/src/api/apus.js`
- `frontend/src/pages/APUs.jsx`
- `frontend/src/components/presupuestos/ApuEditorModal.jsx`
- `frontend/src/components/presupuestos/ApuBudgetEditor.jsx`
- `frontend/src/utils/nestedApuEditing.js`
- pruebas backend asociadas

## Implementación
1. Añadir un resumen de impacto para `APUs anidados` con conteo de APUs padres y presupuestos afectados.
2. Bloquear cierre o retorno cuando existan cambios sin guardar.
3. Mostrar contexto visible cuando se edita un APU hijo desde un padre.
4. Reforzar el retorno al padre mediante recarga real del editor correspondiente.

## Validación
- El drawer de presupuesto no cierra ni vuelve sin confirmación cuando hay cambios pendientes.
- `APUs` aplica la misma protección al cerrar o volver desde un anidado.
- La confirmación de edición de `APU anidado` muestra impacto estimado cuando está disponible.
- Las pruebas backend cubren cascada multinivel e impacto.
