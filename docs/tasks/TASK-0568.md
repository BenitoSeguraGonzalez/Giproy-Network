# Descripción
El `superadministrador` necesita una entrada explícita en `Ajustes` para listar y editar cuentas con rol `Superadministrador`, y la experiencia de `Tienda` debe priorizar siempre la vista comercial inicial de catálogo y filtros sin quedar degradada por bloqueos de perfil pensados para otros roles.

# Objetivo
Añadir una superficie SaaS clásica exclusiva para gestión de superadministradores y corregir la UX inicial de Marketplace para que el `superadministrador` vea primero el listado de productos con sus filtros y no choque con un requerimiento de perfil en flujos de acceso comercial.

# Alcance
- Crear una entrada de `Ajuste SaaS` visible solo para `superadministrador`.
- Mostrar listado filtrado de cuentas `Superadministrador` y permitir su edición.
- Mantener esa gestión restringida solo al rol `Superadministrador`.
- Evitar que el `superadministrador` quede bloqueado por `marketplace_profile_complete` en flujos de tienda.
- Reforzar la presentación inicial del catálogo clásico como primera lectura comercial.
- Mantener el ajuste limitado a la capa clásica.

# Hallazgos de partida
- El backend común de usuarios ya permite a `superadministrador` listar y editar usuarios sin requerir un endpoint nuevo.
- `Settings` no dispone hoy de una superficie diferenciada para superadministradores; todo cae en la gestión general de usuarios.
- Marketplace ya tiene catálogo visible, pero los flujos laterales de compra/venta/biblioteca seguían tratando al `superadministrador` como si debiera completar el mismo perfil operativo que otros actores.

# Plan de trabajo
1. Promover el slice a una TASK específica.
2. Añadir entrada SaaS exclusiva para `superadministrador` dentro de `Settings`.
3. Implementar listado filtrado y edición de superadministradores reutilizando el backend común.
4. Corregir el gating de perfil en Marketplace para `superadministrador`.
5. Validar compilación frontend y no interferencia BIM.
6. Documentar resultados.

# Criterios de validación
- Solo `superadministrador` puede ver y operar la nueva entrada SaaS.
- La nueva vista lista únicamente cuentas con rol `Superadministrador`.
- Desde esa vista se puede editar un superadministrador existente.
- Entrar a `Tienda` como `superadministrador` muestra normalmente el catálogo y sus filtros.
- Los flujos de comprador/vendedor no fuerzan completar perfil cuando el actor es `superadministrador`.
- No se tocan rutas, flags ni componentes BIM.

# Implementación ejecutada
- Se añadió una nueva entrada `Ajuste SaaS` dentro de `Settings`, visible únicamente para `superadministrador`.
- La nueva vista lista solo cuentas con rol `Superadministrador`, con búsqueda dedicada, lectura operativa y acceso directo a edición.
- La edición reutiliza el formulario clásico existente de personal para no abrir una experiencia paralela y mantener coherencia visual/operativa.
- Se corrigió el gating de Marketplace para que `superadministrador` no quede bloqueado por `marketplace_profile_complete` en comprador, vendedor ni detalle de producto.
- Se reforzó la presentación inicial de `Tienda` con lectura comercial inmediata: catálogo primero, filtros visibles y resumen rápido de productos/categorías.

# Validación ejecutada
- `npm run build` completado correctamente en `frontend`.
- Revisión de impacto: el ajuste quedó limitado a `frontend/src/pages/Settings.jsx`, superficies clásicas de Marketplace y documentación operativa.
- No se tocaron endpoints BIM, flags BIM ni componentes de la capa BIM.

# Resultado
- `superadministrador` ya dispone de una superficie SaaS propia para gobernar sus cuentas.
- La entrada a `Tienda` vuelve a comportarse como home comercial de catálogo para ese rol, sin fricción innecesaria por perfil.
