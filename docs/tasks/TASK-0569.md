# Descripción
El Marketplace clásico necesita endurecer sus reglas de publicación por rol: `Sistema` debe vender productos exclusivos como licencias, actualizaciones/addons y adicionales, mientras los vendedores normales solo deben publicar `APUs`, `Bases Maestras` y `Proyectos`. Además, el superadministrador requiere un gestor de categorías con alcance de uso por vendedor: `Todos`, `Sistema`, `Usuarios`.

# Objetivo
Implantar reglas explícitas de venta por rol y un gestor de categorías en la capa clásica, manteniendo backend común y UX coherente para el panel vendedor del `superadministrador`.

# Alcance
- Restringir tipos de producto publicables según rol.
- Mostrar productos del superadministrador con propietario visible `Sistema`.
- Añadir alcance de categoría (`all`, `system`, `users`) en el dominio de Marketplace.
- Crear un gestor clásico de categorías accesible desde el menú de venta del superadministrador.
- Mantener el ajuste completamente desacoplado de BIM.

# Criterios de validación
- Un vendedor normal solo puede publicar `base_maestra`, `apu` y `proyecto`.
- El superadministrador puede además publicar `licencia`, `addon` y `adicional`.
- Los productos del superadministrador se muestran con propietario `Sistema`.
- El superadministrador puede crear, editar y activar/desactivar categorías marketplace.
- Las categorías soportan alcance `Todos`, `Sistema` y `Usuarios`.
- No se activan rutas, flags ni componentes BIM.

# Implementación ejecutada
- Se endureció el backend común de Marketplace para restringir tipos publicables por rol:
  - vendedores normales: `base_maestra`, `apu`, `proyecto`
  - `superadministrador`: además `licencia`, `addon`, `adicional`
- La validación de venta del backend ya no exige perfil completo al `superadministrador` para publicar o reseñar en Marketplace.
- Se añadió `visibility_scope` al dominio de categorías Marketplace mediante migración Alembic y nuevos contratos de schema.
- El backend ahora expone gestión admin de categorías (`listar`, `crear`, `editar`) y valida que una categoría `Sistema` no pueda ser usada por vendedores normales, ni una categoría `Usuarios` por `Sistema`.
- El frontend clásico muestra productos del `superadministrador` con propietario visible `Sistema`.
- El `Seller Dashboard` del `superadministrador` incorpora un gestor de categorías con alcance `Todos / Sistema / Usuarios`, edición y activación/desactivación.
- El formulario de publicación del vendedor se ajusta dinámicamente al rol y solo expone tipos/categorías permitidos.

# Validación ejecutada
- `npm run build` completado correctamente en `frontend`.
- `python -m py_compile` completado correctamente sobre modelos, schemas, servicios, endpoint Marketplace y migración Alembic.
- Revisión de impacto: no se tocaron rutas, flags ni componentes BIM.

# Resultado
- `Sistema` ya puede vender su catálogo exclusivo con identidad visible propia.
- Los vendedores de empresa quedan restringidos al catálogo técnico esperado (`APUs`, `Bases Maestras`, `Proyectos`).
- El Marketplace clásico gana gobierno real de categorías por tipo de vendedor sin introducir deuda hacia BIM.
