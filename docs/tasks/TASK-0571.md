# Descripción
El flujo de ventas del Marketplace clásico presentaba un único `Panel vendedor`, mezclando la operación comercial de empresa con la operación exclusiva de `Sistema`. Esto dificultaba la lectura UX para `superadministrador` y no dejaba explícito que el administrador de empresa solo debe operar el alcance empresarial.

# Objetivo
Separar la administración comercial del Marketplace en dos superficies claras:
- `Panel Empresa`, visible para administradores de empresa y superadministración.
- `Panel Sistema`, visible solo para superadministración.

# Alcance
- Añadir lectura agregada por empresa en backend común.
- Rediseñar el dashboard vendedor clásico con dos secciones de ventas según rol.
- Mantener publicación exclusiva de `Sistema` solo para `superadministrador`.
- Ajustar la entrada desde `Tienda` para que la navegación de ventas sea clara desde el primer clic.

# Implementación
- Se añadieron endpoints clásicos de lectura agregada por empresa para productos, estadísticas y ventas Marketplace.
- `SellerDashboard` ahora separa UX y narrativa entre `Empresa` y `Sistema`.
- El `superadministrador` puede alternar entre ambos paneles desde la misma consola.
- El administrador de empresa solo ve y opera el `Panel Empresa`.
- El `Panel Empresa` del superadministrador queda en modo supervisión comercial sobre la empresa activa.
- La entrada desde `Tienda` ya nombra explícitamente `Ventas empresa / sistema` para superadministración.

# Validación
- `npm run build` en `frontend` completado correctamente.
- `python -m py_compile backend/app/services/marketplace.py backend/app/api/endpoints/marketplace.py` completado correctamente.

# Resultado
La administración de ventas del Marketplace clásico ya distingue con claridad el alcance comercial de empresa frente al catálogo exclusivo de `Sistema`, sin introducir acoplamiento BIM ni romper el backend compartido.
