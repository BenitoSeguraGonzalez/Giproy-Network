# Descripción
El flujo actual de duplicación de APUs crea una copia, refresca el catálogo y deja al usuario fuera del editor. Esto rompe la expectativa de continuidad y deja copias en estado `Borrador` aunque el usuario no continúe con ellas.

# Objetivo
Convertir la duplicación en un flujo de trabajo continuo:
- abrir inmediatamente el APU duplicado en edición
- tratarlo como borrador descartable
- si el usuario decide salir sin guardar, ofrecer guardado o descarte
- si descarta, borrar la copia creada

# Alcance
- Rediseñar la UX de duplicación en `APUs`.
- Añadir control explícito de `duplicado pendiente`.
- Reutilizar el backend clásico existente de borrado sin introducir acoplamiento BIM.

# Plan ejecutado
1. Reencauzar la acción `Duplicar` para abrir directamente la copia en el editor.
2. Marcar la copia recién generada como borrador descartable mientras no se confirme guardado.
3. Interceptar cancelación, cambio de APU, creación de otro APU y salida de pantalla para decidir entre guardar, descartar o cancelar.
4. Si el usuario descarta la copia duplicada, borrar el nuevo APU creado usando el endpoint clásico ya existente.
5. Validar compilación y documentar la no interferencia con BIM.

# Implementación
- `frontend/src/pages/APUs.jsx`
  - La duplicación ahora abre inmediatamente el APU copiado en modo edición.
  - Se añadió estado `pendingDuplicatedApuId` para tratar la copia como borrador temporal.
  - Se incorporó el flujo `Guardar / No guardar / Cancelar` al cerrar, cambiar de APU, crear otro APU o duplicar nuevamente.
  - Si el usuario elige `No guardar` sobre una copia duplicada, se elimina automáticamente el nuevo APU con el borrado clásico.
  - También se bloquea la salida por navegación interna y cierre/recarga del navegador mientras exista trabajo pendiente.

# Validación
- `npm run build`

# Resultado
- El usuario entra directamente al APU duplicado tras copiarlo.
- Si abandona el borrador duplicado sin guardarlo, el sistema pregunta y permite borrarlo sin dejar residuos.
- El ajuste quedó limitado a `GiProy Clásico`; no se añadieron dependencias ni señales BIM.

# Ajuste posterior de compatibilidad
- Se retiró `useBlocker` tras detectar que el proyecto usa `BrowserRouter` clásico y no un data router.
- La protección de salida quedó rehecha con una estrategia compatible:
  - advertencia nativa en recarga/cierre del navegador
  - interceptación de navegación interna por enlaces del sistema con confirmación y continuidad controlada
- Con esto se elimina la regresión `useBlocker must be used within a data router` sin perder la protección principal del borrador duplicado.
