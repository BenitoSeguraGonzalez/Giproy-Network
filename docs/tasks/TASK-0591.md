# Descripción
El vendedor ya puede ver observaciones administrativas dentro de sus publicaciones, pero todavía falta una lectura prioritaria de cuáles requieren acción. No es lo mismo una publicación simplemente listada que una bandeja que concentre rechazos y observaciones pendientes de corrección.

# Objetivo
Añadir una bandeja prioritaria para publicaciones observadas o rechazadas dentro del panel vendedor del Marketplace clásico.

# Alcance
- Priorizar publicaciones `rejected` o con `admin_notes`.
- Dar acceso directo a edición desde la propia bandeja.
- Mantener el ajuste dentro del frontend clásico.

# Implementación ejecutada
- `frontend/src/pages/SellerDashboard.jsx`
  - Se añadió una bandeja prioritaria de publicaciones observadas o rechazadas dentro del panel vendedor.
  - La bandeja concentra primero los items del usuario actual que requieren corrección administrativa.
  - Cada publicación observada expone contexto, estado y acceso directo a edición con scroll al formulario.
  - El ajuste reutiliza `admin_notes` y el editor existente sin abrir rutas paralelas ni backend adicional.

# Validación ejecutada
- `npm run build`

# Resultado
- El vendedor ya no depende de revisar todo el catálogo para descubrir qué publicaciones requieren atención.
- Las publicaciones rechazadas u observadas quedan visibles como trabajo accionable y no solo como contexto pasivo.
- No hubo interferencia BIM.
