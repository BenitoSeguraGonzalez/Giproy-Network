# Descripción
Tras reforzar el detalle de pedido, el siguiente frente natural es hacer más accionable el bloque de historial de pedidos dentro del dashboard buyer.

# Objetivo
Mejorar la lectura y operatividad del historial de pedidos en la portada buyer del Marketplace clásico.

# Alcance
- Revisar la sección de pedidos del dashboard buyer.
- Añadir señales y acciones rápidas que mejoren el flujo postcompra sin introducir backend nuevo.
- Mantener el trabajo dentro de la capa clásica sin interferencia BIM.

# Implementación ejecutada
- Se reforzó la sección de historial de pedidos en `frontend/src/pages/MarketplaceBuyerDashboard.jsx`.
- Se añadió una capa de pulso de pedidos con métricas compactas de ticket medio, último pedido, completados y pedidos multi-item.
- Se añadió una tarjeta de foco siguiente con acciones rápidas hacia historial y biblioteca.
- Cada pedido ganó una lectura operativa más clara con chips, bloques de valor/composición/prioridad y mejor jerarquía visual.

# Validación ejecutada
- `npm run build`

# Resultado
- El historial buyer de pedidos ya no es una lista plana y ahora actúa como bandeja postcompra más accionable dentro del Marketplace clásico.
