# Descripción
Tras reforzar pedidos y biblioteca por separado, el siguiente paso natural es consolidar la lectura general del cockpit buyer para que las secciones dialoguen mejor entre sí.

# Objetivo
Mejorar la cohesión general del dashboard buyer del Marketplace clásico.

# Alcance
- Revisar la continuidad visual y operativa entre cabecera, biblioteca y pedidos.
- Añadir conexiones o señales que reduzcan fragmentación sin introducir backend nuevo.
- Mantener el trabajo dentro de la capa clásica sin interferencia BIM.

# Implementación ejecutada
- Se reforzó la cohesión general de `frontend/src/pages/MarketplaceBuyerDashboard.jsx`.
- Se añadió una nueva capa de `Ruta operativa` para conectar catálogo, pedidos y biblioteca como un único recorrido buyer dentro de tienda.
- Se añadió una tarjeta de `Consola unificada` con frente recomendado según el estado real de compras y activos.
- Se redujo la fragmentación entre las secciones buyer existentes sin introducir backend adicional.

# Validación ejecutada
- `npm run build`

# Resultado
- El dashboard buyer del Marketplace clásico ahora se comporta más como una consola integrada y menos como bloques funcionales separados.
