# Descripción
Tras consolidar el cockpit buyer, el siguiente paso natural es pulir estados vacíos y bordes de uso para que el flujo se mantenga claro incluso con poca actividad.

# Objetivo
Mejorar los estados vacíos y estados borde del dashboard buyer del Marketplace clásico.

# Alcance
- Revisar mensajes y orientación operativa cuando no hay pedidos, activos o actividad reciente.
- Mejorar la claridad del flujo sin introducir backend nuevo.
- Mantener el trabajo dentro de la capa clásica sin interferencia BIM.

# Implementación ejecutada
- Se reforzaron los estados vacíos y estados borde en `frontend/src/pages/MarketplaceBuyerDashboard.jsx`.
- Se añadió una banda contextual superior que explica el estado operativo real del buyer según compras, activos y sincronización.
- Se mejoraron los mensajes vacíos de biblioteca y pedidos para que orienten mejor el siguiente paso dentro del cockpit.
- Se añadieron acciones rápidas desde esos estados vacíos para mantener continuidad hacia catálogo, pedidos y biblioteca.

# Validación ejecutada
- `npm run build`

# Resultado
- El cockpit buyer mantiene una lectura operativa más clara incluso cuando todavía no hay compras, activos o actividad suficiente.
