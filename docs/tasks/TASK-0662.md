# Descripción
Aunque la lógica superior ya filtraba el catálogo, la interfaz todavía la comunicaba como una búsqueda genérica. Se redefine visualmente como filtro rápido de catálogo.

# Objetivo
Evitar lectura ambigua de “buscador posicional” y dejar explícito que el campo superior actúa como filtro del catálogo.

# Implementación ejecutada
- Se cambió el placeholder de `Buscar productos...` a `Filtrar catálogo...`.
- Se añadió una nota breve en la storefront aclarando el alcance del filtro rápido.
- Se mantuvo intacta la lógica de filtrado existente sobre nombre, resumen, descripción, categoría y vendedor.

# Validación ejecutada
- `npm run build` en frontend.
- Revisión de no interferencia BIM.

# Resultado
- La interfaz comunica ya de forma inequívoca que el campo superior es un filtro del catálogo y no un buscador posicional.
