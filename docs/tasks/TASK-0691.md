# Descripción
Primer slice integrado de `Portal de compras públicas` que aterriza varias de las mejoras definidas en el plan:
- versión técnica del artículo
- validación fuerte antes de guardar
- estado técnico del producto
- visor de previo para confirmación visual
- entrega inicial postcompra como proyecto adquirido

# Implementación ejecutada

## Frontend
- El creador/editor de `Portal de compras públicas` ahora incorpora:
  - configuración híbrida de entrega
  - origen técnico de importación
  - versión de plantilla
  - estado técnico calculado
  - resumen operativo de la política inicial del proyecto entregado
- Se añadió un visor de previo obligatorio antes de confirmar:
  - resumen comercial
  - ubicación y licitación
  - configuración híbrida
  - proyecto que se entregará al comprador

## Backend
- Se amplió la normalización del metadata de portal para soportar:
  - `delivery_mode`
  - `import_source`
  - `project_delivery_policy`
  - `template_version`
  - `template_revision`
  - `processing_status`
  - `delivery_preview`
  - `traceability`
- Se endureció la validación de publicación del producto `portal_compras_publicas`.
- El checkout ya crea un proyecto adquirido para este tipo de artículo:
  - sin base madre
  - con metadata de origen
  - con política inicial de envío bloqueado guardada en configuración

## Biblioteca comprador
- La biblioteca buyer ya distingue mejor estos activos mostrando:
  - tipo `Portal compras públicas`
  - bloqueo inicial de envío
  - versión técnica cuando exista

# Validación ejecutada
- `python -m py_compile backend/app/services/marketplace.py backend/app/services/marketplace_checkout.py`
- `npm run build`

# Resultado
- `Portal de compras públicas` deja de ser un formulario simple y pasa a un creador técnico-comercial más completo.
- El usuario administrador puede revisar visualmente la entrega antes de crear el artículo.
- La compra ya genera un proyecto adquirido inicial dentro del sistema comprador.
