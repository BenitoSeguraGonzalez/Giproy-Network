# Descripción
Segundo slice integrado de `Portal de compras públicas` para absorber una parte útil del antiguo importador externo dentro del sistema:
- análisis técnico desde archivo base
- persistencia del análisis en el producto
- resumen visible dentro del creador y del visor de previo
- exportación Excel disponible tras la compra

# Implementación ejecutada

## Backend
- Se creó el servicio interno [`public_procurement_portal_import.py`](e:/Repositorios/GiProy%20Network/backend/app/services/public_procurement_portal_import.py).
- El sistema ya puede analizar archivos técnicos base:
  - `PDF` de presupuesto si el parser PDF está disponible en backend
  - `XLSX` de presupuesto institucional
- El análisis produce:
  - nombre de fuente
  - cantidad de rubros
  - cantidad de capítulos
  - importe técnico
  - snapshot de rubros
- El metadata del producto `portal_compras_publicas` ahora persiste `import_analysis`.
- El checkout ya arrastra ese análisis al activo adquirido.
- Los pedidos de este tipo ya exponen una descarga `Portal Excel` cuando la modalidad incluye Excel.

## Frontend
- El creador/editor de `Portal de compras públicas` ahora incorpora:
  - carga de archivo base
  - botón `Analizar fuente`
  - resumen técnico integrado dentro del modal
  - resumen técnico dentro del visor de previo
- La validación exige análisis previo cuando el origen técnico es `archivo_base`.
- El detalle de pedido ya puede descargar la exportación Excel técnica del portal adquirido.

# Validación ejecutada
- `python -m py_compile backend/app/services/public_procurement_portal_import.py backend/app/services/marketplace.py backend/app/services/marketplace_checkout.py backend/app/api/endpoints/marketplace.py`
- `npm run build`

# Resultado
- La creación de `Portal de compras públicas` deja de depender solo de campos manuales y ya soporta una fuente técnica real.
- El análisis de importación queda guardado dentro del producto.
- La compra puede devolver tanto proyecto adquirido como exportación Excel técnica, según modalidad.
