# Descripción
Tercer slice integrado de `Portal de compras públicas` para que la compra no entregue solo metadata o un proyecto vacío, sino un proyecto adquirido con presupuesto base listo para trabajo interno.

# Implementación ejecutada

## Backend
- El fulfillment de `Portal de compras públicas` ahora crea:
  - proyecto adquirido
  - `ProyectoDetalle` descriptivo
  - presupuesto operativo base
  - estructura EDT mínima por capítulos importados
- Los rubros detectados por el importador técnico ya se siembran como líneas de `PresupuestoDetalle`.
- El proyecto guarda además metadata de entrega indicando si el presupuesto fue sembrado y cuántas líneas se generaron.

## Frontend
- La biblioteca buyer ahora informa cuando el activo portal llega con presupuesto base sembrado.
- El detalle de pedido explica que la entrega incluye proyecto adquirido y presupuesto inicial preparado a partir de la fuente técnica.

# Validación ejecutada
- `python -m py_compile backend/app/services/marketplace_checkout.py`
- `npm run build`

# Resultado
- La compra de `Portal de compras públicas` ya deja en la empresa compradora un proyecto más cercano a trabajo real.
- El activo entregado ya no se limita a la creación del proyecto y al Excel técnico: también deja un presupuesto base sembrado desde los rubros detectados.
