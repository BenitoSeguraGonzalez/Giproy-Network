# Descripción
Se unifica la política de publicación temporal para todos los artículos de `Tienda`: cada producto debe tener fecha de inicio y fecha fin de publicación como metadatos comunes, y solo queda disponible públicamente dentro de esa ventana.

# Implementación ejecutada

## Backend
- Se normalizan como metadatos comunes:
  - `fecha_inicio_publicacion`
  - `fecha_fin_publicacion`
- Ambas fechas pasan a ser obligatorias para crear o editar artículos.
- Se mantiene compatibilidad de lectura con metadatos heredados:
  - `fecha_publicacion`
  - `fecha_retirada`
- El catálogo público, el detalle de producto y el checkout ya solo consideran disponibles los artículos aprobados, activos y dentro de su ventana de publicación.
- `Portal de compras públicas` deja de apoyarse conceptualmente en fechas particulares para publicación y pasa a usar la política común.

## Frontend
- El editor genérico de productos ahora exige:
  - inicio de publicación
  - fin de publicación
- El creador/editor de `Portal de compras públicas` mueve esas fechas al bloque de meta común del producto.
- La validación previa del portal también exige ambas fechas.

## Catálogo de sistema
- El bootstrap de catálogo clásico ya siembra `product_meta` con ventana de publicación para los productos de muestra del sistema.

# Validación ejecutada
- `python -m py_compile backend/app/services/marketplace.py backend/app/services/marketplace_checkout.py backend/app/api/endpoints/marketplace.py backend/app/services/marketplace_catalog_bootstrap.py`
- `npm run build`

# Resultado
- La ventana temporal de publicación queda gobernada desde una política común de artículo.
- `Portal de compras públicas` queda alineado con esa política.
- El storefront y la compra ya no ignoran las fechas de publicación.
