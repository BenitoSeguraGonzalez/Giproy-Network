## Contexto

Los artículos demo de Tienda debían dejar de usar fechas neutras y pasar a una ventana de publicación realista para poder comprobar correctamente la política temporal de disponibilidad.

## Objetivos

- Dejar todos los artículos demo con `fecha_inicio_publicacion = ayer`.
- Asignar `fecha_fin_publicacion` variada por artículo.
- Reaplicar la semilla local para que el catálogo de prueba quede actualizado.
- Certificar la política efectiva de auto activación / desactivación temporal.

## Implementación

- Se añadió `build_sample_publication_window(index)` en `backend/app/services/marketplace_catalog_bootstrap.py`.
- La semilla de catálogo ahora genera una ventana reproducible por artículo:
  - inicio: `ayer`
  - fin: valor variable por artículo entre `14` y `180` días
- Se reaplicó la semilla local desde `backend/scripts/seed_marketplace_system_catalog.py`.

## Certificación de política actual

La política temporal hoy funciona así:

- Un artículo solo está disponible en storefront, detalle y checkout si cumple simultáneamente:
  - `estado == approved`
  - `activo == true`
  - fecha actual dentro de `fecha_inicio_publicacion` y `fecha_fin_publicacion`

- Esto se aplica en:
  - listado público de productos
  - detalle de producto
  - checkout

- El sistema **no cambia físicamente** el flag `activo` al vencer o adelantarse la ventana.
- La activación/desactivación temporal es hoy **efectiva por disponibilidad**, no por mutación persistida del campo `activo`.

## Validación

- `python -m py_compile backend/app/services/marketplace_catalog_bootstrap.py`
- `python scripts/seed_marketplace_system_catalog.py`

## Resultado

- El catálogo demo local ya usa ventanas temporales realistas.
- La política temporal quedó comprobada y documentada sin alterar la semántica del flag manual `activo`.
