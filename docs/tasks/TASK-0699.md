# Descripción
Se redefine la política de precio del producto `Portal de compras públicas`: el administrador ya no edita manualmente el precio comercial, sino que este se deriva automáticamente del `Precio de licitación` según una tabla fija por tramos.

# Objetivo
Evitar edición manual del precio del artículo y fijar una política comercial reproducible tanto en frontend como en backend.

# Regla implantada
- `0` a `100000.00` -> `11.50 USD`
- `100000.01` a `300000.00` -> `35.50 USD`
- `300000.01` a `1000000.00` -> `115.00 USD`
- Mayor a `1000000.00` -> `345.00 USD`

# Implementación ejecutada
- El modal especializado muestra `Precio comercial` como campo de solo lectura.
- El valor visible se recalcula automáticamente a partir de `Precio de licitación`.
- El payload del portal deja de depender del valor editable del formulario y usa el precio derivado.
- Backend recalcula y fuerza el precio final del producto `portal_compras_publicas` durante creación y edición.
- La metadata común `precio_con_iva` queda alineada al precio derivado real persistido.

# Validación ejecutada
- `python -m py_compile backend/app/services/marketplace.py`
- `npm run build`
- Revisión de no interferencia BIM

# Resultado
- `Portal de compras públicas` ya no admite precio manual en su creador/editor.
- El precio comercial queda gobernado por política fija y consistente.
- El ajuste queda acotado a `Tienda clásica` sin introducir dependencia hacia BIM.
