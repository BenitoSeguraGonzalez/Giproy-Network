# Descripción
Se implanta una política de borrador persistible para `Portal de compras públicas`: el administrador puede guardar el producto aunque aún esté incompleto, pero el artículo debe comenzar inactivo y solo puede activarse cuando se hayan completado todos los descriptores obligatorios.

# Objetivo
Permitir trabajo incremental sobre el producto sin perder avance, evitando al mismo tiempo que un artículo incompleto quede visible o comprable por error.

# Política implantada
- El portal nuevo arranca en `modo inactivo`.
- El producto puede guardarse en estado incompleto.
- Mientras falten descriptores obligatorios:
  - el control de activación queda bloqueado
  - el producto se guarda forzosamente inactivo
- Solo cuando estén completos todos los campos necesarios, el usuario puede manipular el modo activo.

# Implementación ejecutada
- Frontend:
  - se añadió lectura de completitud del portal
  - el slider de activación queda bloqueado hasta completar el producto
  - se añadió CTA de `Guardar progreso / Guardar borrador`
  - la `Vista previa` solo se habilita cuando el portal está completo
  - se muestran pendientes de completitud dentro del modal
- Backend:
  - se añadió evaluación de readiness para activación
  - creación y edición ya aceptan guardar borradores incompletos
  - si el portal no está completo, `activo` se fuerza a `False`
  - la metadata del portal persiste también su estado de readiness

# Validación ejecutada
- `python -m py_compile backend/app/services/marketplace.py`
- `npm run build`
- Revisión de no interferencia BIM

# Resultado
- `Portal de compras públicas` ya puede trabajarse por fases sin perder información.
- La activación comercial deja de depender de disciplina manual del usuario.
- El ajuste queda acotado a `Tienda clásica` y no introduce dependencia hacia BIM.
