# TASK-0712.md

## Objetivo
Blindar el campo `Precio de licitación` del editor de `Portal de compras públicas` para que el pegado de importes use solo la normalización monetaria específica del campo y no la política global de trim.

## Contexto
- La capa clásica ya dispone de una política global de saneamiento de pegado en `AppLayout`.
- `Precio de licitación` usa además `normalizePortalLicitacionInput` para interpretar separadores de miles y decimales.
- Se reportó un caso donde al pegar `86,083.88` el valor terminaba corrompido como `86083.8886083.88`.

## Plan de adecuación
1. Revisar el punto de entrada del pegado en el layout protegido y la normalización específica del campo monetario.
2. Aplicar la excepción prevista por infraestructura (`data-paste-trim="off"`) solo sobre `Precio de licitación`.
3. Mantener intacta la política global para el resto del sistema clásico.
4. Validar compilación frontend y registrar la no interferencia con BIM.

## Implementación
- Se marcó el `input` de `Precio de licitación` en `frontend/src/pages/MarketplaceAdminDashboard.jsx` con `data-paste-trim="off"`.
- El valor pegado queda procesado únicamente por `normalizePortalLicitacionInput`, evitando solapamientos con el trim global.

## Validación
- `npm run build`

## No interferencia BIM
- El ajuste se limitó al editor clásico de `MarketplaceAdminDashboard`.
- No se activó ni modificó ninguna superficie BIM.
