# TASK-0713.md

## Objetivo
Separar la política de guardado de borradores de la política de activación en Marketplace clásico, permitiendo guardar productos inactivos incompletos y reservando la completitud obligatoria para la publicación.

## Contexto
- En `Portal de compras públicas`, el usuario debe poder guardar y cerrar aunque aún falten descriptores.
- El bloqueo por campos obligatorios debe aplicarse solo al activar/publicar, no al persistir un borrador.
- El frontend ya enviaba `activo=false` para borradores incompletos, pero el backend seguía exigiendo ventana de publicación completa al normalizar `product_meta`.

## Plan de adecuación
1. Revisar la normalización de `product_meta` y detectar dónde se forzaba la ventana de publicación incluso en borrador.
2. Introducir una separación explícita entre `guardar inactivo` y `activar`.
3. Aplicar la nueva regla en creación y edición para mantener una semántica consistente.
4. Validar backend y frontend sin interferir con la capa BIM.

## Implementación
- `backend/app/services/marketplace.py` ahora permite `product_meta` sin ventana de publicación completa cuando el producto permanece inactivo.
- Si el borrador define solo una fecha de publicación, el backend sigue rechazándolo para evitar rangos incompletos.
- La activación continúa condicionada por `activation_readiness` y por `activo=true`, de modo que solo un producto completo puede publicarse.

## Validación
- `python -m py_compile backend/app/services/marketplace.py`
- `npm run build`

## No interferencia BIM
- El ajuste se limita al backend común del marketplace clásico.
- No se activó ni modificó ninguna ruta, flag ni UX BIM.
