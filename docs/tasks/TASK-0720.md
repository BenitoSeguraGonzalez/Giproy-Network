# TASK-0720.md

## Objetivo
Replantear el bloque de importación del editor clásico de `Portal de compras públicas` para soportar varios archivos de entrada `PDF` y/o `Excel` (`.xls`, `.xlsx`), evitando la UX confusa de selector nativo único.

## Implementación
- `frontend/src/pages/MarketplaceAdminDashboard.jsx` cambia el estado de importación a colección de archivos y rediseña el bloque como `Archivos técnicos de entrada`.
- El usuario puede seleccionar varios `.pdf`, `.xlsx` o `.xlsm`, verlos listados y lanzar un análisis combinado.
- `frontend/src/api/marketplace.js` envía varios archivos bajo la misma operación de preview.
- `backend/app/api/endpoints/marketplace.py` acepta múltiples `UploadFile`.
- `backend/app/services/public_procurement_portal_import.py` combina los análisis individuales y devuelve una estructura agregada con `source_files`.
- `backend/app/services/marketplace_checkout.py` adapta la presentación de fuentes para análisis con varios archivos.

## Validación
- `python -m py_compile backend/app/services/public_procurement_portal_import.py`
- `python -m py_compile backend/app/api/endpoints/marketplace.py`
- `python -m py_compile backend/app/services/marketplace_checkout.py`
- `npm run build`

## No interferencia BIM
- El ajuste se limita al portal clásico y al importador común de marketplace.
- No se activó ni modificó ninguna superficie BIM.
