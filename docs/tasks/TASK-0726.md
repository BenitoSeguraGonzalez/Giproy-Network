# TASK-0726.md

## Objetivo
Diseñar la politica de completitud documental y degradacion funcional del producto segun la cobertura real del bundle.

## Implementacion ejecutada
- El bundle ya clasifica cobertura real en estos niveles:
  - `solo_presupuesto`
  - `presupuesto + apus_base`
  - `presupuesto + apus + recursos`
  - `presupuesto + apus + recursos + vae`
- La degradación funcional se materializa así:
  - `solo_presupuesto`: válido, con bootstrap de APUs `Pendiente`
  - `presupuesto + apus_base`: válido, pero todavía apoyado en APUs generados
  - `presupuesto + apus + recursos`: cobertura operativa alta
  - `presupuesto + apus + recursos + vae`: cobertura avanzada
- Los warnings del bundle ya acompañan la cobertura para distinguir calidad documental de readiness comercial.
- La conciliación incremental por firmas queda integrada como parte de esta política: cuando varias fuentes se solapan, el bundle conserva una sola versión y expone `dedupe_summary` para que la UX informe qué fue conciliado.
- Se añade además una lectura semántica `budget_apu_alignment` para medir cuánto del presupuesto ya tiene correspondencia técnica:
  - `matched_real_apus`
  - `matched_pending_apus`
  - `unmatched_budget_rows`
  - `coverage_ratio`
- Esa lectura de cobertura se apoya ahora también en claves semánticas normalizadas para reducir falsos negativos cuando presupuesto y APUs describen la misma partida con variaciones menores de texto.
- El editor y la vista previa muestran esta cobertura y una muestra de rubros sin correspondencia técnica para facilitar saneamiento incremental.
- El bundle se autodiagnostica además con warnings ejecutivos derivados de cobertura parcial, referencias APU ambiguas, enlaces pendientes y ausencia de recursos suficientes.

## Validacion ejecutada
- `python -m py_compile backend/app/services/public_procurement_portal_import.py`
- `npm run build`
- Verificación visual del editor y preview del portal mostrando cobertura, warnings, conciliación incremental y cobertura presupuesto/APUs.
