# TASK-0728.md

## Objetivo
Diseñar el soporte formal de `APUs anidados` como insumos referenciados dentro del bundle tecnico.

## Implementacion
- `backend/app/services/public_procurement_portal_import.py` resuelve ya una primera capa de `APUs anidados` por cruce entre recursos detectados y APUs detectados dentro de la misma fuente o bundle.
- Se marcan recursos con `is_nested_apu`, `nested_apu_target` y `nested_apu_status`, emitiendo `apu_links` tanto para enlaces `resolved` como para referencias `pending_reference`.
- La resolución de referencias anidadas intenta ya conciliación por descripción semántica además de código o texto literal.
- El `analysis_bundle.summary` expone `nested_apu_link_count` y `pending_nested_apu_link_count`.
- El mismo summary expone ahora `semantic_match_count` para cuantificar cuántos enlaces se resolvieron por vía semántica.
- Cuando una referencia semántica puede apuntar a varios APUs, el bundle ya no la enlaza arbitrariamente y la marca como `ambiguous_reference`.
- El summary expone además `ambiguous_nested_apu_link_count` para diferenciar ambigüedad de simple pendiente.
- La reconciliación entre APUs bootstrap y APUs reales preserva además `temp_id` cuando un APU enriquecido sustituye a uno generado desde presupuesto, reduciendo ruptura en enlaces y trazabilidad del bundle.
- `frontend/src/pages/MarketplaceAdminDashboard.jsx` muestra tanto `APUs anidados` como `Anidados pendientes`, `Anidados ambiguos`, la métrica `Semánticos` y muestras de referencias anidadas aún no resueltas o ambiguas.

## Validacion
- `python -m py_compile backend/app/services/public_procurement_portal_import.py`
- `npm run build`
