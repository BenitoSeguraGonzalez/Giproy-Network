# TASK-0733.md

## Objetivo
Rediseñar el bloque `Archivos técnicos de entrada` como flujo de ingesta multiarchivo claro, lineal y usable.

## Implementacion ejecutada
- Sustituir la composición actual por una secuencia visual explícita:
  1. seleccionar archivos
  2. revisar archivos cargados
  3. analizar
- Dar jerarquía clara a la acción primaria (`Seleccionar archivos`) y a la acción operativa (`Analizar`).
- Evitar que textos largos o estados residuales compitan con los controles principales.
- Mantener soporte de múltiples `pdf`, `xls` y `xlsx`.
- El bloque `Fuente documental` ya muestra esa secuencia con dos acciones claras, estado documental visible y ayudas compactas de formatos.
- El flujo se limpia aún más retirando textos explicativos y la cartela de estado: `Seleccionar archivos` abre la sección, `Archivos cargados` ocupa el centro y `Analizar` baja debajo del listado.
- La selección multiarchivo deja de reemplazar la cola anterior: nuevas cargas se agregan sin duplicar entradas ya presentes, el actuador se compacta en un botón con icono y desaparecen las etiquetas visuales residuales de formatos.
- La solución de carga se endurece además sustituyendo el patrón `label + input` por un `input` oculto controlado por `ref`, con handler centralizado de merge, re-selección segura y apertura explícita del picker.
- El resultado del análisis queda blindado además con normalización previa del payload (`import_analysis`) antes de entrar al estado del modal, filtrando filas nulas y asegurando arrays/objetos mínimos para que el render nunca derive en pantalla blanca.
- El manejo de errores del análisis deja además de pasar `detail` crudo al diálogo: respuestas `422` estructuradas se normalizan a texto legible para evitar una nueva caída del render por intentar pintar objetos de validación.
- El endpoint backend de preview queda además compatible con ambos nombres de campo multipart (`files` y `file`) para absorber desfases de contrato entre frontend y servidor activo sin volver a bloquear el importador.
- El frontend y el backend cierran esa compatibilidad manteniendo ambos nombres de campo multipart (`files` y `file`) pero con deduplicación server-side, evitando dobles análisis aunque el contrato se publique por las dos vías.
- El preview queda además con timeout ampliado del lado cliente (`120s`): si el backend no responde en tiempo razonable, el modal sale de `Analizando` y muestra un mensaje operativo en lugar de quedar bloqueado indefinidamente.
- El manejo de error del preview también incorpora `message/details` además de `detail`, para que un `500` backend deje un diagnóstico visible en UI y no un mensaje genérico opaco.
- La corrección estructural del preview mueve además el análisis pesado del importador a `threadpool` en backend, evitando que una ruta `async` bloquee el ciclo de atención mientras procesa PDFs/XLS/XLSX.
- La UX del importador añade además un indicador de progreso honesto: subida real cuando el navegador reporta bytes enviados y fases visibles de procesamiento (`validando`, `leyendo`, `extrayendo`, `conciliando`, `finalizando`) mientras el backend completa el bundle.

## Validacion
- `npm run build`

## Resultado
- El usuario identifica el siguiente paso sin esfuerzo.
- `Analizar` solo se percibe como acción contextual cuando ya existen fuentes cargadas.
- La sección deja de sentirse improvisada o bloqueada.
- La carga documental queda más sobria y centrada en acciones reales, sin ruido textual ni bloques auxiliares.
- La selección de archivos queda estable para cargas sucesivas y deja de depender de un comportamiento frágil del navegador sobre labels ocultos.
- El contrato HTTP del importador conserva compatibilidad máxima sin reprocesar la misma fuente dos veces, y la ruta de preview deja además de bloquear el hilo principal del backend durante el análisis.
- El usuario ya no queda mirando una pantalla muda durante el preview: el importador muestra progreso y fase actual incluso cuando el análisis todavía está procesándose en backend.

- Slice exclusivo de UX clásica sin impacto BIM.
