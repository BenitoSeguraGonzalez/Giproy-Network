# TASK-0755 - Core de pagos del marketplace clásico: órdenes, intentos, eventos e idempotencia

## Objetivo
Definir e implementar la base estructural de pagos del marketplace clásico para soportar múltiples métodos y confirmación backend.

## Alcance
- Modelo `order`
- Modelo `payment_attempt`
- Modelo `payment_event`
- Modelo `checkout_draft`
- Estados de pedido y pago
- Idempotencia
- Preparación para `fulfillment`
- Snapshot comercial por pedido
- `seller_scope` como base de evolución futura
- Matriz de estados mínima
- Política monetaria base
- Auditoría mínima del core

## Dependencias
- Ninguna. Es la base del frente.

## Criterio de cierre
- Existe separación formal entre `cart`, `checkout_draft`, `order`, `payment_attempt`, `payment_event` y `fulfillment`.
- Quedan definidos `order_status`, `payment_status` y expiraciones mínimas.
- El modelo soporta idempotencia y snapshot comercial sin depender del producto vivo.
- El diseño deja previsto `seller_scope` para vendedores parciales futuros sin implementarlos aún.
- Queda cerrada la matriz mínima de transiciones válidas del core.
