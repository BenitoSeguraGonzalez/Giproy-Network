# TASK-0758 - Adaptación del checkout clásico a selección dinámica de método de pago

## Objetivo
Convertir el checkout clásico en un flujo multi-método sin romper la estética actual del storefront, detalle y carrito.

## Alcance
- Bloque `Método de pago`
- Estados de pago visibles
- Checkout draft
- Cierre UX por método
- Compatibilidad con carrito persistente
- No ruptura del diseño actual
- Convivencia con feature flags y métodos no listos

## Dependencias
- `TASK-0755`
- `TASK-0756`
- `TASK-0757`

## Criterio de cierre
- El checkout soporta selección dinámica de métodos activos.
- El flujo conserva la estética actual del storefront, carrito y detalle.
- Existen cierres diferenciados para pago confirmado, pago pendiente y validación manual.
- El checkout usa `checkout_draft` sin contaminar el carrito persistente original.
- El checkout puede operar por fases sin exponer métodos desactivados o incompletos.

## Estado
Completado - 2026-03-31

## Resultado parcial
- El carrito clásico ya consulta métodos públicos disponibles y muestra selector dinámico cuando existen.
- Si no hay métodos activos/listos, el checkout inmediato actual sigue funcionando sin cambios.
- Si ya existen métodos listos, el checkout crea `checkout_draft` con el método seleccionado y evita activar compras sin confirmación real en esta fase.
- La adaptación conserva la estética actual del carrito y no rompe el storefront existente.
- El circuito ya soporta cierres diferenciados por método, vaciado postconfirmación y continuidad con carrito persistente.
