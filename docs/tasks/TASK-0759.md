# TASK-0759 - Integración PayPhone con confirmación backend y activación de compra

## Objetivo
Integrar `PayPhone` usando su flujo de cajita de pagos y confirmación backend para activar compras solo tras confirmación válida.

## Alcance
- Configuración de credenciales
- Flujo frontend de cajita/modal
- Confirmación backend
- Idempotencia
- Cambio de estado y fulfillment
- Preparación para conciliación posterior

## Dependencias
- `TASK-0755`
- `TASK-0757`
- `TASK-0758`

## Criterio de cierre
- `PayPhone` puede activarse desde configuración.
- El pago no activa la compra hasta confirmación backend válida.
- El intento soporta idempotencia y expiración.
- La orden pasa a `paid` y luego a `fulfilled` solo por backend.

## Estado
Completado - 2026-03-31

## Avance actual
- Backend ya prepara la transacción `PayPhone` a partir de `checkout_draft`.
- El storefront ya puede abrir la cajita de pagos desde el carrito clásico.
- El retorno a `/marketplace` ya confirma `id + clientTransactionId` contra `PayPhone` antes de activar la compra.
- La activación de la compra sigue ocurriendo solo tras confirmación backend válida.
- Buyer, detalle y `Ventas Sistema` ya exponen además la huella operativa de `PayPhone` bajo la misma semántica del resto de pagos.
