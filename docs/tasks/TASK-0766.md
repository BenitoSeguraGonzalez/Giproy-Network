# TASK-0766 - Reembolso y revocación de acceso para devoluciones automáticas y manuales

## Objetivo
Separar la devolución económica del simple cambio de estado para que toda devolución implique también la revocación real del activo comprado.

## Alcance
- Modelo `refund`
- Revocación o borrado del activo entregado
- Reembolso por método de pago
- Trazabilidad de devolución
- Compatibilidad con devolución automática y manual

## Dependencias
- `TASK-0755`
- `TASK-0759` o `TASK-0760` o `TASK-0761`
- `TASK-0764`
- `TASK-0765`

## Criterio de cierre
- Una devolución aprobada revoca el acceso al activo de forma segura.
- El sistema registra `refund_status`, timestamps y motivo.
- `PayPhone`, `PayPal` y `Transferencia bancaria` tienen camino previsto de devolución según su naturaleza.
- La devolución no deja activos huérfanos ni accesos residuales.

## Estado
Completado - 2026-03-31

## Avance 2026-03-31
- Se añadió el modelo `marketplace_refunds` como base de reembolso trazable.
- Ya existe refund de orden completa para pedidos elegibles: automático para comprador dentro de ventana y manual para superadministración.
- La revocación de acceso se realiza por `MarketplaceAssetOrigin`, marcando el activo como revocado y sacándolo de biblioteca/uso normal sin borrar entidades físicas.
- El pedido ya expone también `refund_mode`, `refund_reason`, `refunded_at` y actor asociado para que buyer y backoffice no vean el reembolso como un simple cambio de estado.
- El refund queda además acompañado por una resolución operativa explícita según método de pago, cubriendo reversa bancaria manual y conciliación pendiente con proveedores online.
