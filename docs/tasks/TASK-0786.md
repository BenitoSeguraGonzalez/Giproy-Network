# TASK-0786

## Objetivo
Hacer explícitos los modos de sincronización entre `Base Maestra` y `Base de Proyecto` mediante preview operativo y carriles separados de sync/reparación.

## Estado
Completado.

## Alcance
- Añadir `preview` backend para `sync-missing`.
- Añadir endpoint explícito `repair-inherited`.
- Reutilizar un mismo criterio interno para preview, sync y repair.
- Mejorar el mensaje de confirmación y resultado en `BasesTrabajo`.

## Resultado
- La sincronización deja de ser una caja negra.
- El usuario ve antes cuántos faltantes se agregarán, cuántos heredados están reparables y cuántos divergentes no se tocarán.
- El historial operativo ya muestra también ejemplos concretos de APUs reparables o divergentes intactos, no solo contadores.
- `repair-inherited` deja de ser una capacidad escondida en backend y pasa a ser una acción explícita en la UI de bases de proyecto.
- La misma preview permite resolver ambos carriles: sincronizar faltantes o reparar heredados de forma conservadora.
