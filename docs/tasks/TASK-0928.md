# TASK-0928 - Modelo Formal De Dependencias Gantt

## Modo
GIPROY CLASICO

## Estado
Completada - Slice 1

## Objetivo
Introducir un contrato formal de dependencias compatible con Microsoft Project, manteniendo compatibilidad con las predecesoras legacy actuales.

## Alcance
- Añadir schema `CronogramaTrabajoDependency`.
- Soportar tipos `FS`, `SS`, `FF`, `SF`.
- Soportar `lag_days` y `lag_unit`.
- Convertir `predecessors: [id]` legacy a `FS + 0d`.
- Validar IDs inexistentes, autorreferencias y ciclos.
- Mantener respuesta compatible para frontend actual durante la transición.

## Implementado En Este Slice
- Se añade `CronogramaTrabajoDependency` al contrato backend.
- `CronogramaTrabajoLinea` y `CronogramaTrabajoComputedRow` exponen `dependencies` sin eliminar `predecessors`.
- El backend normaliza predecesoras legacy como dependencias `FS + 0d`.
- La validación de IDs usa el contrato normalizado, conservando los guardarraíles actuales.
- El exportador XML MS Project usa el tipo formal cuando existe y conserva `FS` para datos legacy.
- No se cambia la UX del Gantt ni se introduce migración destructiva.

## Criterio De Aceptación
- Cronogramas existentes siguen abriendo sin migración destructiva.
- El backend puede emitir dependencias ricas y predecesoras legacy.
- No hay dependencia BIM ni cambios de UX BIM.
