# TASK-0934 - Esfuerzo, Cuadrilla Y Rendimiento APU

## Modo
GIPROY CLASICO

## Estado
Completada - Slice 1 / Reclasificada Como Auxiliar

## Objetivo
Consolidar la relación inversa entre duración y cuadrilla desde el rendimiento real de recursos del APU como cálculo auxiliar, no como motor dominante del cronograma.

## Alcance
- Formalizar esfuerzo efectivo en horas.
- Usar días y horas laborables para convertir esfuerzo a duración.
- Mantener relación inversa `Duración <-> Cuadrilla`.
- Preparar indicadores de sobrecarga simple.

## Criterio De Aceptación
- Aumentar duración reduce cuadrilla proporcionalmente cuando el esfuerzo se mantiene.
- Aumentar cuadrilla reduce duración proporcionalmente cuando el esfuerzo se mantiene.
- El cálculo respeta calendario laboral vigente.

## Implementación
- `CronogramaGantt` formaliza el esfuerzo efectivo de cada tarea desde `trabajo_total` / `horas_total` calculado por APU.
- La relación `Duración <-> Cuadrilla` usa ahora:
  - `esfuerzo_horas = trabajo_total`.
  - `cuadrilla = esfuerzo_horas / (duracion_laborable * jornada_laboral_horas)`.
  - `duracion_laborable = esfuerzo_horas / (cuadrilla * jornada_laboral_horas)`.
- El cálculo deja de aplicar un factor semanal residual porque, desde `TASK-0931`, la duración del Gantt ya representa días laborables efectivos.
- Los cambios por input y por resize de barra pasan por la misma normalización de esfuerzo antes de quedar como borradores locales.
- El backend común de `cronogramas-trabajo` recalcula `recursos_asumidos` cuando se persiste una duración manual, usando el esfuerzo del APU y la jornada laboral vigente.

## Reclasificación 2026-04-07
- La regla `Duración <-> Cuadrilla <-> Rendimiento` deja de ser eje principal de planificación.
- El flujo rector aprobado pasa a ser `Gantt -> Cronograma Valorado -> Flujo de Caja`, con retorno controlado `Gantt <-> Valorado <-> Caja`.
- Este cálculo permanece como soporte técnico de recursos/APU y no debe bloquear la integración integral de cronogramas.
