# TASK-0947 - Saneamiento de periodos en Cronograma Valorado

## Estado
Completada - 2026-04-07

## Modo

## Objetivo
Corregir el calculo de periodos de `Proyecto > Cronogramas > Cronograma Valorado` para que el plazo operativo y el tipo de periodo controlen de forma coherente el label de periodos, el grid de trabajo, el pie y la Curva S.

## Plan De Saneamiento
1. Sustituir el corte por mes calendario por una base operativa nominal: diario 1 dia, semanal 7, quincenal 15, mensual 30, bimestral 60, trimestral 90, semestral 180 y anual 360.
2. Usar `plazo_ejecucion` como referencia de conteo cuando exista, evitando que una fecha final civil ligeramente desfasada genere un periodo extra.
3. Mantener el ultimo periodo ajustado a la fecha final visible del proyecto para no ocultar el rango operativo declarado.
4. Hacer que el frontend previsualice el cambio de tipo de periodo en el label, matriz, pie y Curva S antes de aplicar la configuracion.
5. Normalizar distribuciones al nuevo numero de periodos para evitar columnas con porcentajes desfasados.
6. Cubrir el caso real `180 dias + mensual = 6 periodos` con tests backend.

## Cambios
- Backend `cronogramas.py`: `_build_periods` calcula periodos por duracion operativa nominal y acepta `plazo_days`.
- Frontend `Cronogramas.jsx`: se agrega previsualizacion de periodos, distribucion, footer y Curva S segun el tipo seleccionado.
- Frontend `Cronogramas.jsx`: se bloquea la edicion de celdas de porcentaje mientras el cambio de tipo de periodo esta solo en previsualizacion y aun no fue aplicado, evitando guardar distribuciones con longitud distinta al contrato persistido.
- Frontend `Cronogramas.jsx`: el aviso de guardado de celda muestra el motivo real del error cuando no viene de backend.
- Frontend `Cronogramas.jsx`: se corrige regresion visual del header de periodos, usando fondo opaco y capa sticky superior para evitar que los valores del cuerpo se vean por debajo.
- Frontend `Cronogramas.jsx`: el guardado de porcentajes por celda deja de activar la recarga global del grid; ahora aplica una actualizacion optimista local de fila, pie y Curva S, persiste en backend y revierte si falla.
