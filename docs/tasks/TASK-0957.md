# TASK-0957 - Trazabilidad Operativa De Flujo De Caja

## Modo
GIPROY CLASICO

## Estado
Completada - Slice 1

## Objetivo
Mejorar la lectura operativa del `Flujo de Caja` dentro del contrato `Gantt <-> Cronograma Valorado <-> Flujo de Caja`, sin convertir Caja en editor inverso ni modificar Gantt automáticamente.

## Alcance
- Mostrar el origen funcional del flujo de caja vigente.
- Confirmar consistencia entre `Flujo de Caja` y `Cronograma Valorado`.
- Identificar total acumulado y periodo de mayor costo.
- Preparar la superficie para una futura restricción financiera controlada `Caja -> Valorado/Gantt`.

## Implementación Slice 1
- La pestaña `Flujo caja` muestra una banda operativa con:
  - origen de la caja (`Gantt vía Valorado`, `Gantt + overrides valorados`, `Valorado con overrides` o distribución valorada);
  - total acumulado de caja;
  - pico de caja por periodo;
  - estado de consistencia frente al Valorado vigente.
- No se añaden endpoints ni persistencia.
- No se habilita edición inversa de Caja.
- No se modifican fechas, dependencias, recursos ni calendario del Gantt.

## Criterios De Aceptación
- El usuario puede saber si Caja deriva de Gantt, de Valorado o de overrides.
- Caja avisa si el acumulado no cuadra contra el Valorado vigente.
- La UI mantiene la bidireccionalidad inversa como lectura/reconciliación explícita, no como mutación automática.
