# TASK-0963 - Partidas Candidatas En Borrador Financiero

## Modo
GIPROY CLASICO

## Estado
Completada - Slice 1

## Objetivo
Mejorar el flujo `Caja -> Valorado` para que el borrador financiero explique no solo los periodos afectados, sino también las partidas candidatas que concentran o podrían absorber el ajuste.

## Alcance
- Mantener `Preparar borrador` como acción local y controlada.
- Enriquecer el diff `actual -> propuesta` con partidas candidatas por periodo.
- No guardar automáticamente.
- No modificar Gantt.
- No introducir contrato nuevo de API.

## Implementación Slice 1
- El diff previo del borrador financiero calcula partidas candidatas desde las filas visibles del Cronograma Valorado.
- Para periodos a reducir, prioriza partidas que ya concentran costo en ese periodo.
- Para periodos a incrementar, prioriza partidas con mayor capacidad económica potencial para recibir distribución.
- El diálogo de confirmación muestra hasta dos partidas candidatas por periodo relevante.
- El borrador sigue cargando una distribución global `Definido por usuario`; la aplicación por partida queda reservada para una fase posterior con confirmación explícita.

## Criterios De Aceptación
- El usuario ve qué partidas explican los cambios principales del borrador.
- No se crean cambios silenciosos sobre Gantt, Valorado ni Caja.
- La persistencia sigue dependiendo de `Aplicar configuración`.
