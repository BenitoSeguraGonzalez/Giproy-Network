# TASK-0964 - Aplicación Controlada Por Partidas

## Modo
GIPROY CLASICO

## Estado
Completada - Slice 1

## Objetivo
Avanzar el flujo inverso `Caja -> Valorado` desde una lectura de propuesta hacia una aplicación controlada por partidas, sin modificar Gantt ni introducir cambios silenciosos.

## Alcance
- Añadir una acción explícita para aplicar una propuesta por partidas.
- Usar el contrato existente de actualización de línea del Cronograma Valorado.
- Mantener confirmación previa e impacto visible.
- No crear endpoint nuevo.
- No mover fechas, dependencias, recursos ni calendario del Gantt.

## Implementación Slice 1
- Se añade helper de borrador por partidas que redistribuye importes desde periodos con superávit hacia periodos deficitarios frente a la referencia lineal.
- La propuesta opera sobre líneas calculables del Cronograma Valorado y genera overrides por línea.
- La pestaña `Flujo caja` incorpora la acción `Aplicar por partidas`.
- Antes de guardar, el modal muestra redistribución aproximada, líneas afectadas y movimientos principales.
- Si falla una actualización, se revierte el estado local previo y se muestra error.

## Criterios De Aceptación
- El usuario puede aplicar una propuesta financiera por partidas solo tras confirmación explícita.
- El Gantt no se modifica.
- La operación queda en overrides de Cronograma Valorado y puede revertirse con `Limpiar overrides`.
- No se añade API nueva ni persistencia paralela.
