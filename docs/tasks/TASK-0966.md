# TASK-0966 - Ancla Horaria De Jornada En Gantt, Valorado Y Caja

## Modo
GIPROY CLASICO

## Estado
Completada - Slice 1

## Objetivo
Expandir el modelo temporal del flujo `Gantt <-> Cronograma Valorado <-> Flujo de Caja` para que los cálculos se anclen en una `hora_inicio_jornada` explícita y dejen de trabajar solo con fechas civiles a medianoche.

## Alcance
- Añadir `hora_inicio_jornada` al contrato común de `cronogramas-trabajo`.
- Aplicar esa hora como valor por defecto cuando una fecha no traiga hora explícita.
- Medir la periodización `Gantt -> Valorado` por ventanas de jornada (`hora_inicio_jornada + jornada_laboral_horas`).
- Propagar el nuevo concepto a la exportación MS Project y a la UI clásica.
- No tocar BIM.

## Implementación Slice 1
- `CronogramaTrabajoConfig` incorpora `hora_inicio_jornada`.
- El backend común normaliza inicio de jornada, duración horaria y fin de jornada al resolver filas y exportar MS Project.
- El XML de MS Project usa la nueva hora de inicio para `StartDate` y para el calendario laboral (`FromTime` / `ToTime`).
- `Cronograma Valorado` toma la configuración del Gantt para construir periodos y distribuciones con fecha-hora efectiva.
- La periodización `Gantt -> Valorado` ya no reparte por fechas planas, sino por horas de jornada solapadas en cada periodo.
- La UI clásica de `Cronogramas` y `Gantt` permite guardar `hora_inicio_jornada` y persiste `start_date` / `end_date` con hora local de trabajo.

## Criterios De Aceptación
- Si no existe hora explícita, el sistema arranca por defecto en la hora de inicio de jornada configurada.
- Los periodos valorados muestran `Fecha / hora inicio` y `Fecha / hora fin` coherentes con esa jornada.
- La distribución `Gantt -> Valorado` considera horas efectivas de jornada y no solo medianoches.
- La exportación MS Project refleja la jornada real de inicio.
- No se rompe el flujo clásico existente ni se introduce acoplamiento BIM.
