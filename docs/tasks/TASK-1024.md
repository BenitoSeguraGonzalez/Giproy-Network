# TASK-1024 - Implementar Motor CPM/PDM Autoritativo En Backend Clasico

## Modo
GIPROY CLASICO

## Estado
Open

## Objetivo
Construir el motor CPM/PDM autoritativo del cronograma clasico en backend comun para que `ES`, `EF`, `LS`, `LF`, `HT`, `HL`, restricciones y rutas criticas salgan de una sola fuente matematica auditable.

## Alcance
- Implementar forward pass y backward pass en backend.
- Soportar dependencias `FS`, `SS`, `FF`, `SF` con `lag/lead`.
- Detectar ciclos, hitos, holgura negativa y multiples rutas criticas.
- Incorporar restricciones `SNET`, `SNLT`, `FNET`, `FNLT`, `MSO`, `MFO`.
- Hacer que frontend consuma el resultado ya calculado.

## Criterios De Cumplimiento
- Backend devuelve `ES/EF/LS/LF/HT/HL` por actividad.
- Todas las reglas del documento se resuelven en backend, no en frontend.
- Multiples rutas criticas y holgura negativa quedan identificadas.
- Existen tests matematicos del motor.

## No Interferencia BIM
- Sin cambios en BIM, rutas BIM, feature flags BIM, modelos BIM ni UX BIM.

## Plan De Ajuste
1. Definir estructuras de actividad, dependencia y resultado CPM.
2. Implementar algoritmo topologico con deteccion de ciclos.
3. Implementar forward/backward pass y restricciones.
4. Exponer resultados en el servicio/endpoint del cronograma clasico.
5. Cubrir con tests unitarios y de contrato.
