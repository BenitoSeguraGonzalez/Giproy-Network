# TASK-1031 - Contrato Dual De Duracion Gantt Clasico Vs Exportacion Project

## Modo
GIPROY CLASICO

## Estado
Done

## Objetivo
Separar de forma explícita la duración operativa visible del `Gantt` clásico de la duración usada para interoperabilidad `MS Project` o equivalente, sin romper el backend común ni contaminar BIM.

## Alcance
- Mantener para el módulo actual del Gantt la fórmula directa desde `cantidad x rendimiento gobernante`.
- Mantener para exportación `Project/XML equivalente` la formulación basada en `recursos asumidos`.
- Permitir duraciones subdía reales en el Gantt clásico.
- Evitar que la cuadrilla asumida reescriba automáticamente la duración visible del módulo.

## Criterios De Cumplimiento
- El contrato calculado distingue claramente duración Gantt y duración exportable.
- El Gantt clásico puede representar duraciones menores a una jornada.
- La exportación Project conserva el carril de duración por recursos asumidos.
- No se tocan rutas ni UX BIM.

## No Interferencia BIM
- Sin cambios en BIM, rutas BIM, feature flags BIM, modelos BIM ni UX BIM.

## Implementacion
1. Se amplía `CronogramaTrabajoComputedRow` con campos específicos de exportación:
   - `duracion_horas_exportacion`
   - `dias_utiles_exportacion`
   - `dias_calendario_exportacion`
2. El backend clásico resuelve un contrato dual:
   - `Gantt clásico`: duración desde `trabajo_gobernante`
   - `Exportación Project`: duración desde `trabajo_gobernante / recursos_asumidos`
3. El backend publica además `metadata.duration_contract` para auditoría del carril activo y del carril exportable.
4. El exportador `MS Project` usa la duración de exportación y recompone el `finish` desde ese carril.
5. El frontend del Gantt admite duraciones fraccionales y deja de acoplar automáticamente `duration <-> assumed_resource_units` en la vista clásica.
