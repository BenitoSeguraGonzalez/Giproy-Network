# TASK-1033 - Recuperar Presupuesto Operativo En Gantt Cuando El Selector Queda Desincronizado

## Modo
GIPROY CLASICO

## Estado
Closed

## Objetivo
Evitar que `Proyectos > Cronogramas > Gantt` muestre el estado vacío `Sin cronograma operativo` cuando el presupuesto operativo existe pero el `selectedBudgetId` queda vacío o desincronizado del listado local.

## Alcance
- Blindar la resolución del presupuesto activo en `Cronogramas.jsx`.
- Reconstruir el presupuesto operativo desde datos ya cargados (`selectedBudgetDetail`, `cronogramaTrabajo`, `cronograma`, `budgets`).
- Reinyectar el `selectedBudgetId` cuando sea recuperable.

## Criterios De Cumplimiento
- El Gantt no debe caer al estado vacío si ya existe un presupuesto operativo recuperable.
- La cabecera del Gantt debe mostrar un presupuesto consistente aunque el listado llegue tarde o quede desincronizado.
- No se debe tocar BIM ni depender de BIM.

## No Interferencia BIM
- Sin cambios en BIM, rutas BIM, flags BIM, modelos BIM ni UX BIM.

## Implementacion 2026-04-11
- Se añade una resolución `inferredBudgetId` con fallback desde:
  - `selectedBudgetId`,
  - `selectedBudgetDetail.id`,
  - `cronogramaTrabajo.presupuesto_id`,
  - `cronograma.presupuesto_id`,
  - primer presupuesto del listado.
- `selectedBudget` deja de depender solo del array `budgets` y puede reconstruirse con un objeto fallback cuando el id existe pero el listado todavía no lo refleja.
- Se añade una resincronización automática del `selectedBudgetId` cuando el presupuesto puede inferirse.
- Se endurece la selección para ignorar `selectedBudgetId` obsoletos si ya no coinciden con `budgets` ni con ids persistidos en `selectedBudgetDetail`, `cronogramaTrabajo` o `cronograma`.
- Las recargas, reportes, exportaciones e importaciones del módulo pasan a depender del presupuesto resuelto y validado, no solo del estado local crudo.
- Se corrige un `ReferenceError` en `CronogramaGantt` reordenando los `useMemo` de recomendaciones para que no consuman `visibleCalculableRows` ni `displayPlanningMap` antes de su inicialización.

## Validacion
- `npm run build` en `frontend` correcto.

## Resultado
- El Gantt clásico deja de mostrar falsamente `Sin cronograma operativo` por pérdida local del presupuesto activo.
- El módulo resiste mejor recargas, cambios de revisión y desincronizaciones del selector local sin romper el acceso al presupuesto operativo.
