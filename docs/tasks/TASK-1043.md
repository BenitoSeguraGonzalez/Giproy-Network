# TASK-1043 - Control Calendario Oficial Gantt Ecuador

## Modo
GIPROY CLASICO

## Estado
Done

## Objetivo
Centralizar el calendario oficial de festivos del Gantt clásico con catálogo maestro, snapshot por proyecto y overrides manuales, usando Ecuador como país inicial de despliegue.

## Alcance
- Maestro backend de festivos oficiales.
- Snapshot por proyecto para el Gantt.
- Overrides manuales por proyecto.
- Integración en `Configuración de Proyecto`.
- Sin BIM.

## Subtasks
- `TASK-1044`: modelo de datos y catálogo maestro.
- `TASK-1045`: integración backend con cronograma de trabajo.
- `TASK-1046`: UI clásica de calendario de festivos.
- `TASK-1047`: QA y documentación.

## Criterios De Cumplimiento
- El Gantt consulta un snapshot propio del proyecto y no depende de internet en tiempo real.
- Los festivos oficiales nacionales Ecuador se cargan en el período operativo.
- El proyecto puede añadir o desactivar festivos sin contaminar el maestro.
- Existe recarga y reset del calendario.
- El cálculo laboral del Gantt respeta esos días no laborables.

## No Interferencia BIM
- Sin rutas BIM, sin UX BIM, sin feature flags BIM y sin contratos BIM nuevos.

## Implementacion Ejecutada
- Se incorpora el modelo base `maestro + snapshot + overrides` para festivos del Gantt clásico.
- El backend ya centraliza fuentes y festivos oficiales Ecuador en tablas propias.
- El cronograma de trabajo consume el snapshot del proyecto y respeta esos días como no laborables.
- `Configuración de Proyecto` ya expone consulta, recarga, reset, alta manual y desactivación por proyecto.
- Los festivos manuales y overrides quedan anclados al `proyecto raíz`, por lo que afectan a todas sus revisiones sin duplicar ni fragmentar calendario.
- La UI clásica sustituye el listado de festivos por un calendario visual mensual que resalta días laborables, no laborables y festivos oficiales o manuales.
- El detalle del festivo ya no ocupa un listado persistente: se consulta con `tooltip` sobre el día y con panel contextual del día seleccionado.
- Se aplica la migración `fb1c2d3e4f5a_project_holiday_calendar_foundation.py` sobre la base activa para habilitar el slice de calendario.
- Se corrige el alta inicial del snapshot para persistir `start_date` y `end_date` antes del primer `flush`, evitando fallo `NOT NULL` durante la primera importación real.
- Se ejecuta la primera importación efectiva del maestro Ecuador para `2025-2028` y se precalienta el snapshot del proyecto `SantiagoBermeo-2026-001`.
- Se añade la utilidad operativa `backend/scripts/prewarm_project_holiday_calendars.py` para resembrar el maestro y precalentar snapshots reales del entorno clásico de forma repetible.
- Se ejecuta una pasada `--force-refresh` sobre la base activa y se confirma precarga efectiva del proyecto clásico disponible con cobertura local `resolved`.
