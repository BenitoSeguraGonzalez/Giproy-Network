# TASK-1064 - Alineación Visible De Codificación En Presupuesto Clásico

## Modo
GIPROY CLASICO

## Estado
DONE

## Objetivo
Extender la misma semántica visible de `Item` y `Cod EDT` al árbol operativo de `Presupuesto`, manteniendo intacto el contrato clásico `EDT -> Presupuesto`.

## Alcance
- `frontend/src/components/presupuestos/LineasPresupuestoTab.jsx`
- Headers, badges y lectura visible de filas estructurales y líneas APU.
- Sin recálculo de códigos backend.

## Criterios De Cumplimiento
- El usuario puede distinguir visualmente `Cod EDT` y `Item` también en `Presupuesto`.
- No se rompe drag & drop, selección, tanteo ni navegación.
- `codigo_item` permanece como identidad de línea presupuestaria/APU.

## No Interferencia BIM
- Cambio limitado a `Presupuesto` clásico.

## Implementacion
- El árbol operativo de `Presupuesto` refuerza visualmente la separación entre `Item` y `Cod EDT`.
- Corrección de criterio aplicada:
  - `Item` = numeración secuencial visible de filas.
  - `Cod EDT` = código jerárquico visible de la fila actual.
- Las filas estructurales `EDT` muestran su numeración visible en `Item` y su `Cod EDT` solo cuando corresponde al nivel mostrado.
- Las líneas presupuestarias/APU dejan de mostrar un bloque dual `Item / Cod EDT` dentro de una sola columna y pasan a alinearse con dos columnas reales separadas, como en la referencia visual aprobada.
- El ajuste se aplica al carril virtualizado/memoizado, que es el render operativo visible del presupuesto clásico.

## Validacion
- `npm run build` OK en `frontend`.
- Verificación explícita de no interferencia BIM sobre alcance y archivos tocados.
