# TASK-1071 - Contrato Temporal Base Diaria Y Reagrupación Visible

## Modo
GIPROY CLASICO

## Estado
DONE

## Objetivo
Formalizar en backend y frontend la unidad base `día operativo efectivo` y separar definitivamente esa base interna del formato visible de periodos.

## Alcance
- Modelo temporal base diario.
- Reglas de reagrupación a `mensual`, `quincenal`, `semanal`, etc.
- Diferencia operativa entre `cambiar presentación` y `rehacer homogéneo`.
- Respeto a `hora_inicio_jornada` y `jornada_laboral_horas`.

## Entregables Esperados
- Contrato técnico claro para secuencia diaria por línea.
- Reagrupación visible sin redistribución silenciosa.
- Acción futura de `rehacer homogéneo` distinguida del simple cambio de vista.

## Riesgos A Vigilar
- Proyectos que inician fuera del comienzo del mes.
- Periodos parciales.
- Meses con distinta longitud.
- Hitos o duraciones cero.

## No Interferencia BIM
- Sin BIM.

## Implementacion
- Backend: `backend/app/api/endpoints/cronogramas.py` deja de construir periodos visibles con spans planos `30/15/7` y pasa a reagrupar sobre limites reales de calendario (`mensual`, `quincenal`, `bimestral`, `trimestral`, `semestral`, `anual`) respetando `hora_inicio_jornada` y `jornada_laboral_horas`.
- Frontend: `frontend/src/components/projects/Cronogramas.jsx` replica el mismo contrato para la previsualizacion local del cambio de tipo de periodo, evitando divergencia entre preview y backend.
- El cursor entre periodos queda normalizado al inicio real de la jornada siguiente para no heredar la hora de cierre del periodo anterior.
- La implementacion mantiene intacto el resto del flujo: no introduce todavia derivacion economica nueva, no toca subbarras Gantt y no altera BIM.

## Validacion

- `PYTHONPATH=backend pytest backend/app/tests/test_numeric_integrity_secondary_modules.py -q` OK.
- `npm run build` en `frontend` OK.
