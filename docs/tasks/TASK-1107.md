# TASK-1107 - Implementación Del Reset Integral Clásico

## Modo
GIPROY CLASICO

## Estado
DONE

## Objetivo
Implementar endpoint backend, contrato API frontend y acción UX clásica para resetear integralmente los cronogramas del presupuesto activo.

## Criterios De Cumplimiento
- Endpoint común con permisos de edición.
- Respuesta combinada `cronograma + trabajo`.
- Acción visible en `Cronogramas.jsx`.
- Recarga atómica del estado local sin inconsistencias visuales.

## Resultado
- Backend: nuevo `POST /cronogramas-trabajo/{presupuesto_id}/reset-integral`.
- Frontend: nuevo `cronogramasApi.resetIntegral(...)`.
- UX clásica: la acción queda ubicada en las opciones generales del `Gantt` clásico (`Sparkles`), con doble confirmación antes de ejecutar el reset.
- Semántica de recreación corregida: el reset deja el `Valorado` en modo `gantt` y persiste una semilla operativa continua por línea (`factory_reset_seed`) para evitar la regeneración de subsegmentos homogéneos por periodo.
- Endurecimiento posterior: el carril de drag de subbarras promociona `factory_reset_seed -> gantt_manual_move` en el primer movimiento y usa el mismo desplazamiento laboral/configurado del Gantt clásico para no romper el arrastre tras el reset.
