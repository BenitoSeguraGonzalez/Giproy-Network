# TASK-1141 - Ejecución del slice inicial de ruta crítica integral en Gantt clásico

## Objetivo
Implementar el primer slice completo y seguro de ruta crítica integral en el Gantt clásico, reforzando backend y frontend sin reescribir la geometría ni la experiencia operativa consolidada.

## Alcance autorizado
- `backend/app/services/cronograma_trabajo.py`
- `backend/app/tests/test_cronograma_trabajo_cpm_metadata.py`
- `frontend/src/components/projects/CronogramaGantt.jsx`
- Sin activar ni mostrar UX BIM
- Sin introducir acoplamientos hacia BIM

## Implementación
- Se amplía la metadata CPM por fila para publicar:
  - conteo de rutas críticas activas
  - rutas críticas a las que pertenece la tarea
  - duración total de la red
  - estado de restricción
  - advertencias CPM
- Se mantiene el motor backend como autoridad y no se sustituye la programación visible actual.
- El Gantt clásico consume esta metadata con señales seguras y no disruptivas:
  - chips compactos por tarea para rutas múltiples, holgura negativa y restricción
  - tooltips enriquecidos con lectura de ruta crítica
  - bloque contextual por tarea con holguras, rutas, restricción y advertencias
- No se altera la geometría de barras, la segmentación de subtramos ni el color base de trabajo.
- Se endurece además la captura de `Ctrl + rueda` sobre el viewport real del Gantt clásico:
  - listener nativo no pasivo
  - fase de captura
  - callback estable para evitar fugas entre renders
  - sin tocar la semántica del zoom general ni la navegación BIM

## Validación
- `pytest backend/app/tests/test_cronograma_trabajo_cpm_metadata.py -q`
- `npm run build`
- `node frontend/scripts/smoke-cronogramas-gantt-subbars.mjs`
- `node frontend/scripts/smoke-cronogramas-gantt-zoom.mjs`

## Resultado
La ruta crítica del Gantt clásico deja de ser solo un dato técnico paralelo y pasa a integrarse de forma útil, visible y segura dentro del flujo clásico.
