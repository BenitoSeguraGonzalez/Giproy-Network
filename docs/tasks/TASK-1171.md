# TASK-1171 - Control maestro de adecuación integral del Gantt clásico a lógica MS Project en castellano

## Objetivo
Gobernar y cerrar la adecuación integral del módulo de secuenciación del `Cronograma Gantt` clásico para que adopte la lógica de Microsoft Project, manteniendo la nomenclatura visible en castellano (`Predecesoras`, `Sucesoras`, `FC/CC/FF/CF`).

- `docs/tasks/TASK-1171.md`
- `docs/tasks/TASK-1172.md`
- `docs/tasks/TASK-1173.md`
- `docs/tasks/TASK-1174.md`
- `docs/runtime/WORK_MODE_STATE.json`
- `docs/CHANGELOG.md`
- Sin tocar backend común en esta apertura
- Sin activar UX BIM
- Sin introducir acoplamientos hacia BIM

## Subtasks gobernadas
- `TASK-1172`: contrato funcional, modelo de dependencias e identidad MSP-compatible con presentación en castellano
- `TASK-1173`: UX del grid y edición de `Predecesoras/Sucesoras` alineadas con la lógica de MS Project en castellano
- `TASK-1174`: representación gráfica, QA funcional y alineación con import/export para dependencias MSP-compatibles

## Criterio funcional del frente
- Lógica interna compatible con Microsoft Project.
- Nomenclatura visible en castellano.
- `Predecesoras` como campo maestro editable.
- `Sucesoras` como vista derivada del mismo grafo.
- `FC/CC/FF/CF` como shortcodes visibles.
- `FS/SS/FF/SF` reservados al plano interno y a interoperabilidad.
- Soporte de `lag/lead` y múltiples relaciones en una sola celda.
- `ID de tarea` visible para edición humana y `ID único` estable para persistencia.
- Las dependencias solo pueden existir entre tareas completas; quedan fuera del nuevo modelo los subtramos, subtareas operativas o referencias a segmentos internos.

2. Ejecutar `TASK-1173` sobre el contrato consolidado.
3. Ejecutar `TASK-1174` para representación, QA y cierre del frente.

## Notas de arquitectura
- Este frente reemplaza cualquier semántica híbrida previa y fija como objetivo un módulo nativamente MSP-compatible en lógica, pero castellanizado en UX.
- No se considera necesario mantener compatibilidad retrospectiva de shortcodes o nomenclaturas previas dentro del nuevo diseño.
- La lógica histórica basada en `subbar_id`, `source_subbar_id`, `target_subbar_id` o shortcodes que apuntan a tramos internos no forma parte del modelo objetivo y debe eliminarse del frente nuevo.
- La lectura y edición humana priorizan claridad operativa: cuando una referencia no es única, el sistema debe ayudar a resolverla sin degradar la lógica MSP ni abrir dependencias implícitas.
