# TASK-1172 - Contrato funcional y modelo de dependencias MSP-compatible en castellano

## Objetivo
Redefinir el contrato funcional de secuenciación del Gantt clásico para que su motor sea compatible con Microsoft Project, manteniendo la presentación visible en castellano.

## Alcance autorizado
- `frontend/src/components/projects/CronogramaGantt.jsx`
- Documentación mínima vinculada a este frente
- Sin tocar backend común salvo necesidad justificada en un paso posterior autorizado
- Sin activar UX BIM

## Alcance funcional previsto
- Definir `Predecesoras` como campo maestro editable y `Sucesoras` como campo derivado.
- Introducir el modelo oficial de tipos internos `FS/SS/FF/SF`.
- Definir el mapeo visible `FC/CC/FF/CF`.
- Diseñar `ID de tarea` visible y `ID único` estable para persistencia.
- Redefinir el parser y formatter de shortcodes al estilo MSP con presentación en castellano.
- Soportar múltiples relaciones por celda.
- Soportar `lag` positivo y `lead` negativo, con unidades de duración y porcentaje.
- Limitar el modelo a relaciones entre tareas completas; sin tramos, subbarras ni subtareas operativas como extremos enlazables.

## Casos objetivo
- `14`
- `14FC`
- `6CC+2d`
- `10FF`
- `3CF-50%`
- `4FC,6CC+2d,10FF`

## Criterio de completitud
- El contrato queda centralizado y sin mezclas semánticas dispersas.
- La normalización interna y la presentación visible quedan claramente separadas.
- El módulo deja de depender de convenciones híbridas heredadas.

## Estado
- TASK en progreso.

## Slice 1 ejecutado
- El parser de `Predecesoras` adopta ya el patrón MSP en castellano:
  - `14`
  - `14FC`
  - `6CC+2d`
  - `10FF-50%`
  - múltiples relaciones separadas por coma
- El formatter visible deja de priorizar `tipo + referencia` y pasa a emitir `ID de tarea + tipo opcional + lag/lead`, omitiendo `FC` cuando la relación es la predeterminada sin adelanto ni retraso.
- El `ID de tarea` visible se consolida como referencia principal de salida para shortcodes, manteniendo el código EDT como resolución alternativa de entrada.
- El contrato soporta ya `lag/lead` también en `%`, además de `d`, `h` y `min`.
- La validación deja de imponer que la predecesora esté antes en la secuencia visible y se limita a bloquear autoreferencia o referencias inválidas, más cercano a la lógica de Project.
- La conversión de lag a días incorpora tratamiento de porcentaje respecto de la duración de la tarea origen.
- El flujo nuevo de dependencias deja de ofrecer o persistir relaciones por subtramos: el parser, el formatter y el creador rápido trabajan ya solo con tareas completas.

## Corrección de alcance confirmada
- El modelo objetivo de esta TASK no debe contemplar relaciones contra subtramos o subtareas internas.
- Cualquier soporte legado a referencias tipo `Tnn-Snn`, `source_subbar_id` o `target_subbar_id` queda fuera del diseño final y deberá retirarse en la continuación de la implementación.
