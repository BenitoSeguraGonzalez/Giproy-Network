# TASK-1177 - Integración de serializaciones con duración APU, recurso gobernante, CPM y trazabilidad

## Objetivo
Integrar la nueva lógica de serializaciones temporales con las capacidades ya implementadas del carril clásico: duración base derivada desde APU, `recurso gobernante`, metadata CPM, holguras, criticidad, restricciones y trazabilidad.

## Alcance autorizado
- Documentación y control funcional del frente clásico
- Backend común ya existente de `cronogramas-trabajo` como contrato autoritativo
- Frontend clásico del Gantt como consumidor e integrador
- Sin activar UX BIM
- Sin introducir acoplamientos hacia BIM

## Base existente que se debe respetar
1. `TASK-1034`, `TASK-1036`, `TASK-1048`
   - recurso gobernante individual,
   - trazabilidad del criterio,
   - duración visible alineada a APU.

2. `TASK-1140` y slices CPM posteriores
   - motor CPM backend como autoridad matemática,
   - metadata de criticidad,
   - holguras,
   - restricciones,
   - recomendación CPM y deriva.

## Trabajo aprobado
### Fase 1. Auditoría de integración real
- Revisar qué partes del contrato APU/duración ya consume el Gantt.
- Revisar qué metadata CPM está ya disponible y cómo se usa hoy.
- Detectar contradicciones entre duración base, serialización y cronología visible.
- Verificar qué trazabilidad visible del recurso gobernante y de restricciones ya existe y cuál falta completar.

### Fase 2. Definición del acople correcto
- Fijar cómo conviven:
  - duración base por APU,
  - recurso gobernante,
  - posición temporal impuesta por relaciones,
  - criticidad/holguras,
  - conflicto relacional.
- Definir prioridad entre duración, posición, conflicto y tramos existentes.
- Fijar la convivencia entre barra operativa, criticidad, holgura y restricción dominante.

### Fase 3. Trazabilidad operativa
- Garantizar que la UI o el diagnóstico pueda explicar:
  - recurso gobernante,
  - criterio de selección,
  - duración base,
  - relación dominante,
  - restricción temporal activa,
  - estado crítico / no crítico / holgura negativa.

### Fase 4. Coherencia con colorimetría y semántica de dominio
- Confirmar que la criticidad siga usando estándar azul/rojo del frente clásico.
- Confirmar tratamiento visible de holgura negativa y conflicto sin invadir el código visual BIM.
- Confirmar que la serialización no borra ni contradice la trazabilidad APU/CPM existente.

### Fase 5. Validación
- Confirmar que la adecuación de serializaciones no rompe el frente de recurso gobernante.
- Confirmar que no degrada la lectura CPM ya publicada por backend.
- Confirmar el resultado sobre `Santiago Bermeo`.

## Criterios de aceptación
- No se duplica ni contradice el contrato ya implementado de recurso gobernante.
- La serialización no deja desalineada la lectura de duración base y posición temporal.
- La criticidad, holguras y restricciones siguen siendo coherentes tras la adecuación.
- La trazabilidad visible permite auditar el resultado.
- Las normas visuales derivadas de CPM y conflicto quedan alineadas con el contrato visual maestro del frente.
