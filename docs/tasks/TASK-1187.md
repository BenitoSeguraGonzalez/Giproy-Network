# TASK-1187 - Drag seguro respetando políticas temporales del Gantt clásico

Estado
DONE

Tipo
functional-ux

Prioridad
high

Descripción
Adecuar el drag'n drop existente del Gantt clásico para que el ratón pueda proponer desplazamientos, pero el motor temporal siga mandando: inicio de proyecto, predecesoras `FC/CC/FF/CF`, cascada de sucesoras y tramos operativos no pueden romper la política actual.

Alcance
- Solo capa clásica.
- Solo interacción de arrastre existente en Gantt.
- Sin reabrir lógica BIM, sin UX BIM y sin acoplamientos hacia BIM.
- Sin sustituir el motor de predecesoras: el drag reutiliza sus restricciones.

Checklist

[x] Crear task de control e implementación.
[x] Auditar flujo existente de `pointermove/pointerup`.
[x] Mantener drag de tareas sin predecesoras.
[x] Bloquear/snapear tareas gobernadas por predecesoras a su fecha política.
[x] Mantener cascada de sucesoras cuando se mueve una tarea origen.
[x] Aplicar mínimo de inicio de proyecto y mínimo relacional a subtramos arrastrados.
[x] Añadir smoke de guardarraíl.
[x] Documentar.

Validación ejecutada
- `node scripts/smoke-cronogramas-gantt-subbars.mjs`
- `npm run build`

Resultado
- Una tarea sin predecesoras puede moverse con ratón y sus sucesoras se recalculan por la cascada existente.
- Una tarea que recibe predecesoras queda anclada a la fecha gobernada por `FC/CC/FF/CF`; el drag no puede convertir una relación autoritativa en una posición manual inválida.
- Un subtramo arrastrado conserva el mínimo de inicio de proyecto y de predecesoras de su tarea.
- Cronograma Valorado conserva la sincronización ya existente vía guardado batch de Gantt.
- Sin interferencia con GiProy BIM.
