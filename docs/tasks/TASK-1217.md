# TASK-1217 - Contrato compatible de datos y persistencia para calendario avanzado del Gantt

## Objetivo
Diseñar e implantar la nueva capa de persistencia del calendario avanzado del `Gantt` clásico sin sustituir el contrato simple vigente.

## Alcance
- Extender el contrato de `config`/metadata del cronograma de trabajo para soportar:
  - modo simple vs avanzado
  - patrón semanal laborable
  - excepciones por fecha
  - festivos efectivos
  - múltiples franjas horarias por día
- Mantener lectura y escritura compatible con cronogramas previos.

## Requisitos funcionales
- El sistema debe poder seguir calculando con el calendario simple actual si no existe configuración avanzada.
- La nueva configuración avanzada debe quedar persistida por proyecto/revisión del Gantt.
- Debe existir una separación clara entre:
  - patrón semanal
  - excepciones por fecha
  - festivos
  - franjas horarias

## Requisitos de seguridad funcional
- No eliminar campos actuales ni reinterpretarlos de forma destructiva.
- No romper `factory reset`, `initial creation` ni snapshots actuales.
- No mutar cronogramas existentes al solo abrirlos.

## Validación esperada
- QA de serialización/deserialización del contrato.
- QA de compatibilidad con cronogramas legacy.
- QA de lectura estable del frontend sin capa avanzada activa.

## Impacto BIM
- Ninguno.

## Implementación 2026-04-23
- Se añade contrato backend compatible para `advanced_calendar` dentro de `CronogramaTrabajoConfig`.
- El contrato mantiene `enabled: false` y `mode: simple` por defecto, por lo que cronogramas legacy continúan usando el calendario simple actual.
- Se separan estructuras para:
  - patrón semanal (`weekly_pattern`)
  - excepciones por fecha (`date_exceptions`)
  - festivos efectivos (`holidays`)
  - múltiples franjas por día (`slots`)
- Las franjas se normalizan a `HH:MM`, se ordenan por hora de inicio y se rechazan solapes.
- El default común del servicio incluye `advanced_calendar` apagado sin activar cálculos avanzados ni UX BIM.
