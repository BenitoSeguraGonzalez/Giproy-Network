# TASK-1221 - Integración del calendario avanzado en Gantt, dependencias, drag'n drop y representación

## Objetivo
Integrar el nuevo calendario avanzado en el `Gantt` clásico para que cálculos, secuenciación, drag'n drop y representación visual respeten tiempo laborable efectivo real.

## Alcance
- Recalcular `Inicio` y `Fin` visibles con el calendario avanzado.
- Mantener el grid izquierdo sincronizado con el cálculo real.
- Adaptar dependencias `FC/CC/FF/CF` al tiempo laborable efectivo.
- Adaptar `drag'n drop` para que el desplazamiento siga trabajando sobre lag según el secuenciador.
- Mantener representación gráfica estrictamente coherente con los tiempos reales calculados.

## Requisitos funcionales
- Si no hay calendario avanzado, el Gantt debe comportarse como hoy.
- Si el calendario avanzado está activo, la geometría temporal debe seguir el motor avanzado.
- La representación no puede generar lag visual falso.
- La barra y las líneas deben seguir siendo válidas respecto a `Inicio/Fin` reales.

## Requisitos de no regresión
- No romper la navegación crítica.
- No romper el zoom, viewport ni redraw del grid.
- No romper el guardado ni el rollback del drag.

## Validación esperada
- QA funcional en:
  - tareas sin relación
  - `FC`
  - `CC`
  - `FF`
  - `CF`
  - drag'n drop con relaciones
  - festivos
  - días con múltiples franjas

## Implementación 2026-04-23
- `CronogramaGantt` persiste `advanced_calendar` desde `resolveGanttConfigDraft`.
- Las utilidades temporales frontend del Gantt clásico reconocen calendario avanzado activo.
- `isGanttLaborableDate`, `shiftToGanttWorkingDateTime`, `addGanttWorkDuration` y `measureGanttWorkWindowHours` usan franjas reales cuando el calendario avanzado está activo.
- En modo simple, las funciones mantienen el comportamiento previo basado en inicio de jornada, horas por día y días laborables por semana.
- Backend mantiene autoridad final para guardar y recalcular relaciones; frontend evita previsualizaciones falsas durante edición/drag cuando hay franjas múltiples.

## Hotfix 2026-04-23
- Se corrige `ReferenceError: Cannot access 'us' before initialization` en runtime minificado de `CronogramaGantt`.
- Causa: helpers avanzadas de calendario declaradas como `const` quedaban referenciadas desde utilidades tempranas del archivo y podían entrar en zona temporal muerta durante el primer render/bundle minificado.
- Solución: las helpers de calendario avanzado se convierten en declaraciones `function` hoisted para eliminar dependencia de orden de inicialización sin cambiar comportamiento.
- Validado con `npm run build` y pruebas backend objetivo.
