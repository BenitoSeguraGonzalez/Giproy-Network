# TASK-1222 - QA de regresión, migración segura y cierre del calendario avanzado del Gantt

## Objetivo
Cerrar el frente del calendario avanzado del `Gantt` clásico con una validación completa de regresión, una ruta de compatibilidad segura y documentación final de operación.

## Alcance
- Validar compatibilidad con cronogramas anteriores.
- Validar `factory reset` y creación inicial.
- Validar no contaminación de Cronograma Valorado ni BIM.
- Dejar documentada la política de convivencia simple/avanzado.

## Requisitos funcionales
- Un cronograma viejo debe seguir abriendo y calculando correctamente.
- Un cronograma nuevo con calendario avanzado debe recalcular sin romper el resto del ecosistema.
- Debe quedar clara la política de retorno al comportamiento actual si el usuario no aprueba el nuevo frente.

## Checklist mínimo de cierre
- QA backend
- QA frontend
- QA visual
- QA de secuenciación
- QA de drag'n drop
- QA de fechas reales `Inicio/Fin`
- QA de factory reset
- QA de exportes afectados

## Regla de cierre
- No retirar código actual ni degradar el modo simple hasta confirmación explícita del usuario.

## Impacto BIM
- Ninguno.

## Cierre QA 2026-04-23
- Compatibilidad legacy validada con calendario avanzado apagado por defecto.
- Pruebas nuevas cubren:
  - serialización/deserialización de contrato
  - ordenamiento de franjas
  - rechazo de solapes
  - suma/resta atravesando huecos
  - festivos
  - excepciones por fecha
  - lag de dependencias sobre tiempo laborable efectivo
- Regresión de duración existente validada.
- Build frontend validado.

## Validaciones ejecutadas
- `python -m py_compile backend/app/schemas/cronograma_trabajo.py backend/app/services/cronograma_trabajo.py`
- `cd backend && python -m pytest app/tests/test_cronograma_trabajo_advanced_calendar_config.py app/tests/test_cronograma_trabajo_duration_model.py`
- `cd frontend && npm run build`

## Validaciones con incidencia externa
- `cd backend && python -m pytest app/tests/test_cronograma_trabajo_dependency_response.py`
- `cd backend && python -m pytest app/tests/test_cronograma_trabajo_ms_project.py -q`
- Ambas suites contienen escenarios con fechas de abril de 2026 que quedan antes de la fecha actual del sistema de esta sesión (`2026-04-23`) y disparan la validación ya existente de `no iniciar antes del proyecto`.
- La incidencia no proviene del calendario avanzado; los fallos aparecen con `advanced_calendar.enabled === false`.

## Impacto BIM
- Ninguno. No hay cambios en rutas, componentes, hooks ni flags BIM.
