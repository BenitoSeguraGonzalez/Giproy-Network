# TASK-1237 - Control QA de borrado y secuenciación de hitos manuales

## Modo
GIPROY CLASICO

## Tipo
Control / QA / trazabilidad

## Objetivo
Controlar que los hitos manuales del Gantt clásico puedan eliminarse y participar en secuenciación visual sin convertirse en tareas productivas ni romper cálculo, licencias, diseño o BIM.

## Relación
- Frente padre: `TASK-1230`.
- Implementación asociada: `TASK-1238` y `TASK-1239`.

## Criterios de control
- Solo los hitos manuales pueden exponer acción `Eliminar hito`.
- El borrado exige confirmación visual con `appConfirm`.
- El borrado elimina la entrada de `config.manual_milestones`.
- El borrado limpia selección, drafts y relaciones asociadas al hito.
- Un hito manual puede actuar como origen o destino de una relación visual.
- Las relaciones de hitos manuales se persisten dentro de `manual_milestones`, no en `schedule_data` de líneas reales.
- Las tareas reales siguen enviando al backend solo dependencias compatibles con ids numéricos.
- Los hitos manuales conservan duración `0`, coste `0`, recursos `0` y no generan subbarras.
- No se activan rutas, contratos ni UX BIM.

## Licenciamiento
- Sin nueva capacidad licenciable.
- Sin cambios en middleware ni límites.
- No se permite bypass backend: las tareas reales conservan contrato backend compatible.

## Impacto UI
- Medio en Gantt clásico.
- Añade acción contextual de borrado y habilita conectores visuales sobre hitos manuales.
- Debe respetar iconografía y confirmadores del sistema.

## No interferencia BIM
- Sin cambios en rutas o componentes BIM.
- Sin dependencias hacia BIM.

## Validación obligatoria

- `npm run build`.
- `node scripts/smoke-cronogramas-gantt-subbars.mjs`.

- QA visual real/desplegada: crear, mover, secuenciar y borrar hito.
