## Slices de Ejecución

### [ ] Slice 1: Alembic – Validación y migraciones pendientes
- **Responsable:** Backend + Arquitectura
- **Acciones:**
  - Ejecutar `alembic revision --autogenerate` para detectar divergencias actuales entre modelos SQLAlchemy y esquema PostgreSQL real.
  - Validar que no existan columnas/tabla huérfanas ni faltantes en módulos críticos (`presupuestos`, `cronograma_trabajo`, `proyecto_detalles`, `apu_lineas`, `community_posts`, etc.).
  - Generar migraciones consolidadas si no hay drift destructivo; documentar migraciones manuales si las hay.
  - Validar que `alembic upgrade head` sea idempotente en la BD local.
- **Criterio de cierre:** `alembic upgrade head` ejecuta sin errores en BD local.

### [ ] Slice 2: Frontend – Code splitting de páginas monolíticas
- **Responsable:** Frontend + QA
- **Acciones:**
  - Auditar chunks pesados post-build (`rollup-plugin-visualizer` o análisis de `dist/assets`).
  - Aplicar splitting adicional en `Cronogramas`, `PresupuestoDetail`, `Proyectos`.
  - Extraer componentes pesados no críticos en el primer paint a lazy imports con boundary de error.
  - Validar que `npm run build` no genere regresión de chunks ni errores de carga diferida.
- **Criterio de cierre:** `npm run build` genera chunks sin regresión de tamaño (>10% del chunk anterior se justifica).

### [ ] Slice 3: Limpieza de artefactos locales
- **Responsable:** Backend + QA + Documentación
- **Acciones:**
  - Eliminar del árbol de trabajo (no solo `.gitignore`) archivos generados en runtime: `.db`, `dist/`, `__pycache__/`, logs (`auth_debug.log`, `fatal_errors.log`).
  - Verificar que `.gitignore` raíz y subdirectorios cubran todos estos patrones.
  - **Validación crítica:** Nunca borrar archivos fuente `.py`, `.jsx`, `.sql` de seed ni configuraciones operativas.
- **Criterio de cierre:** No existen `__pycache__`, `.db` ni logs de runtime en el árbol de trabajo limpio.

### [ ] Slice 4: Normalización de llamadas API (trailing slashes)
- **Responsable:** Frontend + Backend + QA
- **Acciones:**
  - Auditar `frontend/src/api/` y `frontend/src/services/` para detectar inconsistencias (`/api/v1/recursos` vs `/api/v1/recursos/`).
  - Normalizar todas las llamadas operativas a **sin barra final** (convención REST dominante).
  - Asegurar que `axiosConfig.js` aplique política transversal o documentar excepciones explícitas.
  - Validar con smoke test rápido contra backend local que no haya rotura de rutas.
- **Criterio de cierre:** Todos los endpoints del frontend usan convención consistente de trailing slash.

### [ ] Slice 5: Política de `backend/.env`
- **Responsable:** Arquitectura + Documentación
- **Acciones:**

  - Crear `backend/.env.example` con variables requeridas (sin valores sensibles).
