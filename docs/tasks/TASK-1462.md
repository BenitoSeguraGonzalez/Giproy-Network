## Objetivo
Controlar la implementacion del Codigo CPC para APUs a nivel de proyecto, separado del CPC universal de recursos y respetando APUs anidados.

## Politicas obligatorias
- El CPC de recurso sigue siendo universal por recurso.
- El CPC de APU se persiste por empresa y proyecto raiz, no por revision aislada.
- Un mismo APU puede tener CPC distinto en proyectos distintos.
- Un mismo APU mantiene el mismo CPC entre revisiones del mismo proyecto.
- Un APU anidado que actua como recurso no hereda CPC APU, no muestra `Sin CPC`, queda en blanco y no cuenta como CPC faltante.
- El VAE de un APU anidado usado como recurso es el VAE total calculado de ese APU.

## Impacto licencias
Sin modulo nuevo. Toda lectura/escritura debe validar empresa activa y acceso al proyecto en backend.

## Impacto UI
Desagregacion agrega columna CPC entre Unidad y Cantidad y reutiliza el selector CPC existente.

## No interferencia BIM
No se activa ni modifica UX BIM. Backend comun sin dependencia BIM.

## Validacion requerida para cierre
- Persistencia CPC APU por proyecto raiz.
- Persistencia entre revisiones del mismo proyecto.
- Aislamiento entre proyectos.
- No contaminacion de CPC de recursos.
- APU anidado en blanco, sin contador faltante y VAE calculado desde su APU normal.
- Build y pruebas focalizadas.
