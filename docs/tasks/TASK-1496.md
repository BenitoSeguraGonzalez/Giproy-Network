# TASK-1496 - Control: preview de hito manual no propagaba sucesores

## Estado
Completada al 100%.

## Objetivo
Controlar la regresión detectada tras recuperar el drag del hito manual: durante el arrastre se movía solo el hito y la cascada de sucesores se redibujaba recién al soltar.

## Diagnóstico
- Empresa real usada: `Santiago Bermeo`.
- Proyecto: `7`.
- Presupuesto: `13`.
- Hito manual: `hm-mok8sj9c-j04f`.
- Síntoma:
  - durante el drag solo se desplazaba el rombo del hito;
  - al soltar se recalculaban los sucesores y aparecían rutas visuales inesperadas;
  - los inicios visibles no cuadraban con la relación hito -> tarea.
- Causa real:
  - el preview de cascada se había desactivado para hitos manuales;
  - la capa de dependencias seguía calculándose contra `drafts` persistidos, no contra el estado temporal completo;
  - para hitos manuales el router priorizaba una geometría calculada por fecha en vez de la geometría visual real durante el drag.

## Criterio de cierre
- El preview debe mover hito, sucesora y ruta asociada de forma coherente.
- El commit debe guardar hito y sucesora con el mismo inicio cuando la relación `FS` sin lag lo exige.
