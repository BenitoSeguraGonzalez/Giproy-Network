## Objetivo

Corregir la causa funcional que mantenia divergencias al mover el hito manual inicial: el commit del hito no debe desplazar una cascada antigua por delta si existe una relacion autoritativa; debe reconstruir sucesores desde la regla real de dependencia.

## Cambios

- `frontend/src/components/projects/CronogramaGantt.jsx`
  - El preview de hito manual usa `runtimeBuildDependentScheduleDrafts(...)` para calcular sucesores desde la relacion real.
  - El commit de hito manual deja de priorizar `cascadeShiftPatches` y persiste `dependentPatches`.
  - Se conserva el estado optimista de `manual_milestones` para evitar rebote visual mientras se persiste.
  - Si la persistencia falla, se revierte el snapshot anterior de hitos manuales.

- `frontend/scripts/smoke-cronogramas-gantt-manual-milestone-drag.mjs`
  - El smoke exige que preview y commit de hito manual usen dependencias autoritativas.
  - Mantiene validacion de persistencia optimista y rollback.

- `tmp/rebuild_santiago_gantt_dependencies_clean.py`
  - Herramienta de saneamiento local usada para snapshot, limpieza y reconstruccion real de `Santiago Bermeo`.

## Resultado funcional

- El hito inicial queda en el inicio del proyecto.
- La tarea sucesora directa inicia en la misma fecha/hora del hito cuando la relacion es `FS`/por defecto y el hito no tiene duracion.
- El resto de relaciones se recalcula en cascada con la red limpia.
- No se conservan dependencias antiguas mezcladas en `schedule_data`.
- La relacion `FF` existente `1.1.6 -> 1.1.7` se mantiene como `FF`, con final alineado y sin proyectar tareas antes del inicio del proyecto.
