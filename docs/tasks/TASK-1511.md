# TASK-1511 - Control saneamiento integral drag de hito manual en Gantt

## Objetivo

Gobernar el saneamiento integral de la regresion de movimiento horizontal de hitos manuales en `Proyectos > Cronogramas > Gantt`.

Este control no autoriza parches visuales aislados. El problema debe tratarse como una falla de contrato entre:

- captura de `drag'n'drop`;
- calculo de fecha/hora del hito de duracion cero;
- preview de cascada;
- helper visible de movimiento;
- persistencia real al soltar;
- dependencias `FS/SS/FF/SF` y lags;
- calendario laboral simple y avanzado;
- validacion de inicio de proyecto;
- no contaminacion BIM.

## Diagnostico rector inicial

- El cierre anterior `TASK-1510` no corrigio el problema integral: ataco geometria y clasificacion de `pointerup`, pero el preview sigue apoyado en una cascada que puede divergir del contrato real esperado por el usuario.
- La ruta actual de preview para hito manual vuelve a llamar `buildDependentScheduleDrafts(...)`, que recalcula sucesores desde todas sus dependencias activas.
- En una red real con relacion `FF` aguas abajo, ese recalculo puede reinterpretar una tarea destino desplazando su inicio hacia atras para cumplir el fin, provocando preview incoherente y, en commit, bloqueo por inicio antes del proyecto.
- Existe una funcion historica especifica, `buildManualMilestoneCascadeShiftDrafts(...)`, que desplaza la cascada por delta laboral preservando la forma temporal existente. Esa funcion esta registrada en refs pero no se usa en el flujo actual del hito manual.
- El helper visible mezcla duracion de tarea con movimiento de hito: para un hito de inicio/fin iguales la duracion debe ser `0`, pero el usuario necesita ver delta de movimiento real, no interpretar `0 dias` como ausencia de movimiento.

## Criterios de aceptacion

- Preview y commit usan la misma estrategia temporal para el movimiento horizontal de hito manual.
- El hito manual conserva `start_date === end_date` a efectos funcionales de duracion cero.
- Las sucesoras acompañan el movimiento de forma consistente sin generar inicios antes del proyecto por reinterpretacion de `FF` existente.
- El helper distingue entre duracion del hito (`0`) y delta de movimiento real.
- La validacion compara el calculo de preview contra el calculo aplicado al soltar.
- Sin backend nuevo salvo que el diagnostico demuestre necesidad real.

## Avance de saneamiento aplicado pendiente de validacion

- `CronogramaGantt.jsx` deja de usar `buildDependentScheduleDrafts(...)` para la cascada de preview de un hito manual.
- Preview y commit del hito manual usan ahora `buildManualMilestoneCascadeShiftDrafts(...)` con el mismo delta laboral del movimiento.
- El commit calcula el delta desde fecha anterior/nueva con calendario laboral vigente y, si el resultado cae en cero por redondeo/snap, usa como respaldo el delta ya observado durante el drag.
- El helper visible conserva el concepto funcional de hito de duracion cero, pero muestra el delta de movimiento (`d mov.`) para no confundir `0 dias` con ausencia de desplazamiento.
- Validado tecnicamente por smoke focal, smoke doble ciego preview/commit, smoke clasico completo, `smoke-classic-no-bim-contamination` y build.
- Saneamiento final en `TASK-1515`: `resolveManualMilestoneMovePreview(...)` pasa a ser la unica fuente temporal del preview horizontal. Se elimina `manualMilestoneStartDate`, `translationPx` queda derivado de la fecha efectiva, helper/rutas/cascada/commit leen `manualMilestonePreview` y los gestos verticales limpian el preview horizontal para no interferir.
- Se anade contrato `previewCommitContract` para comparar lo mostrado por preview con lo recalculado al commit; si difiere, se cancela la persistencia.
- La prueba `smoke-gantt-preview-commit-double-blind.mjs` calcula el delta `1d 2h15m` por preview y por commit sobre tareas, hitos, duracion cero y dependencias `FS/SS/FF/SF`.
- Correccion posterior por evidencia visual del usuario: se detecto que el cuerpo del hito manual podia activar `beginDependencyLinkFromDragInteraction(...)` por deriva vertical y mezclar preview de movimiento con preview de enlace/lag. Se corta esa conversion automatica para hitos manuales; las dependencias nacen solo desde conector explicito. Al cambiar de modo, se limpian `dragPreview`, `dragInteraction` o `linkingState` segun corresponda.
- No se usa DOM como evidencia de cierre: la verificacion tecnica se hace por contrato sin DOM, smoke clasico y build, segun instruccion expresa de la sesion.
- No queda cerrada ni al 100% hasta confirmacion expresa del usuario.
