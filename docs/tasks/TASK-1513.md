## Objetivo

Corregir la regresion integral del movimiento horizontal de hitos manuales haciendo que preview y commit usen un unico contrato temporal.

## Contrato esperado

- El hito manual se mueve por fecha/hora real derivada del pixel del timeline.
- El delta de trabajo entre fecha anterior y fecha nueva se calcula con calendario laboral vigente.
- La cascada visual y la cascada persistida desplazan los sucesores del hito por ese mismo delta laboral.
- Las dependencias aguas abajo conservan su coherencia relativa; no se reinterpreta toda la red como una nueva planificacion desde cero durante el drag de un hito manual.
- Si la persistencia real rechaza por inicio de proyecto u otra regla, el hito y la cascada vuelven al snapshot anterior.

## Validacion requerida

- Smoke focal actualizado y OK: `node scripts/smoke-cronogramas-gantt-manual-milestone-drag.mjs`.
- Smoke clasico completo OK: `npm run smoke:gantt-classic`.

- Build frontend OK: `npm run build`.
- Intento DOM ejecutado previamente sobre el validador disponible; agoto tiempo y no se contabiliza como evidencia de cierre visual.

## Implementacion aplicada

- Preview de hito manual: usa `runtimeBuildManualMilestoneCascadeShiftDrafts(...)` con `dayDelta` calculado desde el movimiento y calendario laboral.
- Commit de hito manual: calcula `milestoneMoveDeltaDays` entre fecha anterior/nueva y persiste la cascada con `dragBuildManualMilestoneCascadeShiftDraftsRef`.
- Respaldo de commit: si el delta laboral exacto queda en cero por redondeo/snap, se usa `interaction.lastDeltaDays` ya medido durante el drag.
- Helper: muestra `d mov.` para hitos manuales en movimiento, manteniendo el hito como duracion funcional cero.
