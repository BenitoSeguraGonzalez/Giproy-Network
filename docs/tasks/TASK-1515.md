## Objetivo

Sanear integralmente el calculo de preview al mover elementos en `Proyectos > Cronogramas > Gantt`, eliminando caminos paralelos de verdad temporal para tareas, hitos manuales, duraciones cero, dependencias y commit.

## Regla de contrato

El preview de movimiento debe resolverse en un unico contrato:

```text
pointer -> fecha/hora laboral efectiva -> delta laboral efectivo -> elemento + cascada + helper + rutas -> commit equivalente
```

No deben coexistir como verdades independientes:

- fecha del hito calculada por pixel;
- `dayDelta` clampado por otra via;
- `translationPx` como fuente funcional;
- `previewPatches` con delta distinto;
- helper calculado por cuenta propia;
- rutas SVG leyendo un estado temporal mixto.

## Criterios de aceptacion

- Hito manual, cascada, helper y commit leen el mismo contrato de preview.
- El hito conserva duracion cero (`start_date === end_date`).
- Movimiento horizontal continuo no puede alternar entre fechas y deltas divergentes.
- La cascada preview no reinterpreta toda la red por `FF`; se traslada por delta laboral efectivo.
- El commit usa el mismo delta laboral efectivo del contrato final, no otra formula.
- Smokes sin DOM y build OK.
- `smoke-classic-no-bim-contamination` OK.

## Resultado aplicado pendiente de validacion

- `CronogramaGantt.jsx` incorpora `resolveManualMilestoneMovePreview(...)` como contrato autoritativo del traslado horizontal de hito manual.
- Se elimina la via paralela `manualMilestoneStartDate`: el hito, la cascada, el helper, las rutas y el commit leen `manualMilestonePreview`.
- El preview obtiene fecha/hora efectiva desde el puntero, la ajusta a calendario laboral/proyecto y deriva de ahi el `effectiveLaborDelta`.
- `translationPx` deja de ser verdad funcional independiente y pasa a derivarse de la fecha efectiva calculada.
- Un hito manual con `effectiveLaborDelta` igual a cero apaga el preview completo; ya no puede quedar visible como `Moviendo hito` con `0,00 d mov.` aunque exista desplazamiento visual residual por pixel/snap.
- La cascada de preview y el commit usan `buildManualMilestoneCascadeShiftDrafts(...)` con el mismo `effectiveLaborDelta`, evitando reinterpretar la red por relaciones `FF`.
- El helper muestra fecha-hora y el movimiento real desde `manualMilestonePreview.effectiveLaborDelta`, manteniendo el hito como duracion cero y mostrando horas/minutos cuando no alcanza un dia laboral completo.
- Si el gesto del hito manual es vertical, se limpia cualquier preview horizontal para no interferir con reordenacion/enlace.
- El modo movimiento desactiva la capa interactiva de dependencias incompatible y apaga la guia generica `taskMoveGuide` cuando hay preview de hito manual, eliminando el segundo calculo visible de dias.
- Cada preview guarda `previewCommitContract` con `currentDraft` y `previewPatches`; al soltar se recalcula el commit y se bloquea la persistencia si difiere.
- Se amplia la validacion doble ciego sin DOM: ademas de los `13` deltas temporales, cubre conversion desde puntero/pixel en escalas dia, semana y mes, ancho de columna, scroll virtual, ruido subpixel, tareas, hitos, duracion cero y dependencias `FS/SS/FF/SF`.
- Correccion posterior exigida por evidencia visual del usuario: el cuerpo del hito manual ya no puede convertirse automaticamente en creador de dependencia por deriva vertical. La creacion de dependencias queda limitada al conector explicito.
- El inicio de drag apaga `linkingState`; el inicio de enlace explicito apaga `dragInteraction` y `dragPreview`. No deben coexistir preview de movimiento y preview de enlace/lag.
- El drag normal del hito manual se activa por intencion horizontal; los gestos verticales no alimentan el preview temporal salvo flujos verticales explicitos.
- Correccion posterior por evidencia del usuario: el commit de hito manual ya no usa una copia simple de `manual_milestones`; toma la version efectiva con overlays de `successor_dependencies`, preserva las sucesoras al mover y cancela si un hito con sucesoras no genera cascada dependiente.
- Correccion posterior por evidencia del usuario en movimientos hacia atras: la aritmetica laboral deja de tratar el fin exacto de jornada (`16:00`) como fuera de jornada cuando se desplaza en negativo. Esto evitaba un doble descuento sobre la cascada al mover hitos hacia fechas anteriores.
- Los hitos de duracion cero ya no calculan su `previewEnd` con alineacion laboral positiva; `addGanttWorkDuration(..., 0)` devuelve exactamente la misma fecha/hora, evitando helpers como `03/07/2026 16:00 -> 06/07/2026 08:00` para un hito sin duracion.
- La cascada de hito manual deja de realinear cada sucesor con direccion negativa antes de aplicar el delta laboral; toma la fecha persistida/draft como punto de partida y aplica un unico desplazamiento.
- Extension posterior en `TASK-1517`: el guardado de movimientos queda protegido por una barrera comun de integridad del grafo candidato y por undo/redo de movimientos persistidos, sin crear una segunda formula.
