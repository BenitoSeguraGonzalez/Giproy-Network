# TASK-1536 - Control de reportes de cronogramas clasicos

Estado: En validacion del usuario
Fecha: 2026-05-07
Modo: GIPROY CLASICO

## Objetivo

Controlar la adecuacion de los accesos a reportes de `Proyecto > Cronogramas` despues de los cambios recientes en Gantt, Cronograma Valorado, Inversion y Flujo de Caja.

## Diagnostico

- El backend comun de reporting ya soportaba las variantes `valorado`, `gantt`, `cash_flow`, `integrado` y `pareto` bajo `report_type = cronograma_valorado`.
- La UI clasica habia quedado incongruente porque el reporte `cash_flow` dependia de una pestaña visible `flujo_caja` que ya no existe tras integrarse Caja dentro de `Inversion`.
- El reporte `integrado` quedaba asociado implicitamente a `Curva S`, aunque su intencion real es transversal.

## Alcance autorizado

- Ajustar solo la seleccion visible de variantes de reporte en la cabecera de Cronogramas.
- Mantener el contrato backend y el carril comun `reporting`.
- Mantener MS Project como accion separada del reporte documental.
- No tocar calculos, `cash_flow`, Gantt, Valorado, Presupuesto/APU, persistencia ni BIM.

## Criterios de aceptacion

- El usuario puede abrir reporte de Cronograma Valorado sin depender de la pestaña activa.
- El usuario puede abrir reporte de Flujo de Caja aunque Caja ya no sea una pestaña visible.
- El usuario puede abrir Reporte Integrado de forma explicita.
- En Gantt, el reporte documental queda separado de exportacion MS Project.
- No hay activacion ni contaminacion BIM.

## Cierre

No cerrar sin validacion tecnica y confirmacion del usuario en UI real.
