# TASK-1593 - EDO adecuacion visual base

## Modo
GIPROY CLASICO.

## Objetivo
Adecuar visualmente la seccion EDO usando como base el lenguaje de `Datos de Proyecto` y `Stakeholders`, sin cambiar comportamiento funcional ni sincronizacion EDO/EDT/Stakeholders.

## Alcance
- Header principal claro/soft.
- Workbench operativo claro.
- Toolbar interna oscura compacta.
- Buscador y acciones iconograficas.
- Botones de reporte/acciones alineados al patron soft existente.

## No alcance
- Sin cambios backend.
- Sin cambios de persistencia.
- Sin cambios en EDT salvo validacion de no ruptura.
- Sin BIM, rutas BIM, UX BIM ni acoplamientos nuevos.

## Criterios
- EDO debe ser mas denso que `Datos de Proyecto`.
- Header principal claro, no skin oscuro sin razon.
- Rail oscuro reservado para zona operativa.
- Botones principales con icono y tooltip.
- No duplicar gestion de roles de Stakeholders.

## Validacion prevista
- `npm run build`.
- Smoke no contaminacion BIM.
- Revision focal de que EDO sigue creando/editando nodos y asignando stakeholders.

## Implementacion
- Header principal de EDO alineado con `Datos de Proyecto` y `Stakeholders`: superficie clara/soft, icono azul EDO, titulo tecnico y subtitulo compacto.
- El selector `Grafico / Arbol` permanece en la cabecera clara, a la izquierda del boton de reportes.
- Los controles propios de la vista grafica se proyectan al rail operativo oscuro cuando el modo grafico esta activo.
- Workbench principal convertido a superficie soft clara con rail operativo oscuro.
- Accion de reporte mantiene el boton generico de proyecto.
- Accion `Nuevo hito principal` se traslada al rail operativo como boton iconografico.

## Validacion ejecutada
- `npm run build` OK desde `frontend/`.
- `node scripts/smoke-classic-no-bim-contamination.mjs` OK desde `frontend/`.

## Estado
Implementada y validada.
