# TASK-1602 - Verificacion y alineacion de reportes EDO/EDT

Fecha: 2026-05-08  
Modo: GIPROY CLASICO  
Estado: Implementada y validada

## Objetivo
Revisar la reportería de `EDO` y `EDT`, confirmar que las plantillas y datos suministrados estan alineados, y corregir cualquier rotura detectada.

## Hallazgos
- `EDO` tenia plantilla `001 - EDO.xlsx`, pero no estaba conectado al flujo comun de `preview/export`.
- `EDT` tenia servicio de reporte, pero importaba un modelo inexistente y usaba claves de tabla distintas a las plantillas reales.
- Los botones de reporte de `EDO` y `EDT` usaban el fallback visual del componente generico, sin abrir el visor comun de reportes.

## Implementacion
- Se habilita `report_type: edo` en schemas, preview, export y nombres de descarga.
- Se agrega `generate_edo_report(...)` usando la plantilla `001 - EDO.xlsx`.
- Se corrige `generate_edt_report(...)` para usar `EdtNode` y placeholders reales:
  - `#ITEM`, `#CODIGOEDT`, `#DESCRIPCION_CUENTA_PAQUETE`.
  - `#NOMBRE_RESPONSABLE`, `#CODIGO_STKR`, `#DEFINICION`.
  - `#SUBTOTAL_CUENTA`.
- Se conectan `EDO` y `EDT` al `CommonReportPreviewModal` con exportacion Excel, PDF nativo y PDF desde Excel.
- Se agregan tests focales de generación para `EDO` y variantes `EDT listado/diccionario/valorada`.
- Hotfix posterior: el reporte de `Stakeholders` resuelve el rol con una unica politica para preview y Excel:
  - asignacion consolidada `proyecto_stakeholders`;
  - fallback directo a roles operativos en `EDO` / `EDT`;
  - invalidacion de cache de exportacion con nueva version de render.
