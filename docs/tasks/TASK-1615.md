# TASK-1615 - Implementacion de controles comunes para reportes clasicos

## Modo
GIPROY CLASICO

## Objetivo
Implementar la norma de `TASK-1614` consolidando el boton y los menus de reporte en componentes comunes reutilizados por Gantt, EDO y EDT.

## Implementacion
- `ProjectSectionReportButton` expone la clase activa comun `PROJECT_REPORT_BUTTON_ACTIVE_CLASS`.
- `ProjectSectionReportButton` expone `ProjectReportMenu` para la superficie desplegable de reportes.
- `ProjectSectionReportButton` expone `ProjectReportMenuItem` para cada opcion tipo capsula soft.
- `Cronogramas > Gantt` deja de tener constantes locales para su menu de reporte y consume el patron comun.
- `Cronogramas > Valorado`, `EDO > Reportes` y `EDT > Reportes` usan el mismo patron.
- `docs/STYLE_GUIDE.md` incorpora la regla global para futuros modulos.

## Impacto en GiProy Clasico
Cambio visual frontend clasico. No modifica endpoints, exportes, preview, Excel/PDF, arboles EDO/EDT, Cronogramas ni persistencia.

## No interferencia BIM
Sin rutas BIM, UX BIM, modelos BIM, imports BIM ni dependencias BIM.
