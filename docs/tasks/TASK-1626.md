# TASK-1626 - Subtotales y rendimiento de Presupuesto + APUs

## Objetivo
Corregir la salida clasica `Presupuesto + APUs` para que el formato SERCOP muestre subtotales por seccion de recursos, diferencie visualmente los encabezados de categoria y no bloquee la apertura del preview con generacion pesada en segundo plano.

## Alcance
- Backend comun de reporting clasico.
- Plantillas APU consumidas por:
  - reporte APU individual;
  - lote de APUs;
  - `Presupuesto + APUs`.
- Endpoint comun `/reporting/preview`.
- Smoke focal de alineacion Excel APU.

## Implementacion
- `REPORT_EXPORT_RENDER_VERSION` sube a `2026-05-13-apu-section-summary-v3` para invalidar tambien payloads cacheados durante el primer ajuste de subtotales.
- El motor APU escribe explicitamente los valores de `SUBTOTAL M`, `SUBTOTAL N`, `SUBTOTAL O` y `SUBTOTAL P` en la columna de costo SERCOP, aun cuando la plantilla no exponga placeholders detectables.
- La escritura de subtotales se ejecuta al final del armado de hoja, despues de restaurar blueprints y footer, evitando que se pierda por restauraciones posteriores.
- Los encabezados visibles `EQUIPOS`, `MANO DE OBRA`, `MATERIALES` y `TRANSPORTE` reciben un fondo suave `#EAF3F8`.
- `Presupuesto + APUs` consulta la cache del bundle antes de reconstruir el workbook base cuando ya existe payload cacheado.
- El preview `presupuesto / with_apus` vuelve a precalentar el Excel, pero ahora lo hace en un hilo daemon desacoplado y deduplicado, evitando que el informador quede atado al bundle frio.
- Para `Presupuesto + APUs` el precalentamiento prepara solo `xlsx`; la conversion PDF desde Excel queda bajo demanda para no cargar innecesariamente el request de preview.
- El smoke APU valida ahora valores de subtotales SERCOP y color de encabezados en bundle y standalone.
