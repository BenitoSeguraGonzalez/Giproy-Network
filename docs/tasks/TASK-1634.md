# TASK-1634 - Corregir base economica del reporte de indirectos

Fecha: 2026-05-13

Modo: GIPROY CLASICO

## Objetivo

Corregir la divergencia entre el tablero de Presupuesto y el reporte clasico `Indirectos`, donde el reporte estaba tomando el operativo sin IVA como si fuera el total directo sin indirectos y terminaba aplicando indirectos por segunda vez.

## Alcance autorizado

- Backend comun de reporting clasico.
- Pruebas focales de reporting.
- Documentacion TASK, CHANGELOG, project_state y runtime.

## Implementacion

- `ReportingService` agrega `_resolve_presupuesto_indirectos_totals(...)` para derivar la base directa desde el operativo sin IVA:
  - `base_directa = operativo_sin_iva / (1 + porcentaje_indirectos / 100)`.
- El preview de `Indirectos`, las filas del listado y el Excel usan esa base directa comun.
- Los costos por cuenta de indirectos se calculan sobre la base directa sin redondear y se redondean solo al presentar, evitando descuadres de centavos.
- `REPORT_EXPORT_RENDER_VERSION` sube a `2026-05-13-budget-indirects-report-v5-edo-edt-document-columns-v5`, conservando el sufijo esperado por QA documental EDO/EDT.
