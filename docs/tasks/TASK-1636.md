# TASK-1636 - Control vivo de adecuacion fina grafica de Presupuesto clasico

## Modo

GIPROY CLASICO.

## Estado

Abierta / en curso.

Esta TASK no debe cerrarse hasta que el usuario confirme que la ronda de adecuacion fina grafica de `Proyecto > Presupuesto` queda satisfecha. Funciona como punto central de control para ajustes incrementales pequenos sobre la capa visual clasica.

## Objetivo

Centralizar los ajustes finos de UI/UX visual de Presupuesto clasico derivados del refresh de `TASK-1635`, manteniendo intacta la operativa funcional.

## Reglas de control

- Trabajar solo sobre GiProy Clasico.
- No depender de BIM.
- No mostrar ni activar UX BIM.
- No crear acoplamientos hacia BIM.
- No tocar backend, PostgreSQL, calculos, persistencia, API ni contratos de datos salvo nueva autorizacion explicita.
- Cada ajuste debe conservar coherencia con Datos de Proyecto, Stakeholders, EDO, EDT, Cronogramas/Gantt y STYLE_GUIDE.
- Cada lote implementado debe documentarse aqui antes de cierre de turno.

## Ajustes pendientes centralizados

### Tanteo - header y trazabilidad

- Igualar el alto visual del header de `Tanteo` con el header/listado de Presupuesto.
- Mantener formato de header incluso cuando no haya linea seleccionada; debe mostrar solo `Sin seleccion`.
- Reorganizar el header de `Tanteo` en dos lineas:
  - Linea superior: descripcion del item con codigo EDT y codigo de item visible.
  - Linea inferior: cards informativas y boton iconografico de aplicar cambios.
- Evitar truncado agresivo de la descripcion.
- Las cards informativas deben seguir el patron de Gantt: capsulas oscuras compactas con dot/label/valor, algo mayores si el valor monetario lo requiere.
- Recuperar el boton de aplicar cambios como boton iconografico visible, alineado al patron de controles de Gantt.
- Evitar cards dentro de cards y contenedores anidados que aumenten el peso visual.

### Lineas de Presupuesto - codigo de item

- Mostrar el codigo de item en la descripcion de cada linea de presupuesto.
- No crear columna nueva.
- Mantener consistencia con el listado de APUs, donde el codigo ya aparece junto a la descripcion.

### Tanteo - codigo de item

- Mostrar el codigo de item tambien en la descripcion/header de Tanteo.
- Mantener trazabilidad visual entre Presupuesto, APU y Tanteo.

### Header grid Presupuesto - estados de modo

- Ajustar los botones `Seleccionar` y `Tanteo` del header del grid para que el estado activo se aprecie facilmente.
- Mantener la estetica del rail oscuro y el patron de botones iconograficos tipo Gantt.
- Evitar un resaltado demasiado pesado que rompa la coherencia visual del sistema.
- Conservar intacta la operativa actual de seleccion y apertura de tanteo.

### Headers Presupuesto - homologacion de altura y skin negro

- Homologar el tamano visual de los tres headers visibles en Presupuesto, tomando como referencia principal el header del listado/grid de presupuesto.
- Ajustar el encabezado izquierdo para que adopte skin negro, tamano equivalente y lectura alineada con el header central y el header de `Tanteo`.
- Mantener botones iconograficos segun la premisa del sistema: icono claro, tooltip si aplica, sin texto innecesario cuando el icono sea reconocible.
- Mejorar el movimiento/feedback de pulsacion en botones de skin negro para que el click se perciba con claridad sin romper la estetica.
- Elevar esta regla de feedback a todos los botones de header con skin negro en la aplicacion clasica, como criterio visual transversal.
- No alterar comportamiento, handlers, permisos, persistencia ni logica operativa de los botones existentes.

### Header lateral Presupuesto - retirada de Ocul

- Retirar el boton `Ocul` del header lateral porque el area de trabajo optimizada ya no requiere ese control visible.
- Ajustar y redistribuir el resto de botones del header lateral para ocupar el espacio de forma equilibrada.
- Mantener accesibilidad y no dejar huecos visuales ni perdida de jerarquia.
- No alterar el comportamiento funcional del catalogo salvo la retirada visual del boton.

### Header lateral Presupuesto - busqueda integrada de Catalogo APU

- Mantener intacto el alto total homologado del header lateral.
- Reordenar el contenido interno en tres filas: label `Catalogo APU`, botonera actual y buscador.
- Retirar el buscador de la franja inferior del listado del catalogo y moverlo al header lateral.
- El buscador debe usar el skin definido en el listado de Presupuesto.
- Recuperar el label discreto de cantidad de APUs bajo la busqueda, mostrando totales y visibles cuando haya filtro.
- Ensanchar visualmente el header para alinearlo con el cuerpo/listado inferior del catalogo.
- Ajustar la terminacion inferior del listado para que no llegue al ras y cierre visualmente alineado con el listado de Presupuesto.
- El listado inferior debe ganar el espacio liberado por el buscador anterior, sin romper scroll ni filtrado.
- No alterar carga de APUs, filtrado, insercion, handlers ni persistencia.
