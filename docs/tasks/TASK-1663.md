# TASK-1663 - Recuperacion de entorno y launcher tras reinstalacion Windows

## Modo
GIPROY CLASICO.

## Objetivo
Levantar el sistema despues de una reinstalacion del sistema operativo, recuperando toolchain local, servicios Windows y consistencia del lanzador sin tocar la capa BIM.

## Correccion posterior
El contrato operativo documentado en esta TASK fue corregido por `TASK-1692`: el frontend clasico no debe quedar en `3010`; debe volver a `http://localhost:5173` porque el tunel Cloudflare `https://giproy-network.excompc.dpdns.org` apunta a ese puerto local. Esta TASK queda como antecedente historico de recuperacion Windows, no como fuente vigente de puertos.

## Alcance autorizado
- Launcher Windows: `tools/launcher/launcher_app/ops.py`.
- Configuracion Vite clasica: `frontend/vite.config.js`.
- Arranque manual de respaldo: `iniciar_sistema.bat`.
- Lanzadores raiz: `Launcher.bat` y `giproy_service_start.bat`.
- Entorno local Windows: instalacion de Node.js LTS y registro Git `safe.directory`.

## Implementacion
- Se instalo Node.js LTS mediante `winget` desde la fuente `winget`.
- Se marco el repo como `safe.directory` para Git tras el cambio de SID de usuario provocado por la reinstalacion.
- Se mantuvo el contrato operativo del GiProy Control Center: backend en `3001` y frontend en `3010`.
- `frontend/vite.config.js` conserva el proxy local `/api` hacia `http://localhost:3001`.
- `iniciar_sistema.bat` queda alineado con el launcher: backend `3001`, frontend `3010`, deteccion de `npm.cmd` en `C:\Program Files\nodejs` y PATH temporal hacia Node.
- `Launcher.bat` fue revisado y ya apunta al Control Center `tools\launcher\main.py` usando el venv del proyecto.
- `giproy_service_start.bat` queda saneado como respaldo legacy: backend `3001`, frontend `3010`, Node por PATH temporal y frontend en `preview` como el servicio del Control Center.
- El launcher agrega deteccion robusta de Node.js en `C:\Program Files\nodejs` y propaga esa ruta al entorno de comandos para evitar que `npm.cmd` falle buscando `node`.
- El servicio frontend del launcher se ejecuta via `cmd.exe` con PATH temporal hacia Node antes de invocar `npm run preview`.
- Los checks de plataforma del launcher dejan de depender del script legacy MySQL y validan PostgreSQL mediante la conexion real del backend (`app.core.database`).
- Se lanzo la accion elevada `start_services` del launcher, que reinstalo e inicio `GiProy-Backend` y `GiProy-Frontend`.

## Impacto GiProy Clasico
- El sistema queda levantado localmente desde servicios Windows:
  - Backend: `http://127.0.0.1:3001`.
  - Frontend: `http://127.0.0.1:3010`.
- Mejora la resiliencia del Control Center despues de reinstalar Windows o perder PATH.
- No modifica reglas de negocio, API funcional, modelos, persistencia ni UI de modulos clasicos.
