# TASK-1675 - Materializador Proyecto desde analisis tecnico

## Modo
GIPROY CLASICO.

## Estado
Planificada. Sin implementacion funcional en esta TASK.

## Objetivo
Convertir un analisis tecnico confirmado en un proyecto inicial real, con base de datos de proyecto, recursos, APUs, presupuesto, EDT de control, EDT de presupuesto, Gantt y Valorado en estado inicial.

## Alcance
- Crear proyecto dentro de `Administradores Generales` desde el bundle analizado.
- Crear base de trabajo/base de proyecto asociada.
- Crear recursos; si no hay categoria especifica, usar categoria general del tipo principal.
- Generar APUs principales y APUs anidadas/recursivas.
- Crear presupuesto con capitulos/rubros derivados.
- Crear EDT de control y EDT de presupuesto con estructura inicial coherente.
- Inicializar Gantt y Cronograma Valorado en estado inicial compatible con el resto de Proyectos.
- No crear datos en Stakeholders ni EDO.

## Fuera de alcance
- Publicar o vender el proyecto.
- Crear stakeholders artificiales.
- Inventar EDO si el PDF no lo trae.
- Crear acoplamientos BIM.

## Reglas de transaccion
- Debe existir modo `dry-run`/preview antes del commit.
- El commit debe ser atomico: o crea todo el proyecto coherente o no persiste nada.
- Usar idempotency key por archivo/perfil/import session para evitar duplicados accidentales.
- Registrar trazabilidad tecnica del origen en metadata clasica del proyecto.

## Validacion
- Tests de materializacion con un PDF actual.
- Integridad recursos/APUs/presupuesto/EDT/Gantt/Valorado.
- Verificacion explicita de ausencia de Stakeholders y EDO creados.
- Smoke no contaminacion BIM.
