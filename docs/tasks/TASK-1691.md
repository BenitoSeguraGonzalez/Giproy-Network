# TASK-1691 - Saneamiento de acciones del portafolio de Proyectos

## Estado

Completada el 2026-05-19.

## Objetivo

Corregir el flujo clasico del listado de Proyectos para que las acciones operativas principales funcionen desde el portafolio y para evitar el fallo de carga dinamica al entrar a `Datos del proyecto`.

## Alcance implementado

- `DatosProyecto` deja de cargarse como chunk lazy interno de `Proyectos`, evitando el error de produccion `Failed to fetch dynamically imported module ... DatosProyecto-*.js` al abrir un proyecto.
- El encabezado del listado de proyectos agrega columna real `Acciones` y la tabla usa ancho completo con minimo operativo, corrigiendo la banda que no llegaba al final del contenedor.
- El listado de proyectos muestra la accion `Exportar a Marketplace` para administradores y superadministradores, reutilizando el flujo backend existente `POST /api/v1/proyectos/marketplace-export`.
- La accion de borrado del listado queda reforzada como boton explicito con `type="button"`, `aria-label` y corte de propagacion desde `pointerdown`, evitando que el click se mezcle con la apertura de revisiones.
- La tabla del portafolio define una malla explicita de ocho columnas (`colgroup`) para que cabeceras y contenido vivan en el mismo eje visual en escritorios 1920x1080 o superiores.
- Las acciones `Exportar a Marketplace` y `Eliminar proyecto` se separan de `Fecha fin`, pasan a una columna propia `Acciones` y comparten una medida unica de boton.
- El borrado usa primero `projectToDelete.empresa_id` antes del contexto visual de empresa, evitando fallos cuando un superadministrador opera sobre un proyecto de otra empresa activa/auditada.
- Se agrega prueba de endpoint para `DELETE /api/v1/proyectos/{id}` que valida el borrado completo de proyecto raiz, revision, presupuestos, cronogramas, entradas de calendario y bases de proyecto.
