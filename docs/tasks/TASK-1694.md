# TASK-1694 - Restauracion de puertos de origen GiProy y Cloudflared

Fecha: 2026-05-19

Modo: GIPROY CLASICO

## Objetivo

Restaurar el contrato operativo original de convivencia: GiProy clasico vuelve a `localhost:3010` y `giproy-network.excompc.dpdns.org` vuelve al tunel `eXcom-SaaS`, evitando ocupar `5173`.

## Causa

El movimiento temporal de GiProy a `5173` hizo que `nuria-core.excompc.dpdns.org`, que en Cloudflare estaba publicado hacia `localhost:5173`, mostrara la pantalla de GiProy. El puerto `5173` debe quedar libre para el carril NurIA/Core y GiProy debe volver a `3010`.

## Cambios

- `frontend/vite.config.js` vuelve a `server.port = 3010`.
- `tools/launcher/launcher_app/config.py` vuelve a `frontend_ports=(3010, 8080)`.
- `iniciar_sistema.bat`, `iniciar_sistema_fixed.bat` y `giproy_service_start.bat` vuelven a `FRONTEND_PORT=3010`.
- `tools/launcher/scripts/repair_and_verify_services.ps1` vuelve a limpiar/verificar `3001/3010`.
- `tools/launcher/README.md` vuelve a documentar `3001 / 3010 / 8080`.
- `CloudFlared-bkp/restore_from_backup.ps1` deja de recrear el servicio auxiliar `cloudflared-GiProyNetwork`.
- Se elimina la configuracion local `giproy-network-classic.yml` porque `giproy-network` vuelve a gobernarse por el tunel `eXcom-SaaS`.
- El DNS de `giproy-network.excompc.dpdns.org` se enruta de nuevo al tunel `eXcom-SaaS`.
- El servicio Windows `cloudflared-GiProyNetwork` se detiene y elimina.
- El servicio Windows `GiProy-Frontend` queda corriendo con `--port 3010 --strictPort`.

## Validacion

- `GiProy-Frontend`: `RUNNING`.
- `http://127.0.0.1:3010`: HTTP 200.
- `http://127.0.0.1:5173`: sin listener de GiProy.
- `https://giproy-network.excompc.dpdns.org/login`: HTTP 200.
- `https://nuria-core.excompc.dpdns.org/login`: deja de servir GiProy; responde 502 mientras no haya servicio local escuchando en `5173`.
- `cloudflared-GiProyNetwork`: eliminado.
- `cloudflared tunnel list`: solo quedan `eXcom-SaaS` y `giproy-erp-beta`.
- `default_config().frontend_ports`: `(3010, 8080)`.
- `npm run build`: OK.
- `smoke-classic-no-bim-contamination`: OK.

## No interferencia BIM

No se tocaron rutas, componentes, modelos, hooks ni feature flags BIM. El ajuste es infraestructura local/Cloudflared del carril clasico.
