# TASK-1697 - Exportador Marketplace clasico con clasificacion Proyecto / Compra publica

## Modo

- MODO 1: GIPROY CLASICO
- Capa autorizada: Proyectos clasico, Marketplace clasico y checkout marketplace.
- Restriccion BIM: no se agregan rutas, UX, dependencias ni acoplamientos BIM.

## Objetivo

Ajustar el exportador de proyectos hacia Marketplace para que:

- Empresas normales exporten siempre como `proyecto`.
- Solo un `superadministrador` de `Administradores Generales` pueda elegir entre `proyecto` y `portal_compras_publicas`.
- El modal se rellene con datos del proyecto, permita editar campos comerciales y confirme antes de crear/actualizar el producto.
- El producto quede en revision (`pending`, inactivo, requiere aprobacion).
- Una compra publica exportada desde proyecto pueda comprarse y agregarse como proyecto a la empresa compradora.

## Cambios

- Backend:
  - Se agrega preview `POST /proyectos/marketplace-export/preview`.
  - `POST /proyectos/marketplace-export` acepta tipo de producto y metadatos editados.
  - El exportador fuerza `proyecto` salvo superadmin + Administradores Generales.
  - `portal_compras_publicas` conserva la tabla de precios automatica de compras publicas.
  - `proyecto` usa precio manual editable y arranca por defecto en `19.99 USD`.
  - Para `portal_compras_publicas`, se genera `portal_meta` con politica de entrega por proyecto y trazabilidad de origen.
  - El checkout del portal clona el proyecto origen cuando la politica `clone_source_project_on_purchase` esta activa.
- Frontend:
  - El boton `Exportar a Marketplace` abre modal editable.
  - Se monta el modal tambien en la rama activa del portfolio clasico (`PROJECTS_HTML_REFERENCE_LANDING`), evitando que el click actualice estado sin superficie visible.
  - La accion de exportar usa un boton nativo directo para eliminar interferencias de tooltip o seleccion de fila.
  - El modal se abre inmediatamente con datos base del proyecto y luego se hidrata con el preview backend para evitar clicks sin respuesta visible.
  - El modal muestra total tecnico, precio, estado pendiente y selector `Vender proyecto` / `Compra publica` solo cuando el usuario puede elegir.
  - En `Vender proyecto` el precio queda editable; en `Compra publica` no se edita manualmente porque depende de la tabla.
  - El modal se alinea al lenguaje visual de Proyectos: `AppModalBody/Footer`, campos soft, `Textarea` del sistema y `AnimatedDateInput` en vez de fechas nativas.
  - Se compacta el modal al patron tecnico Proyectos/Gantt: header oscuro, selector `ProjectSegmentedSwitch` en cabecera, metricas tipo semaforo/chip y footer con acciones solo icono.
  - Las etiquetas de campos incorporan `AppHint` oscuro con retardo de hover y cierre al mover el puntero, siguiendo el comportamiento de hints del Gantt.
  - Precio, inicio y fin de publicacion quedan en una misma fila; el precio usa acento naranja de presupuesto y las fechas conservan `AnimatedDateInput` compacto.
  - El `ProjectSegmentedSwitch` se ajusta para no partir etiquetas en dos lineas y el modal mantiene cuerpo de altura estable al alternar tipo de producto.
  - Las acciones finales reutilizan `ProjectSectionIconButton` con `AppHint`, eliminando bordes nativos/negros en hover/foco y unificando comportamiento con el resto de Proyectos.
  - Los valores tecnicos vacios tipo `None`/`null` se normalizan antes de mostrarse en campos editables.
  - Se separan los estados de carga de preview y envio para que el boton final `Enviar a revision` no quede bloqueado por la consulta previa.
  - El boton final pasa a mostrarse como accion textual visible.
  - Los campos de publicacion y compra publica quedan editables antes de enviar a revision.
