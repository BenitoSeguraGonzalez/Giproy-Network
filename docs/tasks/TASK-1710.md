## Objetivo

Convertir el analisis de `print()`, `console.*`, `logger.*` y posibles terminos sensibles en un snapshot reproducible para no reanalizar todo el repo manualmente en futuras sesiones.

## Alcance autorizado

- `tools/ai_tools/logging_inventory.py`
- `docs/logging_inventory.json`
- `docs/tasks/TASK-1710.md`
- `docs/CHANGELOG.md`
- `docs/runtime/WORK_MODE_STATE.json`

## Cambios realizados

- Se agrega un script read-only de inventario de logging.
- El snapshot clasifica coincidencias por zona: backend productivo, frontend productivo, scripts/tools y otros fuentes.
- Se cuentan tipos de salida: `print`, `logger`, `console` y salidas PowerShell.
- Se detectan terminos sensibles de forma heuristica: password, token, Authorization, session/device y email.
- El resultado queda limitado por muestras para evitar ruido excesivo.

## Cambios no realizados

- No se modifica codigo backend productivo.
- No se modifica frontend.
- No se reemplaza ninguna consola ni `print()` automaticamente.
- No se toca DB, auth, tenant, licencias, sesiones, permisos, presupuestos, EDT, cronogramas ni BIM.

## Impacto sobre GiProy Clasico

Impacto runtime nulo. La herramienta solo analiza archivos locales y escribe `docs/logging_inventory.json`.

## No interferencia BIM

Sin cambios en codigo BIM, UX BIM, feature flags BIM ni dependencias nuevas hacia BIM.
