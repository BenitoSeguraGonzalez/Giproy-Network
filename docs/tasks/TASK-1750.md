## Objetivo

Ajustar `.gitignore` para proteger archivos runtime, copias locales, dumps, uploads y artefactos generados sin eliminar trabajo existente ni ocultar codigo fuente necesario.

## Alcance autorizado

- Archivo `.gitignore`.
- Documentacion de trazabilidad en `docs/CHANGELOG.md` y esta TASK.
- Sin `git rm`, sin borrado de archivos, sin cambios de codigo productivo.

## Cambios realizados

- Se agregan patrones para `.pytest_cache/`, `*.db`, `*.jsonl`, `backups/`, compresiones y archivos de respaldo (`*.gz`, `*.tar`, `*.tar.gz`, `*.tgz`, `*.zip`, `*.7z`).
- Se mantiene ignorado `uploads/` y `backend/uploads/` para proteger datos runtime locales restaurados.
- Se mantiene ignorada la copia local `GiProy Network/`.
- Se protegen artefactos runtime de `tools/launcher/.opencode` sin ignorar el codigo fuente oficial de `tools/launcher`.
- Se cambia `docs/runtime/` por una regla selectiva que permite versionar `docs/runtime/WORK_MODE_STATE.json`.

## No perdida de trabajo ni datos

- No se borro ningun archivo.
- No se ejecuto `git rm`.
- Los archivos ya trackeados permanecen trackeados; `.gitignore` solo evita nuevas entradas accidentales.
- Los uploads restaurados permanecen en disco y quedan fuera de Git.

## No interferencia BIM

- No se modifica codigo BIM.
- No se activa UX BIM.
- No se agregan imports ni dependencias BIM.
- El cambio es de higiene Git transversal y no altera comportamiento runtime.

## Validacion

- `git status --short --ignored`.
- `git check-ignore -v` sobre uploads, backups, traces, launcher runtime y `WORK_MODE_STATE.json`.
- Baseline enterprise con frontend incluido.

## Rollback

Revertir esta TASK, la entrada de `CHANGELOG` y las lineas agregadas/modificadas en `.gitignore`.
