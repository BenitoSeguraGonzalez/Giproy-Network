# TASK-1790 - Smoke focal de fronteras API clasicas

Fecha: 2026-05-25

Modo: GIPROY CLASICO

## Objetivo

Proteger los flujos clasicos recientemente encapsulados para evitar que `AuthContext` o `Settings` vuelvan a depender de `axiosConfig` directamente.

## Alcance

- `frontend/scripts/smoke-classic-api-boundaries.mjs`
- `frontend/package.json`
- `tools/ai_tools/validate_enterprise_baseline.py`
- Documentacion de progreso y contexto IA.

## Cambios realizados

- Se crea smoke estatico `smoke-classic-api-boundaries.mjs`.
- Se agrega script npm `smoke:classic-api-boundaries`.
- El baseline enterprise ejecuta el smoke cuando se usa `--include-frontend`.
- El smoke valida que:
  - `AuthContext` no importe `axiosConfig` directamente.
  - `AuthContext` consuma `authApi` y `adminLicensesApi`.
  - `authApi` exponga refresh, usuario actual, login y logout.
  - `Settings` no importe `axiosConfig` directamente.
  - `Settings` conserve clientes API para empresas, usuarios y proyectos.

## No cambios

- No se modifico logica productiva.
- No se modificaron rutas, UI, backend, DB, auth runtime, tenant ni BIM.

## Validacion

- `npm run smoke:classic-api-boundaries`: OK.
- `npm run build`: OK.
- `tools/ai_tools/validate_enterprise_baseline.py --include-frontend`: OK.
- Smoke anti-BIM incluido en baseline: OK.

## Resultado

El baseline detecta regresiones especificas en las fronteras API clasicas de `AuthContext` y `Settings`.
