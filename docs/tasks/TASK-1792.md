## Objetivo

Proteger la frontera API clasica de `ProjectManager` despues de la migracion a clientes de dominio, sin cambiar comportamiento productivo.

- `frontend/scripts/smoke-classic-project-manager-api-boundary.mjs`

## Cambios realizados

- Se crea smoke estatico `smoke-classic-project-manager-api-boundary.mjs`.
- Se agrega script npm `smoke:classic-project-manager`.
- El baseline enterprise ejecuta el smoke cuando se usa `--include-frontend`.
- El smoke valida que:
  - `ProjectManager` no importe `axiosConfig` directamente.
  - `ProjectManager` conserve `proyectosApi`, `basesTrabajoApi`, `edtApi` y `usuariosApi`.
  - Asignaciones de proyectos y bases sigan usando clientes API.
  - `proyectosApi`, `basesTrabajoApi`, `usuariosApi` y `edtApi` conserven helpers tenant usados por ProjectManager.

## No cambios

- No se modifico logica productiva.
- No se modificaron rutas, UI, backend, DB, auth, tenant runtime ni BIM.
