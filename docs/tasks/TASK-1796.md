## Objetivo

Proteger la frontera API clasica de Presupuestos, incluyendo carga de presupuesto/proyecto, lineas, notas, indirectos, tanteo, catalogo APU, EDT y reporting, sin modificar comportamiento productivo ni calculos.

## Cambios realizados

- Se crea smoke estatico `smoke-classic-presupuesto-api-boundary.mjs`.
- Se agrega script npm `smoke:classic-presupuesto`.
- El baseline enterprise ejecuta el smoke cuando se usa `--include-frontend`.
- El smoke valida que:
  - `PresupuestoDetail`, `PresupuestoContext`, `TanteoTab`, `CatalogoApuTab` y `LineasPresupuestoTab` no importen `axiosConfig` directamente.
  - Se conserven `presupuestosApi`, `proyectosApi`, `reportingApi`, `apusApi` y `edtApi`.
  - La empresa activa siga derivando de `selectedEmpresa` o `user.empresa_id`.
  - Carga, lineas, notas, indirectos, tanteo, catalogo APU, EDT y reporting mantengan sus clientes y tenant params.
  - `presupuestosApi` conserve endpoints criticos y `refresh_prices`.
  - `reportingApi` conserve preview/export con `empresa_id` y blob.

## No cambios

- No se modificaron componentes de Presupuestos.
- No se modificaron clientes API productivos.
- No se modificaron calculos, rutas, UI, backend, DB, auth, tenant runtime ni BIM.
