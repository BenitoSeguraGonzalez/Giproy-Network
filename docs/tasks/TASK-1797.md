# TASK-1797 - Smoke focal de Cronogramas clasico

Fecha: 2026-05-25

Modo: GIPROY CLASICO

## Objetivo

Proteger la frontera API clasica de Cronogramas y Gantt, incluyendo Valorado, Trabajo, calendario, reportes, export/import MS Project y tenant activo, sin modificar comportamiento productivo.

## Alcance

- `frontend/scripts/smoke-classic-cronogramas-api-boundary.mjs`
- `frontend/package.json`
- `tools/ai_tools/validate_enterprise_baseline.py`
- Documentacion de progreso y contexto IA.

## Cambios realizados

- Se crea smoke estatico `smoke-classic-cronogramas-api-boundary.mjs`.
- Se agrega script npm `smoke:classic-cronogramas`.
- El baseline enterprise ejecuta el smoke cuando se usa `--include-frontend`.
- El smoke valida que:
  - `Cronogramas` y `CronogramaGantt` no importen `axiosConfig` directamente.
  - `Cronogramas` conserve `cronogramasApi`, `presupuestosApi`, `proyectoDetalleApi`, `edtApi` y `reportingApi`.
  - `CronogramaGantt` conserve `apusApi`, `basesTrabajoApi` y `presupuestosApi`.
  - La empresa activa siga derivando de proyecto, empresa seleccionada o usuario.
  - Valorado, Trabajo, commit delta, calendario, reset integral, reportes y MS Project mantengan sus clientes y tenant params.
  - Export MS Project conserve formato, `open_after_export` y descarga blob.
  - Import MS Project conserve multipart.

## No cambios

- No se modificaron `Cronogramas.jsx` ni `CronogramaGantt.jsx`.
- No se modificaron clientes API productivos.
- No se modificaron calculos, scheduling, rutas, UI, backend, DB, auth, tenant runtime ni BIM.

## Validacion

- `npm run smoke:classic-cronogramas`: OK.
- `npm run build`: OK.
- `tools/ai_tools/validate_enterprise_baseline.py --include-frontend`: OK.
- Smoke anti-BIM incluido en baseline: OK.
