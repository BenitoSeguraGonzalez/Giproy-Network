# TASK-1820 - Guardas multi-tenant superadministrador

Fecha: 2026-05-26

Modo: GIPROY CLASICO

## Objetivo

Cerrar la debilidad de contexto activo cuando un usuario superadministrador cambia de empresa, evitando arrastre de base, proyecto o datos operativos entre tenants.

## Alcance

- Estado frontend clasico de empresa operativa.
- Estado persistido de base de trabajo y proyecto activo.
- Orquestacion existente de desactivacion de bases por empresa.
- Smoke estatico de guardas de tenant.

## Criterio de aceptacion

- Cambiar de empresa limpia base de trabajo y proyecto activos.
- Cambiar de empresa desactiva bases en empresa saliente y entrante cuando corresponde.
- La limpieza se refleja en memoria y `localStorage`.
- La guarda de limpieza permanece cubierta por smoke.
- Sin cambios de auth, JWT, permisos ni backend multi-tenant.

## Resultado

Implementado como guarda automatizada de control sobre el flujo existente.

## No interferencia BIM

Sin cambios BIM, sin UX BIM y sin acoplamientos hacia BIM.
