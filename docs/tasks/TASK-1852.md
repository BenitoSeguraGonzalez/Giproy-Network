# TASK-1852 - Aplicacion persistente solo en Recursos con rollback

Fecha: 2026-05-26  
Modo: GIPROY CLASICO

## Objetivo

Cerrar el ciclo operativo de `Recursos` permitiendo aplicar una propuesta aprobada solo dentro del estado colaborativo de Recursos, con snapshot de rollback y sin modificar el cronograma Gantt.

## Alcance implementado

- La intencion `ready_to_apply` puede aplicarse como `adjustments.leveling_application_result`.
- La aplicacion queda en `status: applied_to_resources`.
- La propuesta y la intencion se marcan como `applied: true` solo para la capa Recursos.
- Se guarda `applied_scope: resources_state_only`.
- Se guarda `rollback_snapshot` para restaurar propuesta e intencion previas.
- Se permite revertir la aplicacion en Recursos.
- Se refuerza el smoke clasico para proteger el contrato.

## Politica aplicada

- La aplicacion no modifica Gantt, fechas, barras, duraciones ni predecesoras.
- No recalcula Valorado ni Flujo.
- No crea backend, tabla, endpoint ni migracion nueva.
- No cambia contratos API, auth, tenant ni permisos.
- Sin tocar `CronogramaGantt.jsx`.
- Sin BIM, UX BIM, Docker, Coolify, CI/CD, staging ni produccion.

## Validacion esperada

- Smoke clasico de frontera Cronogramas.
- Build frontend.
- Smoke anti-BIM.
- JSON documental.
- Hash de `CronogramaGantt.jsx` igual al backup.
- Baseline enterprise con frontend.
