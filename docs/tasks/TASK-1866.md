# TASK-1866: CTA flotante de dependencia seleccionada no destructivo

## Modo
GIPROY CLASICO

## Tipo
UX FIX + GUARDA DE CONTROL

## Alcance

- `frontend/src/components/projects/CronogramaGantt.jsx`
- `frontend/scripts/smoke-cronogramas-gantt-dependencies.mjs`
- `docs/CHANGELOG.md`
- `docs/HANDOFF.md`
- `docs/tasks/TASK-1866.md`

## Objetivo

Evitar que la accion flotante visible al seleccionar una linea de dependencia
parezca una eliminacion directa. El icono `X` resultaba ambiguo porque se leia
como borrar/romper la linea, aunque el flujo deseado es abrir o mantener visible
el editor de dependencia.

## Implementacion

- Reemplazar el boton flotante `X` por `Pencil`.
- Cambiar la semantica interna de `remove-*` a `edit-*`.
- Cambiar `title` y `aria-label` a `Editar dependencia seleccionada`.
- Mantener la eliminacion exclusivamente dentro del panel compacto como accion
  destructiva explicita.

## Validacion esperada

- Smoke focal de dependencias verifica que el CTA flotante usa semantica de
  edicion y no conserva semantica interna de borrado directo.

## No interferencia

- Sin cambios backend.
- Sin cambios API, auth, tenant, EDT, presupuestos, calendario, cronogramas de
  datos ni DB.
- Sin BIM, UX BIM ni dependencia nueva hacia BIM.
- Sin Docker/Coolify/CI/CD.

## Rollback

- Restaurar el boton flotante anterior en `CronogramaGantt.jsx`.
- Revertir las aserciones focales agregadas al smoke.
