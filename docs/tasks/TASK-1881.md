# TASK-1881: guardas server-side de reporting y marca de agua

## Modo
GIPROY CLASICO

## Tipo
EJECUCION BACKEND + SMOKES CERRADA

## Objetivo

Aplicar las restricciones comerciales de reportes PDF/Excel y marca de agua en
backend, no solo en frontend.

## Dependencias

- `TASK-1880` implementada.

## Alcance

- [x] Bloquear Excel en licencias que no lo permitan desde backend.
- [x] Aplicar marca de agua en PDF segun licencia.
- [x] Mantener reporting clasico compatible.

## Implementacion realizada

### Slice 1 - Guardas Excel server-side

- `backend/app/api/endpoints/reporting.py` consulta `commercial_capabilities_service`
  antes de construir exportaciones modernas de reporting.
- Los formatos `xlsx` y `pdf_excel` quedan bloqueados con `403` si la capacidad
  efectiva `excel_exports` es falsa.
- El endpoint `/reporting/export` conserva el `403` original y no lo convierte en
  error generico `400`.
- Se mantiene la guarda comercial previa para no relajar PDF no comercial antes
  de implementar marca de agua server-side.

### Slice 2 - Marca de agua PDF server-side

- `backend/app/api/endpoints/reporting.py` deriva el texto de marca desde
  `commercial_capabilities_service` cuando `requires_watermark=true`.
- Los PDF modernos de `/reporting/export` se generan con marca de agua visible
  `GIPROY - USO NO COMERCIAL` o `GIPROY - VERSION CON MARCA DE AGUA`.
- La marca se aplica en:
  - PDF de preview/reporting comun.
  - PDF documental EDO/EDT.
  - PDF ejecutivo de Uso de Recursos.
  - Conversion `pdf_excel` desde Excel.
- El cache de exportacion moderna incluye el marcador de marca de agua para no
  servir PDFs antiguos tras cambios de licencia.
- `pdf` puede salir con marca de agua cuando Excel no esta permitido; `xlsx` y
  `pdf_excel` siguen bloqueados si `excel_exports=false`.
