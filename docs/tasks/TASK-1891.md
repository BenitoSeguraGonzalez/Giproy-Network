## Objetivo

Certificar en aplicacion completa que el plan de nuevas politicas de negocio
queda operativo de punta a punta: compra/venta Marketplace, entrega SaaS,
visibilidad de productos por empresa, cupos Conecta, permisos de
superadministrador y uso funcional de una empresa mockup.

  - licencia base vendible;

  - producto Conecta;

## Implementacion realizada

- Se agrega `backend/app/tests/test_marketplace_saas_policy_e2e.py`.
- La certificacion usa `TestClient` contra rutas reales bajo `/api/v1` y no llama
  directamente a servicios de checkout/entrega para validar el flujo principal.
- Se crea una empresa mockup transaccional:
  - `Empresa Mockup Politica SaaS E2E`.
  - Usuario administrador comprador.
  - Usuario superadministrador del sistema.
- Se bootstrappea el catalogo SaaS oficial de Sistema con categorias y productos
  existentes.
- Se valida catalogo publico de Marketplace para:
  - licencia base `sistema-licencia-estandar-mensual`;
  - producto SaaS adicional `sistema-pack-conecta-mensual`.
- Se ejecuta compra por transferencia bancaria mediante:
  - `POST /api/v1/marketplace/checkout/drafts`;
  - `POST /api/v1/marketplace/checkout/bank-transfer`;
  - `POST /api/v1/marketplace/admin/orders/{order_id}/confirm-bank-transfer`.
- Se verifica entrega real:
  - licencia base como `empresa_licencia`;
  - Pack Conecta como `saas_right`;
  - eventos `license_marketplace_purchase_activated` y
    `saas_right_marketplace_purchase_activated`.
- Se verifica visibilidad por empresa:
  - `GET /api/v1/admin-licenses/me`;
  - `GET /api/v1/admin-licenses/summary`;
  - `saas_products`, capacidades comerciales y derecho `PACK_CONECTA`.
- Se verifica Conecta funcional:
  - `GET /api/v1/conecta/limits`;
  - `POST /api/v1/conecta/slots`;
  - `GET /api/v1/conecta/slots`;
  - `GET /api/v1/conecta/admin/summary`.
- Se confirma permiso:
  - un administrador comprador no puede editar productos SaaS administrados;
  - superadministrador si puede editarlos.

## Correccion derivada

La certificacion detecto que una edicion parcial superadministradora de un
producto SaaS podia perder metadata comercial en `product_meta`, incluyendo
`delivery_kind` y `commercial_code`. Se ajusta
`backend/app/services/marketplace.py` para preservar metadata existente y nueva
al normalizar productos Marketplace, evitando que una edicion de precio
desactive derechos SaaS comprados.
