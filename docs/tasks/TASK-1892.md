# TASK-1892: MVP Equipo Slice 1 - perimetro EDT anti-fuga

## Modo

GIPROY CLASICO

## Tipo

EJECUCION MVP SEGURA

## Objetivo

Implementar el primer slice verificable de `Equipo colaborativo por EDT` sin activar
colaboracion completa: un colaborador asignado a una rama EDT puede consultar solo
su rama, sus descendientes y el contexto ancestro minimo; no puede ver ramas
hermanas, lineas de presupuesto de otras ramas ni modificar la EDT.

## Decision de alcance

Este TASK no implementa `Equipo` completo. Quedan fuera:

- Invitaciones comerciales.
- Compra/entrega del derecho `PACK_EQUIPO`.
- UI de asignacion de colaboradores.
- Locks por partida.
- Log de cambios colaborativo.
- Flujo de propuesta, aprobacion y rechazo.
- Edicion colaborativa de presupuestos, cronogramas o EDT.

## Slice implementado

1. Reutilizar `ProyectoAsignacion` como materializacion temporal de permisos por
   usuario, proyecto, modulo y `edt_id`.
2. Proteger `GET /api/v1/edt/project/{proyecto_id}` para usuarios no
   administradores:
   - usuario sin asignacion directa al proyecto: `403`;
   - usuario con asignacion EDT restringida: arbol podado a ramas permitidas;
   - administrador/superadministrador: vista completa conservada.
3. Bloquear mutaciones EDT para usuarios no administradores durante el MVP:
   - crear;
   - actualizar;
   - mover;
   - borrar;
   - operaciones bulk.
4. Certificar con empresa mockup que:
   - el colaborador no ve ramas EDT no asignadas;
   - el colaborador no ve lineas de presupuesto de ramas no asignadas;
   - el filtrado no elimina datos ocultos en base;
   - un usuario sin asignacion no accede por URL directa;
   - el administrador conserva visibilidad completa.

## Riesgos tratados

- Fuga lateral de EDT por endpoint directo.
- Fuga lateral de lineas de presupuesto relacionadas con otra rama EDT.
- Mutacion accidental de EDT por colaborador antes de tener locks/auditoria.
- Confusion entre licencia/base SaaS y permiso operativo por proyecto.

## Riesgos restantes

- Aun no existe derecho comercial `PACK_EQUIPO` conectado a Marketplace.
- Aun no existe pantalla superadmin/admin para asignar colaboradores a EDT.
- Aun no hay locks ni aprobacion/rechazo; por eso el MVP queda read-only para
  colaboradores.
- Cronogramas y otros modulos deben recibir validaciones equivalentes en slices
  posteriores antes de permitir escritura colaborativa.
