# TASK-1894: politica global de formas de pago comerciales

## Modo
GIPROY CLASICO

## Tipo
IMPLEMENTACION FOCAL + CONTROL COMERCIAL

## Estado
Cerrada

## Objetivo

Asegurar que las formas de pago activas no se interpreten como exclusivas de
compras publicas, sino como metodos comerciales globales para toda compra
disponible que pase por el checkout de Marketplace/SaaS.

## Politica implementada

- Una forma de pago solo puede usarse si esta activa y lista
  (`sandbox_ready` o `production_ready`).
- La misma lista de metodos activos aplica a productos publicos, licencias,
  packs SaaS, modulos y productos sistema vendibles.
- La visibilidad del producto puede depender de empresa, permisos, licencia o
  metadata comercial, pero los metodos de pago no se duplican por canal.
- La configuracion y activacion sigue siendo administrada desde
  Marketplace/Admin por usuario con permiso administrativo/superadministrador.

## Cambios realizados

- `marketplace_service` expone una validacion unica de metodo de pago comercial
  activo/listo.
- `marketplace_checkout_service.create_checkout_draft` rechaza slugs de pago
  inexistentes, inactivos o incompletos antes de crear el draft.
- `submit_bank_transfer_checkout` vuelve a validar transferencia bancaria antes
  de aceptar el comprobante, evitando drafts antiguos con metodo desactivado.
- El E2E SaaS con empresa mockup valida que transferencia bancaria inactiva no
  puede usarse, la activa por endpoint admin y luego compra una licencia base y
  un pack SaaS con el mismo metodo.
- La base local queda con `bank_transfer` activo y listo para compras
  comerciales disponibles.
