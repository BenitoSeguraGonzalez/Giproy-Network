# TASK-1896: plantilla Modo BIM alineada al baseline clasico

## Modo
GIPROY CLASICO / DOCUMENTACION BIM

## Tipo
DOCUMENTACION OPERATIVA + GOBIERNO DE SESION

## Estado
Cerrada

## Objetivo

Actualizar `docs/plantillas prompt/Prompt Modo BIM.txt` para que tenga la misma
capacidad operativa de la plantilla `Modo Clasico`, ajustada al carril BIM
paralelo y protegiendo GiProy Clasico con BIM apagado. Ademas, separar la
documentacion operativa BIM en una estructura paralela propia.

## Cambios realizados

- La plantilla BIM incorpora el analisis obligatorio completo del modo clasico,
  incluyendo progreso seguro, preflight Docker y documentos BIM complementarios.
- Se agrega el estado enterprise vigente: baseline `TASK-1807`, fases 0 a 5
  cerradas, Fase 6 documental y despliegue Docker/Coolify pausado.
- Se formalizan reglas para:
  - capa BIM paralela;
  - backend unico con dominio BIM aislado;
  - frontend BIM desacoplado;
  - feature flags, allowlists y rollback limpio;
  - no dependencia desde GiProy Clasico hacia BIM;
  - estructura TASK BIM propia e independiente del carril clasico.
- Se agregan reglas de frontend BIM, backend BIM e integracion futura
  BIM `<->` EDT/APUs/Presupuesto.
- Se replica el formato de ejecucion, cierre y respuesta del modo clasico,
  ajustado a impacto BIM y no interferencia con GiProy Clasico.
- Se exige documentar trabajo BIM en una estructura TASK independiente, sin
  reutilizar, renumerar ni mezclar TASKs clasicas para cerrar trabajo BIM.
- Se crea `docs/tasks/bim` como carril operativo paralelo para TASKs BIM.
- Se crea `docs/tasks/bim/BIM_TASK_INDEX.md` y la serie inicial
  `BIM-TASK-0000` a `BIM-TASK-0014`.
- `BIM_INDEX.md`, `BIM_EXECUTION_ROADMAP.md`, `BIM_MASTER_PLAN.md`,
  `BIM_PARALLEL_IMPLEMENTATION_STRATEGY.md` y `BIM_VALIDATION_PLAN.md`
  quedan alineados a la estructura `BIM-TASK-*`.
- Las TASK historicas `TASK-0545` a `TASK-0559` quedan declaradas como
  planificacion legacy, no como carril operativo nuevo.
- Se mantienen las guardas enterprise: sin Docker/Coolify/CI/CD salvo solicitud,
  sin imports directos de `axiosConfig` fuera de `frontend/src/api`, sin
  `console.log` productivos y sin ruptura de `TASK-1779` a `TASK-1807`.

## Impacto

Documentacion operativa de sesiones IA y gobierno paralelo para el carril BIM.
Sin cambios de backend, frontend productivo, DB, migraciones, auth/JWT/tenant,
EDT, presupuestos, cronogramas, BIM runtime, Docker/Coolify/CI/CD ni archivos
runtime.
