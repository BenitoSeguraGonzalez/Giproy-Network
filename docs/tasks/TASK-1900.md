# TASK-1900 - Email real para avisos de licencia

Fecha: 2026-06-09
Modo: GIPROY CLASICO

## Objetivo

Implementar servicio de email real para avisos SaaS de licencias con plantillas versionadas y auditoria de entrega.

## Alcance previsto

- Configuracion SMTP o proveedor transaccional.
- Templates para bienvenida, caducidad, solo lectura, recordatorios y cierre.
- Reintentos controlados y registro de fallos.

## Estado

Parcial.

## Slice implementado

- `email_utils.send_transactional_email` soporta backend `mock` por defecto y backend `smtp` configurable.
- Configuracion disponible: `EMAIL_BACKEND`, `EMAIL_FROM_EMAIL`, `EMAIL_FROM_NAME`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_USE_TLS`, `SMTP_USE_SSL`.
- `dispatch_pending_email_events` usa el adaptador transaccional, marca `sent` con evidencia `email_dispatch` o `failed` con `last_error`.
- `send_reset_password_email` reutiliza el adaptador para no mantener dos carriles de email.
- `dispatch-email`, `housekeeping/run`, `housekeeping/purchase-lifecycle` y el runner operativo soportan `retry_failed` para reintentar eventos `failed` tras corregir SMTP.
- Pytest focal cubre que un evento `failed` no se reenvia por defecto y si se recupera con `retry_failed=true`.

## Pendiente

- Configurar proveedor SMTP real o servicio transaccional en entorno.
- Templates versionadas por tipo de aviso.
- Politica avanzada de backoff/requeue automatico para eventos `failed`.
