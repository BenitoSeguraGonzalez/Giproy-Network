# TASK-1907 - Aviso de fin de compra con vigencia

Fecha: 2026-06-09
Modo: GIPROY CLASICO

## Objetivo

Completar el flujo de aviso cuando un producto comprado con fecha de fin llega a su finalizacion.

## Alcance previsto

- Ejecutar housekeeping periodico sobre compras `completed` con vigencia.
- Detectar fecha de fin desde metadata comercial o contrato persistido.
- Enviar email al comprador/administrador correspondiente.
- Mostrar aviso interno `purchase_lifecycle_ended`.
- Auditar estado, deduplicacion y resultado.

## Slice implementado ahora

- Fundacion backend para colar `purchase_lifecycle_ended` de forma idempotente.
- Deteccion inicial basada en `product_meta.duration_months`.
- Payload cliente con asunto, cuerpo, severidad y accion recomendada.
- Test focal de producto con vigencia vencida, idempotencia y producto aun vigente sin aviso.
- Consumo in-app y despacho mock de email disponibles via endpoints generales de `license-notifications`.
- Housekeeping superadministrador disponible en `/api/v1/license-notifications/housekeeping/purchase-lifecycle` para detectar vencidos y despachar email mock opcional.
- Housekeeping integral superadministrador disponible en `/api/v1/license-notifications/housekeeping/run` para probar compra con vigencia, caducidad de licencia, solo lectura y despacho opcional.
- Test endpoint de producto vencido: superadmin ejecuta housekeeping, cliente ve aviso interno y email queda `sent` en modo mock.
- Runner operativo `backend/scripts/license_notification_housekeeping.py` para ejecutar el barrido de fin de compra, caducidad de licencia y, opcionalmente, despachar emails pendientes de compra/licencia desde una tarea programada externa.
- El runner admite `--dry-run`, `--empresa-id`, `--today`, `--dispatch-email`, `--dispatch-limit` y `--notification-type`.

## Pendiente

- Programar el scheduler externo o tarea periodica que invoque el runner segun la politica operativa.
- Configuracion SMTP real.
- Politica de desactivacion del derecho comprado cuando aplique.

## Estado

Parcial, con fundacion, endpoint, runner operativo y tests focales completados.
