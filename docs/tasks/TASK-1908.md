# TASK-1908 - Validacion email obligatoria en registro publico

Fecha: 2026-06-10
Modo: GIPROY CLASICO

## Objetivo

Corregir la regresion del registro publico para que una empresa no quede activa
sin validar previamente el email del administrador, y bloquear altas duplicadas
por RUC de administrador.

## Alcance

- Registro publico clasico `/register`.
- Email transaccional de validacion.
- Activacion posterior por token.
- Bloqueo server-side de una segunda empresa para el mismo RUC de administrador.
- Eliminacion automatizable de empresas pendientes no validadas tras 5 horas.

## Cambios realizados

- `/register` deja de devolver token de sesion y responde
  `pending_email_verification`.
- La empresa y el usuario administrador inicial se crean como `activo=False`
  hasta validar el email.
- La empresa persiste `ruc`, `email`, `contacto_email`,
  `contacto_nombre` y `contacto_telefono` desde el alta publica.
- Se agrega `RegistrationVerificationToken` y migracion Alembic no destructiva
  `de1908a1b2c3_registration_verification_tokens.py`.
- Se agrega `GET /register/verify?token=...` para activar empresa y usuario
  si el token sigue vigente.
- El token caduca a las 5 horas.
- Si un registro pendiente caduca, el backend puede purgar empresa, usuario,
  token y RUC asociado sin tocar empresas activas.
- El registro purga pendientes caducados del mismo email/RUC antes de validar
  duplicados, permitiendo reintentos limpios despues de caducidad.
- Se agrega `backend/scripts/cleanup_expired_registration_verifications.py`
  para programar el borrado de pendientes caducados desde tarea externa.
- El modal clasico de registro muestra instrucciones de validacion por email
  y ya no auto-inicia sesion.
- Se agrega la pagina publica `/verify-registration`.
