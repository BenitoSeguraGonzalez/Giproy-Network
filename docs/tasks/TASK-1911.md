# TASK-1911 - Plan de adecuacion alias empresa y email corporativo SaaS

Fecha: 2026-06-15
Modo: GIPROY CLASICO
Estado: Cerrada

## Objetivo

Definir y controlar la adecuacion clasica para soportar alias de empresa y
configuracion persistente de email corporativo desde el menu SaaS de
superadministrador, sin interferir con BIM ni reabrir infraestructura pausada.

## Alcance autorizado

- Registro publico clasico y modal de creacion/edicion de empresa.
- Visualizacion clasica del nombre de empresa, usando alias si existe.
- Backend comun clasico para persistir alias de empresa.
- Configuracion SaaS superadministrador para email corporativo, SMTP, Gmail y
  URL publica de activacion.
- Prueba manual de envio desde la UI de superadministrador.

## Fuera de alcance

- Docker, Coolify, CI/CD, staging y produccion.
- UX BIM, rutas BIM o dependencias nuevas hacia BIM.
- Cambios destructivos en PostgreSQL.
- Cambios en auth/JWT, permisos, tenant, EDT, presupuestos, cronogramas o datos
  runtime fuera de lo necesario para el alta pendiente por email.

## Plan de implementacion

1. Auditar estado documental y reglas vigentes de GiProy Clasico. Cerrado.
2. Confirmar que la falta de email real proviene de configuracion SMTP ausente
   y backend `mock` por defecto.
   Cerrado.
3. Crear campo opcional `Empresa.alias` con migracion no destructiva. Cerrado.
4. Exponer alias en schemas y flujos de registro/empresa. Cerrado.
5. Centralizar display name de empresa en frontend clasico. Cerrado.
6. Agregar endpoints superadmin para leer, editar y probar configuracion SMTP.
   Cerrado.
7. Agregar UI exclusiva en menu SaaS `Administracion Global > Email corporativo`
   para email corporativo, Gmail y URL publica de activacion.
   Cerrado.
8. Validar backend, frontend, smokes anti-BIM y guardas clasicas. Cerrado.
9. Documentar TASK de implementacion, CHANGELOG y HANDOFF. Cerrado.

## Riesgos controlados

- El password SMTP queda persistido como configuracion de sistema y se devuelve
  siempre enmascarado al frontend.
- Gmail requiere contrasena de aplicacion, no la contrasena normal de la cuenta.
- Mientras `EMAIL_BACKEND` siga en `mock`, el registro ya no debe considerarse
  email realmente entregado.
- La URL publica de activacion debe mantenerse actualizada si cambia el dominio.

## Diagnostico SMTP inicial

La comprobacion de solo lectura confirma `EMAIL_BACKEND=mock`, sin `SMTP_HOST`
ni `SMTP_USERNAME` configurados. En `SystemConfig` ya consta
`FRONTEND_PUBLIC_URL=https://giproy-network.excompc.dpdns.org`, pero no hay
credenciales SMTP reales cargadas.

## No interferencia BIM

El plan opera solo sobre capa clasica, backend comun y configuracion SaaS
existente. No activa UX BIM ni crea acoplamientos hacia BIM.

## Cierre documental

Plan cerrado el 2026-06-16. La implementacion queda absorbida y validada por:

- `TASK-1912`: alias de empresa y email corporativo SaaS.
- `TASK-1913`: aislamiento SaaS de gestion de empresas.
- `TASK-1914`: ajuste visual de toolbar en Empresas SaaS.

No quedan TASKs de implementacion abiertas dentro de este plan. La carga de
credenciales SMTP/Gmail reales sigue siendo una operacion de configuracion del
superadministrador desde `Administracion Global > Email corporativo`, no una
TASK tecnica pendiente.

## Rollback

Revertir la TASK de implementacion asociada, la migracion de alias si no fue
aplicada, endpoints de email-settings, UI de email corporativo y entradas
documentales.
