## Objetivo

Corregir el fallo runtime `No se pudo cargar la bandeja` en
`Otros Servicios > Envios y Transferencias` sin cambiar contratos funcionales ni
UI clasica.

## Diagnostico

La pantalla llamaba correctamente a
`GET /api/v1/transferencias/tray`, pero PostgreSQL local no tenia aplicadas las
tablas de la migracion `de1917a1b2c3_transferencias_foundation.py`.

Evidencia en `backend/fatal_errors.log`:

- `psycopg2.errors.UndefinedTable: no existe la relacion "transfer_shipments"`.
- Error producido al consultar la bandeja con empresa activa `empresa_id=1`.

## Alcance

- Aplicar la migracion Alembic existente `de1917a1b2c3`.
- Confirmar que la base local queda en la cabeza de transferencias.
- Confirmar que las tablas `transfer_*` existen.
- Confirmar que el servicio de bandeja responde sin error.

## Fuera de alcance

- No se modifica codigo frontend.
- No se modifica codigo backend.
- No se cambian contratos API, auth, tenant, roles, licencias ni Marketplace.
- No se reabre Docker, Coolify, CI/CD, staging ni produccion.
- No se introduce dependencia ni UX BIM.

Se aplico:

```powershell
..\.venv\Scripts\python.exe -m alembic -c alembic.ini upgrade de1917a1b2c3
```

## Impacto

La bandeja deja de fallar por tabla inexistente. Si no hay envios en el rango,
la UI debe mostrar estado vacio sin alerta roja.

anterior en una base local descartable, Alembic permite bajar esta revision,
pero el downgrade elimina las tablas `transfer_*`; por tanto no debe ejecutarse
si ya existen envios reales.
