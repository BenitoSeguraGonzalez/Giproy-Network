# TASK-1929 - Implementacion visual Proyectos en Transferencias

Estado: Cerrada

Fecha: 2026-06-16

Modo: GIPROY CLASICO

## Objetivo

Adecuar visualmente `Otros Servicios > Envios y Transferencias` para que su
toolbar, filtros, KPIs, listado, acciones y modales se alineen con el look &
feel operativo de `Proyectos` y `Datos de Proyecto`.

## Alcance

- Frontend clasico.
- Pantalla `frontend/src/pages/EnviosTransferencias.jsx`.
- Smoke focal `frontend/scripts/smoke-classic-transferencias-ui.mjs` si se
  requiere reforzar guardas visuales.
- Reutilizacion de componentes existentes:
  - `ProjectSegmentedSwitch`.
  - `ProjectHeaderActionButton`.
  - `LiquidButton`.
  - `ClearSearchField`.
  - `SearchableSelect`.
  - `AnimatedSelect`.
  - `AnimatedDateInput`.

## Fuera de alcance

- No backend.
- No DB.
- No migraciones.
- No cambios API.
- No auth, JWT, permisos, empresa activa ni multi-tenant.
- No cambios funcionales en Marketplace, Conecta, licencias, importacion o
  transferencias.
- No UX BIM, rutas BIM ni dependencias BIM.
- No Docker/Coolify/CI-CD/staging/produccion.

## Aceptacion

- La toolbar superior usa botones tecnicos soft alineados con `Proyectos`.
- `Nuevo envio` y `Refrescar` dejan de leerse como botones ajenos o
  sobredimensionados.
- El filtro `Todos / Entrada / Salida` usa `ProjectSegmentedSwitch` o patron
  comun equivalente.
- El buscador se alinea con el patron de `Proyectos` y mantiene valor vacio
  como `''`.
- El selector de estado queda integrado como filtro tecnico compacto.
- Las fechas usan `AnimatedDateInput` en estilo compacto coherente.
- Las metricas se reducen a KPIs compactos.
- La bandeja queda como lista densa alineada con el portafolio de `Proyectos`.
- Las acciones de fila usan microbotones soft con color semantico en icono o
  borde.
- El timeline por envio no rompe la densidad de fila.
- Los modales de nuevo envio y rechazo usan estructura tecnica clasica:
  secciones soft, controles compactos, cierre homogeneo y acciones de footer
  consistentes.
- No hay `<select>` nativo, `input[type="date"]` visible final,
  `window.prompt`, imports directos de `axiosConfig` fuera de
  `frontend/src/api` ni `console.log` productivo.
