# TASK-1930 - Empresas para comunicarse por codigo

Estado: Cerrada

Fecha: 2026-06-16

Modo: GIPROY CLASICO

## Objetivo

Implementar en frontend clasico la entrada de codigo publico y el listado de
empresas habilitadas para comunicarse en `Otros Servicios > Envios y
Transferencias`.

## Alcance

- `frontend/src/api/transferencias.js`.
- `frontend/src/pages/EnviosTransferencias.jsx`.
- `frontend/scripts/smoke-classic-transferencias-ui.mjs`.
- Documentacion del plan funcional.

## Fuera de alcance

- No backend nuevo.
- No DB ni migraciones.
- No auth, JWT, tenant, empresa activa ni permisos.
- No cambios funcionales en licencias, Conecta, Marketplace, importacion ni
  contenido transferible.
- No pulido visual final.
- No BIM.
- No Docker/Coolify/CI-CD/staging/produccion.

## Aceptacion

- El modal de `Nuevo envio` muestra el codigo publico del usuario operador.
- El modal muestra un listado de empresas ya habilitadas para comunicarse.
- El listado distingue destinatarios fijos y adicionales.
- Se muestra resumen de slots fijos disponibles y adicionales activos.
- Existe entrada funcional de codigo de conexion.
- El codigo se valida mediante `/transferencias/recipient-code/resolve`.
- La vista previa muestra solo empresa destino, alias/nombre legal si aplica,
  sin exponer usuario propietario del codigo.
- La asociacion exige confirmacion explicita mediante
  `/transferencias/recipients`.
- Tras confirmar, el listado se refresca y la nueva empresa queda seleccionada.
- Las llamadas API pasan por cliente de dominio en `frontend/src/api`.
- Sin imports directos de `axiosConfig` fuera de `frontend/src/api`.
- Sin `console.log` productivo.
- Sin UX BIM ni dependencia nueva hacia BIM.

## Cambios realizados

- `transferenciasApi` expone `resolveRecipientCode` y `createRecipient`.
- `NewShipmentModal` incorpora estado de destinatarios, resumen de slots,
  entrada de codigo, validacion, vista previa, confirmacion y seleccion
  automatica.
- La lista de empresas habilitadas se puede usar para seleccionar destinatario
  sin depender solo del combobox.
- El smoke focal de transferencias valida que la entrada por codigo y los
  metodos de API no desaparezcan.
- El plan funcional incorpora `TASK-1930`.

  refinamiento como solicito el usuario.
