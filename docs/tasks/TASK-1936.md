# TASK-1936 - Retirada de accion Abrir en Transferencias

Estado: Cerrada

Fecha: 2026-06-17

Modo: GIPROY CLASICO

## Objetivo

Eliminar la accion funcional `Abrir` de `Otros Servicios > Envios y
Transferencias`. El receptor no necesita una apertura intermedia: si el envio
esta disponible, la accion operativa es `Importar`; si esta bloqueado por
Marketplace, debe comprar/revalidar antes de importar o usar.

## Alcance

- UI clasica de bandeja de transferencias.
- Cliente frontend de dominio `transferenciasApi`.
- Endpoint backend publico de apertura.
- Servicio backend de transferencias.
- Contrato de requisitos Marketplace.
- Tests focales y smoke frontend.
- Plan funcional documentado.

## Regla funcional cerrada

- No existe accion `Abrir` para envios recibidos.
- El emisor puede cancelar mientras el envio no haya sido importado.
- Marketplace bloquea importacion y uso, no una apertura intermedia.
- `opened_at` queda solo como campo historico/legacy de persistencia, sin
  accion, timeline ni estado nuevo asociado.

## Cambios realizados

- Se retira el boton `Abrir` de la bandeja.
- Se elimina `openShipment` del cliente frontend.
- Se elimina `POST /transferencias/shipments/{shipment_id}/open`.
- Se elimina `open_shipment` del servicio backend.
- `import_shipment` deja de escribir `opened_at`.
- El timeline deja de emitir `Envio abierto`.
- El contrato de estados nuevos ya no incluye `abierto`.
- `can_open_or_import` pasa a `can_import_or_use`.
- La cancelacion del emisor solo se bloquea si el envio ya fue importado.
- La smoke frontend impide reintroducir accion o cliente `openShipment`.
- El plan funcional queda actualizado con la regla nueva.

## Fuera de alcance

- No se elimina columna `opened_at` ni datos historicos.
- No se toca auth/JWT, tenant global, licencias fuera de transferencias ni
  contratos de otros modulos.
- No UX BIM ni dependencias BIM.
- No Docker, Coolify, CI/CD, staging ni produccion.
