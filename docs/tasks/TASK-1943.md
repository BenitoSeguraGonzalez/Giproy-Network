# TASK-1943 - Retirada de funcion Portatil del header clasico

Estado: cerrada
Fecha: 2026-06-18
Modo: GIPROY CLASICO

## Objetivo

Eliminar la funcion visible `Portatil` del header clasico porque ya no aporta
valor operativo y puede confundir el uso normal del sistema.

## Alcance

- Retirar el boton `Portatil` de `AppLayout`.
- Eliminar la activacion manual y persistida del modo portatil desde el header.
- Dejar inerte el helper legacy de `portableWorkspace` para que ninguna lectura
  local reactive compactaciones.
- Quitar el enganche directo de `APUs` al override manual.
- Actualizar guardas frontend y documentacion.

## No alcance

- No retirar reglas responsive reales basadas en ancho/alto efectivo de modulos.
- No cambiar contratos API, auth, tenant, licencias, empresas ni DB.
- No tocar BIM, Docker, Coolify, CI/CD, staging ni produccion.
- No refactorizar masivamente EDT, EDO, Presupuesto o modales sensibles.

## Cambios

- `frontend/src/layouts/AppLayout.jsx` ya no importa ni ejecuta el override
  manual de `portableWorkspace`.
- `frontend/src/pages/APUs.jsx` compacta el editor solo por viewport real.
- `frontend/src/utils/portableWorkspace.js` conserva compatibilidad inerte:
  no lee ni activa overrides.
- `frontend/scripts/smoke-classic-transfer-header-signal.mjs` bloquea que
  vuelva el boton `Portatil` o la activacion manual al header.
- `docs/STYLE_GUIDE.md` sustituye la regla de override manual por la regla
  `Sin Override Manual de Modo Portatil`.

## Validaciones

- Smoke focal del header de transferencias.
- Smoke anti-BIM clasico.
- Build frontend.

## Resultado

La funcion `Portatil` desaparece del header clasico y queda sin efecto cualquier
preferencia antigua persistida localmente. El responsive real de modulos
sensibles se conserva.
