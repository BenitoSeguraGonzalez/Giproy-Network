# TASK-1946 - Alineacion de encabezados del grid de presupuesto

Estado: cerrada
Fecha: 2026-06-18
Modo: GIPROY CLASICO

## Objetivo

Corregir la regresion visual en `Proyectos > Presupuesto`: los nombres de las
columnas del listado de items no quedaban alineados con las columnas reales,
especialmente tras ampliar la columna de acciones.

## Diagnostico

`LineasPresupuestoTab` mantenia anchos de columnas repetidos en encabezado,
filas, capitulos y placeholders. Las filas operativas ya habian crecido la
columna `ACCIONES` a `144px`, pero el encabezado y algunos placeholders seguian
usando el ancho legacy `96px`, provocando desplazamiento visual.

## Alcance

- Frontend clasico de Presupuestos.
- Solo layout del grid de lineas de presupuesto.
- Sin cambios backend, API, DB, auth, tenant, EDT ni calculos de presupuesto.

## No alcance

- No modificar contratos de Presupuestos.
- No tocar editor APU, tanteo, indirectos, reportes ni persistencia.
- No tocar BIM, Docker, Coolify, CI/CD, staging ni produccion.
- No reabrir el baseline TASK-1807.

## Cambios

- Se centralizan los anchos del grid en `BUDGET_COLUMN_WIDTH`.
- Header, capitulos, lineas y placeholders reutilizan los mismos tokens de
  columna.
- La columna `ACCIONES` queda alineada al ancho real disponible para los
  controles actuales.
- Los encabezados visibles se normalizan a `CÓD. EDT`, `UNIDAD` y
  `P. UNITARIO`.
- El smoke focal de Presupuestos valida que el ancho de acciones este
  centralizado y reutilizado, sin depender de una cadena completa de clases.

## Validaciones

- `cmd /c node frontend\\scripts\\smoke-classic-presupuesto-api-boundary.mjs`: OK.
- `node frontend\\scripts\\smoke-classic-no-bim-contamination.mjs`: OK.
- `npm run build`: OK.

Warning conocido no bloqueante:

- Chunks grandes Vite.

## Resultado

El encabezado del listado de items de presupuesto vuelve a quedar alineado con
las columnas reales y el arreglo queda menos fragil frente a futuras variaciones
del grid.
