# TASK-1952 - Decision de Base de Proyecto al borrar Proyecto

Fecha: 2026-06-18
Modo: GiProy Clasico
Estado: Cerrada

## Objetivo

Ajustar el borrado de Proyecto para que el usuario decida explicitamente si la
Base de Proyecto asociada tambien se mueve a papelera o si se conserva como
Base de Trabajo reutilizable.

## Alcance

- Capa clasica de Proyectos.
- Servicio backend de borrado/papelera de Proyecto.
- Cliente API clasico `proyectosApi`.
- Modal clasico de eliminacion de Proyecto.
- Test focal de contrato Proyecto/Base.

Queda fuera:

- BIM, UX BIM o dependencias BIM.
- Docker, Coolify, CI/CD, staging o produccion.
- Cambios destructivos de DB.
- Cambios en auth, JWT, permisos globales o tenant fuera del endpoint
  existente.

## Cambios realizados

- `DELETE /proyectos/{id}` acepta `delete_project_base`.
  - `true` por defecto: conserva comportamiento anterior, moviendo Proyecto y
    Base de Proyecto a papelera.
  - `false`: mueve solo el Proyecto a papelera y convierte la Base de Proyecto
    asociada en `Base Maestra` visible como Base de Trabajo reutilizable.
- `ProyectoService.soft_delete_full_project` registra en auditoria:
  - bases movidas a papelera,
  - bases preservadas,
  - decision `delete_project_base`.
- Restaurar un Proyecto cuya base fue preservada vuelve a tipar esa base como
  `Base de Proyecto` para recuperar coherencia operativa.
- Purgar un Proyecto cuya base fue preservada elimina el Proyecto pero no borra
  la base conservada.
- El modal de eliminacion de Proyecto pregunta explicitamente por la Base de
  Proyecto antes de la confirmacion final.
- `frontend/src/api/proyectos.js` envia la decision por cliente de dominio, sin
  llamadas API directas.

## Impacto

Impacto funcional acotado y positivo:

- El usuario ya no pierde necesariamente la Base de Proyecto al borrar un
  Proyecto.
- La base puede sobrevivir como Base de Trabajo reutilizable.
- La ruta por defecto conserva compatibilidad con TASK-1951.
- La restauracion mantiene coherencia Proyecto/Base si el Proyecto vuelve desde
  papelera.

## Rollback

Rollback focal posible:

- Retirar el parametro `delete_project_base` del endpoint y del cliente API.
- Volver a mover siempre la Base de Proyecto junto al Proyecto.
- Retirar el selector del modal.

No hay migracion nueva ni cambios destructivos de DB que revertir.
