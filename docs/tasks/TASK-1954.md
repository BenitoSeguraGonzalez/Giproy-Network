# TASK-1954 - Reactivacion de papelera clasica en backend vivo

Fecha: 2026-06-19
Modo: GiProy Clasico
Estado: Cerrada con advertencia operativa de datos

## Objetivo

Corregir la causa real del fallo al abrir la papelera de Proyectos, observado
como `Se produjo un evento del sistema sin detalle adicional disponible.`, y
confirmar si los Proyectos borrados en `Santiago Bermeo` estaban realmente en
papelera.

## Diagnostico

El problema principal no era el texto del dialogo.

El backend vivo en `localhost:3001` estaba ejecutando un proceso anterior a
TASK-1951/TASK-1952:

- `GET /api/v1/openapi.json` no exponia `/api/v1/proyectos/papelera`.
- El OpenAPI vivo tampoco exponia `delete_project_base`.
- El codigo local del repo si exponia esas rutas y parametros.
- Los logs mostraban `GET /api/v1/proyectos/papelera?empresa_id=3` con `422`.

Esto explica el fallo funcional: la UI clasica de papelera hablaba con un
backend desfasado que no tenia la ruta real de papelera cargada.

## Estado de datos Santiago Bermeo

Consulta local de solo lectura sobre empresa `Santiago Bermeo` (`empresa_id=3`)
antes del reinicio:

- `projects_deleted = 0`
- `bases_deleted = 0`
- `projects_active = 1`
- `bases_active = 2`
- Proyecto activo restante: `id=7`, `Proyecto Prueba Compartir 1`,
  `SantiagoBermeo-2026-001`.

Por tanto, los Proyectos borrados durante la prueba no quedaron en la papelera
logica de TASK-1951. La causa mas probable es que fueron procesados por el
backend viejo con borrado fisico, no por el flujo vigente de soft delete.

No se hizo recuperacion ni saneamiento de datos en esta TASK.

## Cambios realizados

- Se reinicio `GiProy-Backend` mediante el launcher oficial:
  `tools/launcher/main.py --elevated-action restart_services` y posterior
  `start_services`.
- Se verifico que el backend nuevo expone:
  - `/api/v1/proyectos/papelera`
  - `/api/v1/proyectos/papelera/purge-expired`
  - `/api/v1/proyectos/papelera/{id}/restore`
  - `/api/v1/proyectos/papelera/{id}/purge`
  - parametro `delete_project_base`
- Se confirmo que `GET /api/v1/proyectos/papelera` sin token devuelve `401`,
  no `422`.
- Se confirmo con token valido del usuario de `Santiago Bermeo` que
  `GET /api/v1/proyectos/papelera?empresa_id=3` devuelve `200` y lista vacia
  `[]`.
- Se confirmo con token valido del usuario de `Santiago Bermeo` que
  `GET /api/v1/bases-trabajo/papelera?empresa_id=3` devuelve `200` y lista
  vacia `[]`.
- Se conserva como mejora secundaria la normalizacion de mensajes de
  `AppDialogProvider`, para que futuros errores backend muestren detalle util
  cuando venga como `detail`, `description`, `error`, `Error.message` o lista
  de validacion.
