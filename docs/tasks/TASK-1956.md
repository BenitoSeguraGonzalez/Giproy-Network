# TASK-1956 - Aviso visual fuerte para nuevos Envios y Transferencias

Fecha: 2026-06-19
Modo: GiProy Clasico
Estado: Cerrada

## Objetivo

Compactar el indicador del header de `Envios y Transferencias` para dejar solo
un icono con badge de nuevos pendientes, visible unicamente para
`administrador` y `superadministrador`, y bajar la frecuencia de refresco a 30
segundos.

## Diagnostico

El indicador ya consultaba `transferenciasApi.getTraySummary(...)` desde
`AppLayout`, pero mostraba dos valores redundantes: `Comunicación` y `Nuevos`.
Para el flujo operativo importa el numero de envios nuevos pendientes. La
consulta se hace:

- al montar el layout o cambiar usuario/empresa activa;
- cada `30` segundos mediante `window.setInterval(loadTransferSignal, 30000)`.

El caso observado de header con `1` y bandeja sin filas se debia a desalineacion
de refresco visual: la API viva devolvia el envio, pero la pantalla podia quedar
con una consulta anterior hasta refrescar manualmente.

## Cambios realizados

- `frontend/src/layouts/AppLayout.jsx` conserva el indicador solo para roles
  `administrador` y `superadministrador`.
- El header muestra solo el icono de comunicacion.
- Cuando hay nuevos envios, el icono aplica borde emerald, `ring`, sombra
  luminosa y `animate-pulse`.
- El badge superior muestra solamente `transferSignal.nuevos`.
- Se conserva el click hacia `/servicios/envios-transferencias?bandeja=entrada`.
- Al hacer click se emite `giproy:transfer-signal-opened` para que la bandeja
  abierta cambie a entrada y refresque filtros.
- `EnviosTransferencias.jsx` refresca la bandeja cada 30 segundos.
- Se refuerza `frontend/scripts/smoke-classic-transfer-header-signal.mjs` para
  validar:
  - polling de `30` segundos;
  - estado derivado de nuevos;
  - icono compacto con badge;
  - ausencia de textos redundantes `Comunicación` / `Nuevos`.
- Se refuerza `frontend/scripts/smoke-classic-transferencias-ui.mjs` para
  validar polling de bandeja y evento local del indicador.
