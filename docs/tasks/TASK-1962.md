# TASK-1962 - Reporte visible en Cronogramas Recursos clasico

Fecha: 2026-06-21

Modo: GIPROY CLASICO

## Objetivo

Hacer visible el acceso al reporte existente de `Uso de Recursos` cuando el
usuario esta en `Proyecto > Cronogramas > Recursos`, sin cambiar contratos API,
backend, datos, tenant, permisos ni comportamiento BIM.

## Diagnostico

- El reporte si existia en backend y frontend como variante `resources`.
- La variante estaba disponible desde los menus de reporte de `Gantt` y
  `Valorado`.
- En la pestaña `Recursos`, el header no renderizaba ningun
  `ProjectSectionReportButton`, por lo que el usuario no tenia acceso visible
  desde la vista operacional donde naturalmente esperaba encontrarlo.

## Cambios realizados

- `frontend/src/components/projects/Cronogramas.jsx` muestra ahora un boton
  directo `Reporte de Uso de Recursos` cuando `scheduleTab === 'recursos'`.
- El boton reutiliza el flujo existente:
  `handleOpenCronogramaValoradoReport('resources')`.
- No se crea endpoint nuevo.
- No se modifica el contrato de `reportingApi`.
- No se altera la generacion de preview, Excel ni PDF.
- `frontend/scripts/smoke-classic-cronogramas-api-boundary.mjs` agrega guarda
  para conservar el boton visible en la pestaña `Recursos`.

## Funcion del reporte asignado

El reporte de `Uso de Recursos` consolida los recursos finales derivados del
cronograma valorado operativo.

Su funcion principal es permitir revisar:

- recursos unicos usados por el presupuesto calendarizado;
- cantidades totales por recurso;
- costos directos por recurso;
- distribucion de cantidades y costos por periodo;
- categoria y subcategoria de cada recurso;
- periodo pico de demanda/costo;
- recursos gobernantes por peso economico.

El preview ofrece una lectura ejecutiva compacta, mientras que el Excel conserva
la matriz completa por periodos para analisis operativo. El PDF entrega una
version ejecutiva orientada a revision y comunicacion.
