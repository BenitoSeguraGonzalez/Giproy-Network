# TASK-1965 - Depuracion de console.error productivo en frontend clasico

## Modo

GIPROY CLASICO.

## Objetivo

Retirar `console.error` productivo de `frontend/src` sin cambiar funcionalidad visible ni contratos API.

## Alcance autorizado

- Frontend clasico runtime (`frontend/src`).
- Reporter cliente controlado.
- Smoke general de fronteras API clasicas.
- Documentacion TASK/CHANGELOG/HANDOFF.

## Implementacion

- Se agrega `frontend/src/utils/clientErrorReporter.js`.
- `frontend/src/main.jsx` instala el reporter en `globalThis.reportClientError`.
- Las llamadas `console.error(...)` de `frontend/src` pasan a `globalThis.reportClientError?.(...)`.
- El reporter:
  - no escribe en consola productiva;
  - conserva un buffer corto en `globalThis.__giproyClientErrors`;
  - emite evento interno `giproy:client-error`.
- `frontend/scripts/smoke-classic-api-boundaries.mjs` recorre `frontend/src` y bloquea reintroducir `console.error(`.

## Fuera de alcance

- No se modifican scripts/harness de validacion.
- No se cambian `console.warn` historicos.
- No se toca backend, DB, auth, tenant, EDT, presupuestos, cronogramas ni BIM.

## Validacion

- `cmd /c node frontend\scripts\smoke-classic-api-boundaries.mjs`: OK.
- `cmd /c node frontend\scripts\smoke-classic-no-bim-contamination.mjs`: OK.
