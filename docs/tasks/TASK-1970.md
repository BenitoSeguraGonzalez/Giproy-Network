# TASK-1970 - Baja purgada y recuperacion SaaS por backup cliente

Fecha: 2026-06-22

Modo: GIPROY CLASICO

## Objetivo

Implementar el flujo SaaS para dar de baja una empresa liberando datos
operativos y archivos, conservando solo ficha minima/auditoria y exigiendo que
la recuperacion se haga con una copia de seguridad validada custodiada por el
cliente.

## Alcance

- Modelo `Empresa` gana estado de ciclo de vida y metadata minima de baja
  purgada.
- La eliminacion fisica directa de empresas queda bloqueada desde el servicio.
- `Company Backup` agrega endpoints SaaS de preflight y ejecucion de baja
  purgada con backup cargado y frase final.
- Restore queda bloqueado cuando la licencia resuelve `access_mode=readonly`.
- La identidad de backup expone identificador fiscal normalizado como fundamento
  funcional, manteniendo fingerprint como guarda tecnica.
- `Administracion Global > Empresas` permite baja purgada y recuperacion desde
  backup validado para superadministrador.

## No alcance

- No se modifica BIM.
- No se crean artefactos Docker/Coolify/CI/CD.
- No se cambian contratos operativos de proyectos, EDT, presupuestos ni
  cronogramas.

## Riesgos residuales

- La baja purgada es irreversible sin la copia custodiada por el cliente.
- Los registros protegidos por comercio/auditoria pueden conservar referencias
  minimas estrictamente necesarias.
