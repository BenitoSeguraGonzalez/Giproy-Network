# TASK-1974 - Diagnostico documental de APUs anidados en tiempo y recursos

Fecha: 2026-06-23

Modo: GIPROY CLASICO

## Objetivo

Crear un documento tecnico real que formule el problema de APUs anidados cuando
se usan como base para duracion, recursos por periodo, histogramas, flujo de
caja y cronogramas.

## Alcance

- Analisis de `docs/anidados-tiempo/conversacion-1`.
- Analisis de `docs/anidados-tiempo/conversacion-2`.
- Lectura estructural del Excel
  `docs/anidados-tiempo/Analisis para Project - Nueva Version 2026.xlsx`.
- Creacion de
  `docs/anidados-tiempo/PROBLEMA_APUS_ANIDADOS_TIEMPO_RECURSOS.md`.
- Registro en `docs/CHANGELOG.md` y `docs/HANDOFF.md`.

## No alcance

- No se implementa logica en backend ni frontend.
- No se modifican contratos API, rutas, auth, tenant ni base de datos.
- No se cambia el motor de APUs, Presupuestos, Gantt, Cronogramas, Valorado ni
  recursos.
- No se toca BIM, Docker/Coolify, CI/CD, staging ni produccion.

## Resultado

El documento formaliza que el APU anidado y el APU explotado no son
matematicamente equivalentes y que la practica compromete simultaneamente:

- duracion del APU padre;
- recursos por periodo;
- histogramas de mano de obra/equipos;
- flujo de caja y cronogramas derivados;
- trazabilidad contractual cuando el software modifica datos silenciosamente.

Tambien queda documentado el plan funcional inferido:

- base de modificaciones por base de trabajo, proyecto, revision y APU origen;
- snapshot operativo ejecutable + delta auditable;
- una sola modificacion activa confirmada por APU/revision;
- explosion de anidados hacia recursos funcionales consolidados;
- rendimiento equivalente por trabajo relativo;
- indicador visual discreto para APUs base, APUs con anidados no explotados,
  APUs con anidados explotados y modificaciones activas;
- microindicador por recurso funcional para distinguir recurso directo,
  anidado, consolidado o no fusionado;
- propagacion mediante resolvedor unico hacia todas las secciones de
  Cronogramas.
