# TASK-1975 - Ajuste operativo de recursos por APUs anidados en Cronogramas

Fecha: 2026-06-23

Modo: GIPROY CLASICO

## Objetivo

Implementar el primer slice funcional del plan de APUs anidados para tiempo y
recursos, manteniendo la base de proyecto y los APUs contractuales sin
modificacion directa.

## Alcance

- Backend de Cronograma de Trabajo:
  - incorpora `apu_resource_modifications_v1` en la configuracion del
    cronograma como base funcional de modificaciones por revision;
  - resuelve APUs con prioridad:
    modificacion activa confirmada -> metadata de linea -> base de proyecto;
  - genera snapshot operativo plano por APU en metadata;
  - explota APUs anidados;
  - consolida recursos por clave fuerte;
  - calcula `trabajo_relativo = cantidad * rendimiento`;
  - calcula `rendimiento_equivalente = trabajo_relativo_total /
    cantidad_consolidada`;
  - marca estados `base_sin_anidados`, `anidados_explotados` o
    `conflicto_explosion`.
- Backend de Cronograma Recursos:
  - consume el snapshot operativo cuando existe;
  - mantiene fallback al calculo recursivo historico si no existe snapshot.
- Frontend Gantt clasico:
  - el editor ligero usa recursos operativos cuando el backend los entrega;
  - cantidad editable corresponde a cantidad del recurso dentro del APU;
  - no modifica la cantidad de obra del presupuesto;
  - en APUs con anidados bloquea rendimiento manual y muestra rendimiento
    equivalente calculado;
  - muestra indicador discreto de estado operativo del APU;
  - confirma explicitamente la aplicacion global del APU en la revision activa;
  - persiste la modificacion activa del APU en la configuracion del cronograma
    antes de sincronizar las lineas afectadas.
- Frontend utilidades numericas:
  - `resolveApuLineSimulatedSubtotal` acepta cantidad simulada para que el
    editor ligero refleje subtotales coherentes cuando cambia la cantidad del
    recurso.
- Smokes:
  - se refuerza la guarda de frontera Cronogramas clasica.

## No alcance

- No se crean tablas nuevas ni migraciones Alembic.
- No se modifica la base global de proyecto; una modificacion activa se
  sobrepone funcionalmente solo dentro de la revision activa.
- No se editan APUs contractuales ni lineas de presupuesto.
- No se modifican auth, JWT, tenant, EDT, Presupuestos ni contratos API.
- No se toca BIM, Docker/Coolify, CI/CD, staging ni produccion.
