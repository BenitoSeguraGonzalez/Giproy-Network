# TASK-1978 - Correccion categoria APUs hijos en editor APU desde Presupuestos

Fecha: 2026-06-24

Modo: GIPROY CLASICO

## Objetivo

Corregir la regresion visual/funcional en el editor de APU abierto desde una
linea de presupuesto: los APUs anidados no deben crear una categoria principal
propia dentro del analisis del APU.

## Alcance

- `ApuBudgetEditor` conserva APUs como familia del catalogo lateral para poder
  localizarlos y agregarlos.
- Cuando un APU hijo entra en las lineas del analisis, se clasifica como
  `Materiales` (`categoria_id = 2`).
- Al cargar un APU existente desde Presupuestos, las lineas con `apu_hijo_id`
  se muestran dentro de `Materiales`.
- Al agregar un APU hijo desde el editor embebido de Presupuestos, la nueva
  linea entra tambien en `Materiales`.
- Se elimina la cabecera especial `APUs Relacionados (Hijos)` del editor
  embebido de Presupuestos.
- El payload mantiene `apu_hijo_id`; no se convierte el APU hijo en recurso ni
  se altera el contrato de guardado.
- Se refuerza el smoke de Presupuestos para evitar que reaparezca la categoria
  principal separada.

## No alcance

- No se modifica backend, base de datos, API, auth/JWT, tenant, EDT,
  Presupuestos base, APUs contractuales ni calculos monetarios.
- No se toca BIM, Docker/Coolify, CI/CD, staging ni produccion.
- No se reabre `TASK-1807`.
