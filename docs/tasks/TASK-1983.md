# TASK-1983 - Cancelacion transaccional del editor light Gantt

Fecha: 2026-06-25

Modo: GIPROY CLASICO

## Objetivo

Garantizar que cerrar con `X` el editor light de APU en Gantt descarte todos
los cambios realizados desde su apertura cuando no se haya pulsado Aceptar.

## Diagnostico

- Al abrir el editor ya se conservaba un snapshot del borrador de la linea.
- Al cancelar se restauraba ese snapshot.
- El modal sincroniza automaticamente el snapshot operativo con el borrador
  padre mientras permanece montado.
- Durante el cierre, una sincronizacion tardia podia ejecutarse despues del
  rollback y reintroducir cantidad, rendimiento o metadata operativa.

## Cambios

- Cada apertura crea una sesion explicita ligada a la linea.
- `X` invalida la sesion antes de restaurar el snapshot de apertura.
- El rollback usa copia profunda para no compartir referencias mutables.
- Las sincronizaciones de metadata comprueban que la sesion siga activa y
  pertenezca a la misma linea.
- Tras Aceptar o Cancelar se limpian sesion y snapshot temporal.
- El smoke clasico de Cronogramas protege la secuencia de invalidacion,
  restauracion y bloqueo de emisiones tardias.

## No interferencia

- No modifica la explosion de APUs, trabajo relativo ni rendimiento
  equivalente.
- No modifica Presupuestos, APUs contractuales, backend, DB, API, auth/JWT,
  tenant, EDT ni cantidad de obra.
- Sin BIM, Docker/Coolify, CI/CD, staging ni produccion.
- No reabre guardas de `TASK-1807`.
