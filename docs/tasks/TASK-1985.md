# TASK-1985 - Slice backend/cliente para borradores Gantt y lock de edicion

Fecha: 2026-06-26

Modo: GIPROY CLASICO

## Objetivo

Implementar el primer slice tecnico de la politica `TASK-1984`: separar la
edicion operativa de Gantt en dos capas controladas:

- borrador Gantt persistente, no propagado;
- lock exclusivo de edicion por cronograma.

Este slice no aplica Gantt globalmente, no recalcula Presupuesto y no modifica
precios oficiales.

## Alcance

- Backend comun clasico.
- API `cronogramas-trabajo`.
- Cliente frontend `cronogramasApi`.
- Smokes de frontera API clasica.
- Tests focales de servicio Gantt workflow y modelo de duracion/costos.

## Politica implementada

- El borrador Gantt persiste en backend para retomar sesiones.
- El borrador se identifica por el cronograma de trabajo operativo.
- Confirmar el editor light debe poder guardar una intencion sin propagarla al
  resto del sistema.
- Varios usuarios pueden leer el Gantt, pero solo uno puede tomar lock de
  edicion.
- El lock registra usuario, heartbeat, expiracion, solicitud de liberacion y
  liberacion.
- Un lock activo de otro usuario bloquea edicion y devuelve conflicto.
- Un usuario bloqueado puede solicitar liberacion sin tomar control ni crear
  concurrencia de trabajo.
- Los cambios locales no confirmados siguen fuera del backend.

## Cambios frontend

- `frontend/src/api/cronogramas.js` expone metodos de dominio:
  - `getTrabajoGanttDraft`;
  - `saveTrabajoGanttDraftIntention`;
  - `preflightTrabajoGanttDraftApply`;
  - `applyTrabajoGanttDraft`;
  - `prepareInvalidatedTrabajoGanttDraftAdjustment`;
  - `acquireTrabajoGanttLock`;
  - `heartbeatTrabajoGanttLock`;
  - `requestTrabajoGanttLockRelease`;
  - `releaseTrabajoGanttLock`.
- No se incorporan llamadas directas desde componentes fuera de `frontend/src/api`.
- `Cronogramas.jsx` carga el borrador Gantt junto al cronograma operativo,
  conserva el preview persistente entre sesiones y muestra indicador discreto de
  borrador no propagado.
- `CronogramaGantt.jsx` toma lock antes de abrir el editor light, mantiene
  heartbeat mientras el lock esta activo y libera el lock al cancelar o aceptar.
- Si otro usuario tiene el lock, el editor light no se abre; la UI permite
  solicitar liberacion, registra la solicitud en backend y el propietario la ve
  como aviso operativo con accion explicita para liberar.
- Aceptar en el editor light guarda una intencion de borrador Gantt acumulada y
  deja de escribir como modificacion confirmada en `cronograma_trabajo` o en la
  configuracion global.
- Confirmar globalmente el Gantt ejecuta preflight automatico del borrador: si
  hay intenciones invalidadas, bloquea la aplicacion y exige descartar o ajustar
  antes de propagar; si el flujo clasico persiste correctamente, marca el
  borrador como `applied`.
- Las modificaciones oficiales desde Presupuesto invalidan de forma parcial el
  borrador Gantt activo:
  - cambios de cantidad/linea invalidan solo la linea relacionada;
  - fusiones de lineas invalidan la linea destino y la linea absorbida;
  - tanteos oficiales de APU invalidan por `apu_id`;
  - las intenciones con `affected_line_ids` se consideran relacionadas aunque
    su linea principal sea otra.
- La vista Gantt muestra las intenciones invalidadas y permite descartarlas de
  forma explicita, conservando las intenciones pendientes compatibles y
  retirando del preview persistente las lineas descartadas.
- La vista Gantt permite preparar reajuste de lineas invalidadas:
  - conserva solo la intencion operativa compatible;
  - elimina snapshots/previews derivados antiguos;
  - marca la linea como `adjustment_required`;
  - bloquea la aplicacion global hasta reabrir y aceptar el editor light desde
    la base vigente.
- Reaceptar el editor light en una linea pendiente de reajuste sustituye la
  intencion stale relacionada, evitando apilar estados ambiguos.
- `CronogramaGantt.jsx` limpia de `drafts` locales las lineas gestionadas por
  backend que ya no existen en `preview_snapshot.line_payload_map`, evitando
  que previews descartados o preparados para reajuste sobrevivan en memoria.
