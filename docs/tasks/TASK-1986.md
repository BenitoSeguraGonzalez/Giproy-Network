# TASK-1986 - Advertencias de borrador Gantt en reportes oficiales

Fecha: 2026-06-27

Modo: GIPROY CLASICO

## Objetivo

Endurecer la politica transversal de precios y tiempo para que los reportes
oficiales de Cronogramas no incorporen trabajos pendientes de Gantt, pero si
adviertan de forma visible cuando existen borradores no propagados.

## Regla funcional

- La Base de Proyecto / revision activa sigue siendo la fuente oficial.
- Los borradores Gantt persistidos en backend son tanteos operativos.
- Los borradores Gantt no se incluyen en calculos oficiales de reportes.
- Si existen intenciones Gantt pendientes, invalidadas o pendientes de reajuste,
  el reporte debe advertirlo de forma explicita.
- La advertencia no modifica totales, precios, periodos ni recursos del reporte.

## Alcance

- Backend comun clasico de reporting.
- Preview comun de reportes.
- Export XLSX/PDF generado por motor comun.
- Reporte especializado de Uso de Recursos.
- Smoke clasico de Cronogramas.
- Tests focales de reporting.

## Cambios backend

- `ReportingService` resume borradores Gantt activos para reportes.
- Las vistas previas de `cronograma_valorado` agregan `warnings` y
  `gantt_draft_summary` cuando hay trabajos pendientes.
- La clave de cache de export incluye firma del borrador Gantt activo para
  evitar servir reportes sin advertencia cuando cambia el estado del borrador.
- Los reportes generados por motor comun muestran la advertencia en XLSX.
- El reporte de Uso de Recursos muestra la advertencia en XLSX y PDF sin
  desplazar columnas ni alterar los calculos.

## Cambios frontend

- `CommonReportPreviewModal` muestra advertencias de reporte en una banda ambar
  sobria.
- La advertencia se muestra tambien en el preview especializado de Uso de
  Recursos.
- El smoke clasico de Cronogramas queda reforzado para conservar la banda de
  advertencia.
