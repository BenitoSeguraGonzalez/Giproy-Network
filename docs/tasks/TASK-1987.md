# TASK-1987 - Cancelacion de borradores Gantt por cambio de estado de proyecto

Fecha: 2026-06-27

Modo: GIPROY CLASICO

## Objetivo

Aplicar la regla confirmada de politica transversal: cuando cambia el estado
general de un proyecto, las ediciones Gantt pendientes no propagadas dejan de
ser vigentes y deben cancelarse con auditoria.

## Regla funcional

- Un borrador Gantt activo es trabajo operativo pendiente.
- Si `Proyecto.estado` cambia, los borradores Gantt activos de ese proyecto se
  marcan como `cancelled`.
- La cancelacion no borra datos; conserva intenciones y auditoria.
- Las intenciones pendientes, invalidadas o pendientes de reajuste pasan a
  `cancelled`.
- No se propagan valores ni se recalculan precios oficiales.

## Cambios backend

- `gantt_workflow_service.cancel_active_drafts_for_project(...)` cancela los
  borradores Gantt activos de un proyecto/empresa.
- `proyecto_service.update_proyecto(...)` invoca esa cancelacion solo cuando el
  campo `estado` cambia realmente.
- `PUT /proyectos/{id}` pasa `current_user.id` al servicio para auditar la
  cancelacion.
