# TASK-1988 - Firma backend de aplicacion global Gantt

Fecha: 2026-06-27

Modo: GIPROY CLASICO

## Objetivo

Endurecer la politica de aplicacion global Gantt para impedir que un borrador
pendiente se marque como `applied` sin evidencia explicita de que el flujo
clasico persistio la confirmacion global.

## Regla funcional

- El editor light guarda intenciones como borrador backend.
- La confirmacion global persiste primero el cronograma mediante el flujo
  clasico existente.
- Solo despues puede cerrarse el borrador Gantt.
- Si existen intenciones pendientes, el backend exige una firma de aplicacion
  con lineas persistidas.
- Un cliente API no puede cerrar un borrador pendiente como aplicado sin esa
  firma.

## Cambios backend

- `CronogramaGanttDraftApplyRequest` acepta `application_result`.
- `gantt_workflow_service.mark_draft_applied(...)` exige
  `application_result.persisted_line_ids` cuando hay intenciones pendientes.
- La auditoria del borrador conserva la firma de aplicacion global.
- El endpoint `/gantt-draft/apply` transmite esa firma al servicio.

## Cambios frontend

- `CronogramaGantt` envia `application_result` despues de persistir filas y
  sincronizar el Valorado.
- `Cronogramas` conserva el versionado esperado y reenvia el payload de cierre
  al cliente de dominio.
- El smoke de frontera de Cronogramas exige la firma de persistencia.
