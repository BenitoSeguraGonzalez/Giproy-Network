# TASK-1989 - Firma de origen para trabajo no aprobado de cronogramas

## Estado

Implementado y validado focalmente.

## Contexto

Tras la politica transversal de cronogramas, Gantt y Valorados no pueden
mezclar trabajos no aprobados con origen distinto dentro del mismo
proyecto/revision/cronograma. El trabajo pendiente puede nacer en:

- `gantt`
- `valorados`

La fuente oficial sigue siendo la base funcional determinada del proyecto. El
trabajo no aprobado no alimenta Presupuesto, APUs, reportes oficiales ni
Analisis de Precios Unitarios hasta aplicarse globalmente con preflight.

## Objetivo

Endurecer el backend para que todo borrador Gantt persistente tenga un origen
operativo explicito y no pueda cerrarse, editarse o aplicarse mezclando otro
origen.

## Cambios realizados

- `gantt_workflow_service` normaliza `work_origin` y firma cada borrador en
  `base_snapshot.work_origin`.
- La creacion de un borrador activo rechaza abrir el mismo cronograma con otro
  origen si ya existe trabajo no aprobado vivo.
- Cada intencion guardada hereda el origen del borrador y se rechaza si declara
  un origen distinto.
- El preflight de aplicacion expone `work_origin`.
- La aplicacion global exige `application_result.work_origin` cuando hay
  intenciones pendientes y rechaza cualquier origen incompatible con el
  borrador.
- Las respuestas API de borrador/preflight exponen `work_origin` sin cambiar
  contratos de rutas.
- `CronogramaGantt` envia `work_origin` en la firma de aplicacion global.

## Fuera de alcance

- No se cambia el calculo de precios.
- No se cambia la explosion de APUs anidados.
- No se modifica la persistencia oficial de Presupuesto/APUs.
- No se cambia UX BIM ni se introduce dependencia hacia BIM.
- No se crea Docker, Coolify, CI/CD, staging ni produccion.
