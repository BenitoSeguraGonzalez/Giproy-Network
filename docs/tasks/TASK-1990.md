# TASK-1990 - Control de estado real para politica transversal de cronogramas

## Estado

Control cerrado. Implementacion transversal pendiente por fases.

## Objetivo

Fijar el estado real actual despues de `TASK-1984` a `TASK-1989`, separar lo
implementado de lo que sigue siendo plan, y declarar las modificaciones reales
necesarias para cerrar la politica universal sin ambiguedad de calculos.

## Estado real comprobado

### Implementado

- Borrador Gantt persistente en backend.
- Lock exclusivo de edicion Gantt con heartbeat/liberacion.
- Confirmacion de editor light como intencion de borrador, no como cambio
  oficial.
- Preflight de aplicacion global.
- Bloqueo de aplicacion con intenciones invalidadas o pendientes de reajuste.
- Firma de persistencia global mediante `persisted_line_ids`.
- Firma obligatoria de origen del trabajo no aprobado mediante `work_origin`.
- Advertencias de borrador Gantt en reportes oficiales sin incorporar sus
  valores a totales.
- Cancelacion de borradores Gantt al cambiar estado general del proyecto.
- Explosion operativa de APUs anidados para Gantt y normalizacion de trabajo
  relativo en el servicio de cronograma.

### Parcial

- `apu_resource_modifications_v1` existe como configuracion tecnica, pero no
  constituye todavia un resolvedor transversal de fuente oficial para todos los
  modulos.
- Gantt puede aplicar y sincronizar flujo operativo, pero la conversion final a
  una modificacion activa universal de proyecto/revision no esta cerrada como
  pipeline comun para Presupuesto, APUs, Analisis de Precios Unitarios,
  Valorados, Recursos, reportes y exportaciones.
- La UI comunica borradores Gantt, pero falta un panel comun ligero para
  `Trabajo no aprobado para proyecto` compartido por Gantt, Valorados y
  Recursos.

### No implementado todavia

- Resolvedor unico de fuente determinada:
  `modificacion_activa -> base_proyecto`.
- Persistencia formal de modificacion activa por
  `empresa/proyecto/base_trabajo/revision`.
- Pipeline todo-o-nada que convierta trabajo no aprobado en fuente oficial.
- Conversion explicita `valorados -> gantt` con preflight.
- Modo simple `valorados -> recursos` como origen de trabajo no aprobado
  protegido por `work_origin=valorados`.
- Grid trazable en editor light para recursos consolidados de APUs anidados
  con desglose padre/hijos.
- Aplicacion oficial que actualice globalmente APUs padre e hijos manteniendo
  auditoria de origen.
- Paridad obligatoria de calculo entre Presupuesto, APUs, APU Analysis, Gantt,
  Cronograma Valorado, Recursos y reportes.

## Modificaciones reales necesarias

1. Crear resolvedor backend de fuente oficial determinada.
2. Crear modelo/servicio de modificacion activa por proyecto/revision.
3. Centralizar calculo de APU/precio en un unico pipeline backend.
4. Rehacer la aplicacion global de Gantt para producir modificacion activa y
   recalcular todos los consumidores oficiales.
5. Implementar origen `valorados` para trabajo no aprobado simple.
6. Implementar preflight de conversion `valorados -> gantt`.
7. Implementar panel comun `Trabajo no aprobado para proyecto`.
8. Implementar grid de trazabilidad de recursos consolidados padre/hijos en el
   editor light.
9. Añadir tests de paridad transversal con un caso tipo `Santiago Bermeo`:
   Presupuesto, APU Analysis, Gantt, Valorados, Recursos y reportes deben dar
   el mismo precio oficial cuando no hay borrador pendiente.
10. Añadir tests de no contaminacion: borradores no afectan totales oficiales y
    solo aparecen como advertencia.

## Criterio de cierre de la politica completa

La politica transversal no debe considerarse cerrada hasta que:

- exista una sola fuente oficial determinada por proyecto/revision;
- toda modificacion aplicada globalmente sea transaccional;
- el mismo APU tenga el mismo costo/precio oficial en todos los modulos;
- los borradores no contaminen reportes ni presupuestos;
- las modificaciones sobre APUs anidados mantengan trazabilidad padre/hijo;
- el preflight bloquee cualquier linea invalidada antes de aplicar;
- las validaciones enterprise pasen sin introducir dependencias BIM.
