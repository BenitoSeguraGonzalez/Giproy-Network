# TASK-1992 - Contrato persistente de modificacion activa de proyecto/revision

## Estado

Implementado y validado focalmente.

## Contexto

El plan transversal exige una fuente oficial unica por
`empresa/proyecto/base_trabajo/revision`. Hasta ahora existian borradores Gantt
y configuracion operacional, pero no una entidad persistente comun que represente
la modificacion oficial activa.

## Objetivo

Crear el contrato persistente inicial de modificacion funcional activa sin
alterar todavia los calculos visibles ni la propagacion oficial.

## Cambios realizados

- Se crea el modelo `ProjectFunctionalModification`.
- Se crea la migracion no destructiva
  `de1991a1b2c3_project_functional_modifications.py`.
- Se crea `project_functional_modification_service` con:
  - `get_active(...)`;
  - `create_active(...)`;
  - supersesion automatica de la modificacion activa previa del mismo alcance.
- Se agregan tests de alcance y supersesion.

## Reglas cubiertas

- Solo una modificacion activa viva por alcance de aplicacion.
- La revision y la base de trabajo forman parte del alcance.
- Crear una nueva modificacion activa no borra la anterior: la marca como
  `superseded` y conserva auditoria.

## Fuera de alcance

- No se recalculan precios oficiales.
- No se conecta aun Gantt global a este contrato.
- No se conecta Presupuesto/APUs/APU Analysis.
- No se crea UI nueva.
- No se toca BIM.

## Validacion

- `py_compile` focal backend: OK.
- `pytest app/tests/test_project_functional_modification_service.py app/tests/test_functional_source.py app/tests/test_cronograma_trabajo_duration_model.py`: OK, `26 passed`.

## Siguiente slice natural

Crear un resolvedor de fuente oficial determinada que consulte
`ProjectFunctionalModification` y entregue:

```text
modificacion_activa si existe; si no, base_proyecto
```

sin cambiar todavia los consumidores.
