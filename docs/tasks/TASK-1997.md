# TASK-1997 - Overlay oficial contextual en APUs de proyecto

## Estado

Implementado y validado focalmente.

## Contexto

El modulo APUs puede operar como catalogo puro o abrirse desde un proyecto con
revision activa. En contexto de proyecto, no debe ignorar una modificacion
determinada por Gantt o Presupuesto, porque eso reintroduce dos fuentes de
verdad para el mismo APU.

## Objetivo

Permitir que APUs/APU Analysis lean la modificacion oficial activa cuando la
consulta incluye contexto de proyecto/revision/base, sin cambiar el uso de
catalogo puro.

## Cambios realizados

- `GET /apus/` acepta `proyecto_id` opcional.
- `GET /apus/{id}` acepta `proyecto_id` y `revision` opcionales.
- Si existe `ProjectFunctionalModification` activa para el proyecto/revision,
  el backend superpone `precio_unitario_total` desde `price_preview`.
- `APUResponse` expone metadatos aditivos `official_source` y
  `official_price_overridden`.
- `frontend/src/api/apus.js` permite enviar parametros contextuales en
  `getById`.
- `APUs.jsx` y `ApuBudgetEditor.jsx` envian `proyecto_id` cuando trabajan desde
  proyecto/presupuesto activo.

## Alcance protegido

- El catalogo APUs sin `proyecto_id` conserva la lectura base.
- No se altera la estructura de lineas APU ni la explosion Gantt.
- Sin cambios BIM ni UX BIM.
- Sin cambios destructivos DB ni nuevos contratos obligatorios.
