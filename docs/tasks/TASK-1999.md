# TASK-1999 - Incidencia presupuesto operativo y Gantt bloqueado

## Estado

Cerrado.

## Contexto

En la empresa `Santiago Bermeo`, proyecto `Proyecto Prueba Compartir 1`,
revision `0`, Presupuesto y Gantt mostraban errores de resolucion de
presupuesto operativo.

## Causa raiz

La base PostgreSQL real no tenia aplicada la rama Alembic de trabajo no aprobado:

- `ab1984c0d1e2_gantt_drafts_and_edit_locks.py`
- `de1991a1b2c3_project_functional_modifications.py`

El presupuesto existia (`presupuesto_id=13`) y el cronograma tambien
(`cronograma_trabajo_id=1`), pero `refresh_presupuesto_prices(...)` consultaba
`project_functional_modifications` y PostgreSQL devolvia `UndefinedTable`.

## Accion realizada

Se aplico solo la rama Alembic necesaria:

`alembic upgrade de1991a1b2c3`

Esto creo tablas e indices no destructivos para borradores/locks Gantt y
modificaciones funcionales del proyecto.

## Verificacion

- `project_functional_modifications`: existe.
- `cronogramas_gantt_drafts`: existe.
- `cronogramas_gantt_edit_locks`: existe.
- Presupuesto operativo `13` resuelve y serializa `201` lineas.
- Gantt de trabajo serializa `187` filas para el mismo presupuesto.
