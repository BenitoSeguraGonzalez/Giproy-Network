# TASK-2005 - Restauracion de clonado completo de Proyecto

Fecha: 2026-07-07

Modo: GIPROY CLASICO

## Objetivo

Corregir la regresion en `Proyectos` donde la accion de clonado completo quedo
poco visible y la creacion de una nueva revision persistia en backend, pero no
activaba ni refrescaba la UI hasta recargar manualmente.

## Diagnostico

- El backend de revision completa seguia operativo y cubierto por tests.
- El cliente `proyectosApi.createRevision(...)` devuelve directamente
  `response.data`.
- El handler frontend intentaba activar `res.data`, dejando `undefined` y
  provocando que la nueva revision no se abriera ni se reflejara
  correctamente en memoria tras crearla.
- La accion visible quedaba etiquetada como `Generar Revision`, ocultando el
  concepto operativo esperado de `Clonar Proyecto Completo`.

## Cambios realizados

- `frontend/src/pages/Proyectos.jsx`:
  - La accion del header de proyecto vuelve a mostrarse como
    `Clonar Proyecto Completo`.
  - El dialogo confirma explicitamente el clonado completo como nueva revision.
  - El handler usa correctamente el objeto retornado por
    `proyectosApi.createRevision(...)`.
  - Tras crear la revision, refresca portafolio, familia de revisiones inline y
    calendario, cierra el modal de revisiones si estaba abierto y activa la
    nueva revision sin requerir recarga manual.
- `frontend/scripts/smoke-classic-proyectos-logging-boundary.mjs`:
  - Se agregan guardas de smoke para el retorno correcto de `createRevision`,
    la activacion inmediata y el copy visible `Clonar Proyecto Completo`.
