# TASK-2013 - Lazy-load de rutas protegidas clasicas

Fecha: 2026-07-08

Modo: GIPROY CLASICO

## Objetivo

Continuar la auditoria transversal de cuellos de botella de presentacion,
reduciendo el peso del chunk inicial del frontend sin alterar funcionalidad,
contratos API, auth, tenant, datos ni capa BIM.

## Diagnostico

- El build posterior a TASK-2012 aun mostraba `index-*.js` como chunk mas
  pesado de entrada:
  - `index-DDa9QeMg.js`: ~638,8 KB.
  - `CronogramaGantt-DufRjVgj.js`: ~565,6 KB.
- `AppRouter.jsx` ya usaba lazy-load para muchas rutas, pero conservaba imports
  eager de rutas protegidas relevantes:
  - `Dashboard`
  - `Proyectos`
  - `BasesTrabajo`
  - `Subcategorias`
  - `OtrosServicios`
- `Proyectos.jsx` es una de las paginas grandes del inventario frontend y no
  debe viajar en el chunk inicial cuando el usuario entra por login u otra ruta.

## Cambios realizados

- `frontend/src/routes/AppRouter.jsx`:
  - `Dashboard`, `Proyectos`, `BasesTrabajo`, `Subcategorias` y
    `OtrosServicios` pasan a `lazyWithChunkRecovery(...)`.
  - Las rutas publicas (`Login`, `ForgotPassword`, `ResetPassword`,
    `VerifyRegistration`) quedan directas.
  - Las rutas protegidas siguen bajo el `Suspense` existente de
    `withProtectedLayout(...)`.
- `frontend/scripts/smoke-classic-route-lazy-boundary.mjs`:
  - Nueva guarda focal para impedir que esas rutas protegidas pesadas vuelvan a
    importarse eager desde el router.
- `tools/ai_tools/validate_enterprise_baseline.py`:
  - El smoke de lazy-load del router queda incorporado al baseline
    `--include-frontend`.
