# TASK-2014 - Lazy-load interno de Pareto en Gantt clasico

Fecha: 2026-07-08

Modo: GIPROY CLASICO

## Objetivo

Continuar la auditoria de cuellos de botella de presentacion, reduciendo el
chunk funcional de `CronogramaGantt` sin alterar el primer render del Gantt,
contratos API, datos, auth, tenant ni BIM.

## Diagnostico

- Tras TASK-2013, el chunk inicial de la app ya quedo reducido, pero
  `CronogramaGantt` seguia siendo el mayor chunk funcional.
- Build beta previo:
  - `CronogramaGantt-CLJ8mdPr.js`: ~567,2 KB, gzip ~149,1 KB.
- `CronogramaGantt.jsx` importaba `GanttParetoModal` de forma eager.
- `GanttParetoModal.jsx` pesa ~33 KB en fuente y solo se usa cuando el usuario
  abre el modal Pareto; no participa en el primer render del Gantt.

## Cambios realizados

- `frontend/src/components/projects/CronogramaGantt.jsx`:
  - `GanttParetoModal` pasa de import estatico a `React.lazy(...)`.
  - El modal se monta solo cuando `paretoOpen=true`.
  - Se usa `React.Suspense fallback={null}` para no introducir UI nueva ni
    cambiar el flujo visual.
- `frontend/scripts/smoke-classic-cronogramas-api-boundary.mjs`:
  - Se agrega guarda para impedir que `GanttParetoModal` vuelva a cargarse de
    forma eager.
  - Se valida que el modal lazy solo se monte bajo `paretoOpen`.
