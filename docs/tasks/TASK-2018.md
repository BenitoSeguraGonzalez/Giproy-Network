# TASK-2018 - Extender superficie visual del Gantt clasico con pocas lineas

Fecha: 2026-07-08

Modo: GIPROY CLASICO

## Objetivo

Corregir un problema puramente visual del Gantt clasico: cuando un proyecto
tiene pocas lineas, el workspace se recortaba a la altura de esas filas y daba
la sensacion de un proyecto incompleto o a media pantalla.

## Alcance

- Frontend clasico: `frontend/src/components/projects/CronogramaGantt.jsx`.
- Smoke clasico: `frontend/scripts/smoke-classic-cronogramas-api-boundary.mjs`.
- Contexto de producto para la skill de UI: `PRODUCT.md`.
- Sin cambios backend, API, rutas, auth, tenant, permisos, datos ni
  migraciones.
- Sin UX BIM ni dependencia hacia BIM.

## Cambios

- El workspace del Gantt deja de calcular su alto por cantidad de lineas.
- `ganttWorkspaceHeight` usa toda la altura disponible medida para el modulo,
  respetando un minimo visual.
- Se agrega un relleno visual inferior calculado desde la altura disponible y
  la altura real de filas virtualizadas.
- La tabla izquierda y el timeline derecho comparten el mismo spacer final para
  que ambos paneles cubran el espacio disponible sin inventar filas ni alterar
  datos.
- El smoke de Cronogramas protege contra la regresion al calculo por
  `rows.length` y exige el spacer visual final.
