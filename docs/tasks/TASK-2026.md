# TASK-2026 - Activación BIM controlada para empresas piloto

Estado: desplegada en beta el 2026-07-13; piloto humano Gate E pendiente

## Objetivo

Habilitar GiProy BIM exclusivamente para `Administradores Generales`
(`empresa_id=1`) y `Santiago Bermeo` (`empresa_id=3`). Para cualquier otra
empresa, la entrada BIM debe permanecer oculta y los endpoints BIM deben
responder como no habilitados.

## Alcance autorizado

- Usar la puerta persistida `system_bim_settings`, sin reglas por nombre en el
  frontend.
- Configurar `is_enabled=true`, `superadmin_only=false` y
  `allowed_company_ids=1,3`.
- Conservar feature flags, tenant, capacidades BIM y rollback existentes.
- No modificar Proyectos, auth, JWT, contratos clásicos ni datos funcionales.
- No ejecutar la cadena Alembic pendiente del entorno local.

## Implementación

- Se verificaron por SQL de solo lectura las empresas activas:
  - `1`: `Administradores Generales`.
  - `3`: `Santiago Bermeo`.
- Se actualizó la configuración BIM en una transacción y se registró el evento
  `bim_pilot_allowlist_activated` en `system_audit_events`.
- El estado anterior queda preservado en el payload de auditoría:
  `is_enabled=false`, `superadmin_only=true`, `allowed_company_ids=''`.
- No se inicia el conteo formal de Gate E: faltan responsables, fechas y dos
  revisiones reales de modelo.

## Validación

- `pytest app/tests/test_bim_foundation.py -q`: `41 passed`.
- Empresa `1`, rol usuario: BIM habilitado.
- Empresa `3`, rol administrador: BIM habilitado.
- Empresa `2`, rol superadministrador: BIM denegado.
- Allowlist resuelta por backend: `[1, 3]`, con scope obligatorio.

## Despliegue beta

- Servidor: `giproy.excomconsultores.com` (`192.168.18.106`).
- La rama Alembic BIM avanzo exclusivamente de `de2001a1b2c3` a
  `de2022a1b2c3`; no se ejecutaron migraciones clasicas globales.
- `bim_rollout_plans` y la persistencia BIM/4D aditiva quedaron disponibles.
- Backend y frontend BIM actuales fueron reconstruidos; el chunk publico
  `BimTab-Dk4eBf8p.js` responde `200` y contiene `2,254,311` bytes.
- Los contenedores PostgreSQL, backend y frontend quedaron saludables; home
  publico `200` y endpoint BIM sin token `401`.
- La activacion posterior al despliegue se audito como
  `bim_pilot_allowlist_reactivated`.

## Hallazgo de entorno local

La base local contiene `system_bim_settings`, pero todavía no contiene
`bim_rollout_plans`. La migración avanzada de rollout debe ejecutarse en una
TASK de despliegue controlada; no bloquea la puerta de visibilidad, pero sí el
registro estructurado del checklist temporal de Gate E.

## Rollback

Restaurar en `system_bim_settings` el estado auditado anterior:
`is_enabled=false`, `superadmin_only=true`, `allowed_company_ids=''`. No hay
rollback de datos BIM ni cambios clásicos.

El despliegue beta conserva el dump
`deploy/backups/giproy-beta-20260713-145438.sql.gz`, el respaldo de fuentes
`deploy/backups/task2026-bim-source-20260713-200303.tar.gz` y la imagen
`giproy-beta-backend:task2026-predeploy-20260713-200303`.
