# TASK-2044 - Invalidacion de frontend tras despliegue beta

Fecha: 2026-07-24

Estado: IMPLEMENTED_PENDING_HEADER_VERIFICATION

## Incidencia

La Lenovo Tab P12 seguia mostrando la version visual anterior despues del
despliegue del gate global de alcanzabilidad.

## Diagnostico

- El contenedor beta servia la imagen nueva y el bundle incluia
  `data-app-page-viewport`.
- No existe service worker.
- `index.html` y las rutas SPA no declaraban una politica explicita de
  revalidacion; el navegador podia reutilizar el documento que referencia los
  chunks anteriores.
- Los assets versionados por hash recibian cache de cuatro horas desde la capa
  publica, lo cual es correcto solamente si el indice siempre se revalida.

## Correccion

- `index.html` y todas las rutas fallback SPA usan `no-store`, `no-cache`,
  `must-revalidate` y expiracion inmediata.
- `/assets/` usa cache inmutable de un ano porque cada build cambia el hash.
- El gate de seguridad de despliegue verifica ambas politicas.

## Verificacion pendiente

- Build Docker y `nginx -t` implicito al arrancar el contenedor.
- Headers HTTPS reales despues del despliegue.
- Recarga normal desde la Tab P12 sin borrar manualmente datos del sitio.
