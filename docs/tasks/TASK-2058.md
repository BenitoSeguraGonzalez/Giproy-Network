Fecha: 2026-08-12

Estado: COMPLETADA Y DESPLEGADA EN BETA

Tipo: bug / infra

Prioridad: critical

## Objetivo

Restaurar el primer paso del login en beta sin cambiar usuarios, contraseñas,
JWT, roles, tenant, permisos ni datos.

## Causa raiz

El cliente usa `/api/v1` como base. El proxy Nginx reemplazaba adicionalmente
`/api/` por `/api/v1/`, por lo que la consulta publica de cuentas llegaba como
`/api/v1/v1/auth/accounts-by-email` y devolvia `404`.

## Cambio autorizado

- Preservar la URI original de `/api/v1/...` en el proxy del frontend beta.
- Reconstruir exclusivamente frontend y WAF, tras backup automatizado.

## Criterios de aceptacion

- `GET /api/v1/auth/accounts-by-email` devuelve `200` para una consulta publica.
- El paso de verificacion de correo del login deja de presentar el error generico.
- Login clasico conserva sus contratos; BIM permanece apagado por defecto.
- Frontend, WAF y backend quedan saludables despues del despliegue.

## Rollback

Restaurar la imagen frontend anterior y recrear el WAF. No hay migraciones ni
cambios de base de datos.
